# 收银合并：把同事做的收银员工作台对照进柚子（需求评审稿）

**这是需求评审，不是开发。** 这份文档和 `PENDING_DECISIONS.md`「收银合并」只登记需求与对照，不改任何代码、不登记迁移号、不改版本号。评审通过、和主线开发会话分好工以后，再按柚子的流程登记迁移号、排版本、开发。

店主 2026-11-26 授权同事的 Claude 会话把收银板块合进柚子。店主的原则：先看柚子里有没有类似的，有就补全、扩展，不另做一套；不把同事的系统整个搬进来，不另建第二套结账、余额或数据库。

**同事的收银员工作台是什么**：一个可交互的前端原型（收银台、发牌台、订单查询、风险手牌、交班、下单、餐厅、沽清、吧台），数据是写在页面里的演示数据，没有后端、没有数据库、没有真实会员或流水，也没有密钥。所以**不搬代码**：逐条拿原型里的做法对照柚子现有的功能，柚子已经有的不做；柚子缺的，按柚子的数据模型、加锁顺序与「结果待确认」写进柚子。原型里的页面写法、演示数据都不进仓库。原型（演示用）：https://claude.ai/artifact/XWjPVYtF1NpmkCUpecKRG7

这份对照按 `main` 的 8.2.17（`c5b43fc`）重新核对过；「柚子已有的」一栏是初查，评审时请主线开发会话按代码再核对一遍。

没定的经营规则按收银系统的常见做法先定默认值，标「待确认」，见 `docs/PENDING_DECISIONS.md`「收银合并」CM-1 起。

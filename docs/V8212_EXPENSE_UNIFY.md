# 8.2.12 · 报销统一成一套：WCP 发起 / 查看，业财法审批与执行

《汤崎 ERP｜业财法审批与 WCP 模块 需求变更文档 v0.1》第 7 批（文档第 7 章，B1）。按文档建议 WB11（`docs/PENDING_DECISIONS.md`）。数据库迁移 `620`，回滚 `docs/rollback/620_oa_expense_retire.down.sql`。

## 1. 核对时

同一类报销有两个入口、两套数据：WCP「审批 → 报销」（办公审批，`oa_approvals`）与「业财法审批 → 报销」（`gf_docs`）。两边各有单号、状态、审批记录。ERP「费用与备用金」的报销（`expense_claims`）是门店经营费用登记，挂预算与采购单，文档没有把它算作这里说的重复，这一版不动（8.2.7 已改成全部要审批）。

## 2. 这一版（7.2）

| 项                               | 做法                                                                                                                                                                               |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 一张单、一个状态机、一条审批记录 | 新报销只在业财法建（`gf_docs`），审批记录只在 `gf_flow_actions`。WCP 的报销模板停用（迁移 `620`），不再产生第二份数据                                                              |
| 入口分工                         | WCP「审批 → 发起」里的「报销」卡片直接跳到「业财法审批 → 报销」；业财法报销页写明「只在这里发起、查看，审批按业财法规则走，审批记录只有这一份」，并能跳回 WCP 审批列表看以前的报销 |
| 状态同步                         | 只有一份数据，两边看到的是同一张单                                                                                                                                                 |
| 菜单与命名                       | WCP 只剩一个「报销」入口（指向业财法）；业财法是审批规则配置与执行后台（第 4、5 批）                                                                                               |
| 历史数据                         | 以前在 WCP 提的报销不合并、不改（不做静默合并）：在审的照旧在原来的审批里走完，历史照旧能看、能导出；8.2.7 的「没审批就通过的清单」照旧列出 WCP 里没审批就通过的报销               |

- 直接调接口用 WCP 报销模板提交的：返回 `EXPENSE_MOVED`，提示去业财法发起。WCP 设置里的模板编辑不能改启用状态，停用的报销模板不能被重新打开（回滚迁移才行）。

## 3. 硬规则（7.3 第 3 条）

业财法的报销、出差、招待通过前，这一轮至少要有一条有人同意的审批记录（节点、审批人、时间、动作）；全部自动跳过的不放行（`GF_NO_APPROVAL_RECORD`）。业财法提交时本来就要求每一级都有能审的人（第 4 批起按快照），这一条是兜底。

7.3 其余几条：查不到审批人停在待审并告警、不自动通过（8.2.7）；没有一键 / 批量通过绕过审批记录（业财法没有批量同意；ERP 审批中心的批量同意每张都记审批记录）；状态变更只追加记录。

## 4. 测试

`tests/oa-approval-templates.test.ts`：模板停用后列表里没有报销、提交返回 `EXPENSE_MOVED`、迁移 `620` 停用模板。原来测 WCP 报销那一套的用例在开头把模板重新打开（测历史单的行为）。业财法报销链里都有财务审核一级，正常流程碰不到兜底，兜底由代码审查覆盖。

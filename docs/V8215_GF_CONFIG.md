# 8.2.15 · 业财法：流程与阈值后台可改、试算

《汤崎 ERP｜业财法审批与 WCP 模块 需求变更文档 v0.1》第 5 批（核对见 `docs/V8212_APPROVALS_PURCHASING.md` A2）。按文档建议 WB4、WB5（`docs/PENDING_DECISIONS.md`）。数据库迁移 `720`，回滚 `docs/rollback/720_gf_flow_config.down.sql`。

## 1. 核对时（A2）

业财法没有设置板块：审批人、知会人、会签 / 或签、节点顺序写在代码里；3,000 元 / 50 件 / 日 1 万 / 月 5 万是常量；查不到审批人时已经拦着提交。

## 2. 这一版

入口：「WCP → 业财法审批 → 流程与阈值」（`/oa/gov?box=config`），和「角色映射」一样只给有「配置业财法角色」权限（`gf.roles`，店主）的人。不做可视化流程设计器，就是一张按顺序的表。

### 2.1 阈值（WB4）

| 项 | 预置（= 原来的常量） | 管什么 |
| --- | --- | --- |
| 零星采购基础审核金额 | 3,000 元 | 同日同供应商合并后不超过它、且件数不超过下一项的，基础审核 |
| 零星采购基础审核件数 | 50 件 | 同上 |
| 部门备用金日额度 | 1 万 | 没有月度核定过的部门用它；核定过的照核定 |
| 部门备用金月额度 | 5 万 | 同上；不能小于日额度 |
| 采购部门当日累计 | 1 万 | 超了非紧急转正式采购，紧急加财总＋CFO 特批 |
| 验收期限 | 7 天 | 审批通过后几天内要验收 |
| 升级审核角色 | 财总（财务负责人） | 见 2.2 |

- 存在 `gf_settings` 的 `rules` 一行；没存过按预置，**升级后行为不变**（升级审核除外，见 2.2）。存的东西不合格（手改过库）整份按预置，免得审批卡住。
- 保存写操作日志（`gf_config`，带改前改后与原因）；没有改动的拒绝（`GF_RULES_SAME`）。
- 零星采购页的说明、比价说明的提示、拦截提示（「超出基础审核（3,000 元或 50 件……）」「采购部门今天零星采购累计超过 10,000 元」）按现在的数写。员工从 `GET /api/gf/settings` 读到现在的阈值。
- 日 / 月累计口径不变（WB5）：按部门、按提交时间、只算有效单（驳回、撤回的解冻，不算）。

### 2.2 零星采购超出基础审核的升级审核（WB4）

文档 Q4 写「零星采购超限的升级审核需业务指定」，WB4 定「默认财务负责人」。原来的代码超出只加比价说明、不加层级，财务那一级还是财务审核人，与 WB4 不一致。这一版：

- 超出基础审核的，财务那一级改由「升级审核角色」审（默认财总），**仍不加层级**（`docs/APPROVAL_V4.md` 第 7.1 节「不加层级」照旧）。
- 升级审核角色可以改成别的角色，或设成「不升级」回到原来的财务审核人。
- 按提交（含退回再提交）那一刻的设置排；已经在审的单不变。

### 2.3 各类事项的流程

每类事项（14 类）可以存一份自己的流程，不存就用内置的（代码里按金额、类型自动排，和以前一样）。

- **审批链**：1–6 级，按顺序。每一级是引擎已有的四种节点之一，不另造：
  - 部门负责人（单据上没有费用承担部门的供应商入库 / 变更、SKU 提报 / 协议价变更不能选）；
  - 内部履约执行人（只有通用事项、合同能选，其他类型单据上不选人）；
  - 某个角色，或签：这个角色里任一人同意；
  - 几个角色会签：2–3 个不同的角色，各由不同的人同意，任一人不同意即不通过。
  - 每一级标性质：审核 / 终审 / 特批（终审、特批适用回避上移）。
- **知会角色**：通过后知会谁；不设用内置的，设了一个都不选 = 不知会。
- 审批链、知会可以只设一样，另一样用内置的。
- **校验**（`flowConfigProblems`，两端共用）：1–6 级、角色在角色清单里、会签 2–3 个角色且不重复、上面两条「不能选」。不通过的 `GF_FLOW_INVALID`，列出每一条。
- **追加版本**：每次保存、清除都在 `gf_flow_configs` 加一版（只追加），生效的是最新一版；清除（`enabled = false`）= 回到内置。列表上写第几版、谁、什么时候；能看历史版本。保存、清除都写操作日志（改前改后）。
- **在途单不受影响**：提交时排好的链本来就存在那一轮审批上（`gf_flows.nodes`），这一轮还记下用的是第几版（`gf_flows.config_version`），审批单上写「按『流程与阈值』里设置的流程（第 N 版）」。退回后再提交按那时生效的。
- **照旧自动加的**：内控参与（招标、单一来源等标记）、回避上移、连着两级一样合成一级、每一级都要有人能审（`GF_NO_APPROVER`）、部门负责人 / 履约执行人本人发起视同确认、WB2 快照。
- **零星采购超额的「财总＋CFO 合并特批」**：是额度规则加的，不是流程的一部分。改了零星采购的流程也照样追加在最后（`TypeHooks.fixedNodes`），合并特批编号、专项额度照旧。
- 业务上的钩子照旧：例如 SKU 提报「最后一级要逐个确认异常 SKU」跟着自设流程的最后一级走。

### 2.4 试算

`POST /api/gf/config/preview`：选事项类型、金额（不含税）、部门、经营主体、谁提交（默认自己）、履约执行人、标记，按现在的阈值、流程与角色映射排一遍（同一套 `planFlow` 与「有没有人能审」的判断），不建单、不占额度：

- 每一级的名称、性质，每一席现在能审的人（姓名；本人发起视同确认的写出来）；
- 排链时的调整（回避上移、内控加签、用的是第几版）；
- 通过后知会的角色与人；
- 零星采购：分级（基础 / 超出）、升级审核角色、部门今天 / 本月已占与额度、要不要合并特批；
- 提交时会被拦的问题（部门没有负责人、某一级没人能审、会签的人不够）**只列成提示，不报错**。

内置流程要看单据内容的，可以带单据字段（`payload`，尽量照填，页面上写着要哪些）：通用事项 `contractLike`；SKU 提报 `core`；零星采购 `qty`、`urgent`、`supplierName`；合同 `type`；付款 `category`、`contractDocId`、`prepay`、`invoice`、`specialId`；报销 `invoiceNo`、`lateClaim`；出差 `priorApplied`、`overStandard`、`overBudget`、`overBudgetMode`；招待 `priorApplied`；用印 `kind`、`contractUnchanged`、`highRisk`；HR 批次 `kind`。排不出来的提示要填哪些。

## 3. 接口

| 接口 | 说明 |
| --- | --- |
| `GET /api/gf/config` | 阈值、预置值、最后谁改的；14 类事项现在用的流程 |
| `PUT /api/gf/config/rules` | 改阈值（全部字段 + 原因选填） |
| `PUT /api/gf/config/flows/:docType` | 存流程：`{ nodes: 节点[] \| null, ccRoles: 角色[] \| null, note }` |
| `POST /api/gf/config/flows/:docType/clear` | 清除，回到内置 |
| `GET /api/gf/config/flows/:docType/versions` | 历史版本 |
| `POST /api/gf/config/preview` | 试算 |
| `GET /api/gf/settings` | 多带 `rules`（员工可读） |

同一类事项的保存串行（advisory lock `gf_flow_config:<类型>`），版本号在锁里取最大 + 1；阈值保存锁 `gf_rules`。

## 4. 假设与偏离

- **升级审核**（2.2）：WB4 的「升级审核默认财务负责人」按「超出基础审核时财务那一级改由财总审、不加层级」做；这是这一版唯一改了默认行为的地方，升级后超出 3,000 元或 50 件的零星采购由财总审（原来财务审核人）。要回到原来的做法，在「流程与阈值」把升级审核角色设成「不升级」。
- 「部门备用金日额度」只替换没核定过的部门的默认值；月度核定（财总＋CFO 共同审批、次月生效）照旧优先。
- 知会角色按**通过时**生效的设置发（与 8.2.14「知会照旧按现在的映射发」一致），审批链才按提交时排好的。
- 节点不能放「店主」或指定某个人，只能放角色、部门负责人、履约执行人（WB1：人走角色映射）。
- 用会签放并行分审（财务、法务分别审核）也是同一种节点，名称可以自己写（选填）。

## 5. 没做

可视化流程设计器、按金额分档的条件分支（内置流程里的金额档位不在页面上改，要按金额变链路的类型用内置的）、加签 / 转派（WB3）。

## 7. Codex 审查修正

会签一级「人够不够」原来只看各角色候选人的并集人数；可以配三个角色会签以后，财务＝{甲}、法务＝{甲}、人事＝{乙、丙} 并集三人，但同意时一个人在一级里只坐一席，财务、法务坐不满。改为按「席位 → 能坐的人」求最大匹配（`maxDistinctSeats`，增广路），坐不满所有席位才报 `GF_COSIGN_SAME`；提交与试算共用 `approverProblems`，提交人回避照旧先剔除。`tests/govflow-cosign-seats.test.ts` 加了用例。

## 2. 数据模型（迁移 `230_price_catalog.sql`）

- `price_catalog_sets`：一份价目表（导入的一份文件，或手工维护的一份）。`status`：草稿 `draft` / 生效 `active` / 停用 `retired`；一家门店同时最多一份草稿、一份生效。导入先落草稿；核对条数无误后再切换生效（第 5 节），原来生效的那份转停用，可以整体回滚到它。
- `price_catalog_entries`：价目表里的一项。
  - **价格形态** `price_mode`：
    - 双价 `dual`：专业价 `price_cents` + 资深价 `price2_cents`。
    - 单价 `single`：只有 `price_cents`。
    - 无价格 `none`：待定价或免费，两个价格都是**空值**、不存 0；页面写「待定价」，不写「0 元」。
    - 比例 `rate`：服务费 `rate_bp`，万分之几，10% = 1000，不在商品上存 0.1 元。
    - 数据库约束保证形态与价格列一致。
  - **金额**：一律整数分。「399/2H」「加钟/19.9」「688 元/位」这类写法拆成价格、时长、单位分别存：
    - 时长：`duration_minutes`，一律分钟——按摩服务时长、门票 12H / 24H、娱乐与房间的「基础价含几分钟」。
    - 加钟价（娱乐）/ 超时单价（房间）：`extra_price_cents`，加上每次多少分钟 `extra_minutes`。
    - 封顶价：`cap_cents`。
    - 台位数 / 房型总间数：`units_count`。
    - 房号清单：`room_numbers`。
    - 时段：`window_start` / `window_end`，0–1439 分钟，跨零点时结束小于开始。
    - 是否含餐：`includes_meal`。
    - 适用房型：`venues`，房间 / 大堂 / 浴区。
    - 适用性别：`gender`。
    - 核心人群、操作内容、项目亮点、备注。
  - **一项里还分档的** 放在 `variants`，每档有名称、价格、分钟、单位、房号、几人位：
    - 轰趴房按面积分 4 档，每档 6 小时 / 12 小时 / 包天；
    - 客房大房间、小房间的过夜价与 3 小时价；
    - 餐饮包房的三种位价与低消；
    - 棋牌房的 8H 价。
  - **板块 / 餐段**存在 `section`，**菜品分类**存在 `category`，**原始编号**存在 `code`，**表格行号**存在 `source_row`，便于与表格核对。
  - **不录内部参考字段**：成本、成本率、思路、核心定位都不录（需求说明第五节）。
  - **停用不删除**：停用是把 `active` 改成 false，不物理删除。
  - **能不能下单**：`orderable`。2 楼零点没有售价的菜录为「待定价」、不能下单，补价后启用（约束：菜品无价格时不能可下单）。

## 3. 导入（第一批）

- `POST /api/admin/price-catalog/import/preview`：读 `.xlsx`，六张表按工作表名认，逐行校验，返回：
  - 条目；
  - 问题：写明工作表、行号、字段与原因。`error` 挡导入，`warning` 只提醒；
  - 条数对照；
  - 预览摘要。
- `POST /api/admin/price-catalog/import`：带预览摘要与操作编号 `opKey`（页面每次预览配一个；迁移 `232`）。结果不确定原样重提时返回第一次导入的那份草稿；那份草稿后来已被替换或放弃的拒绝（`IMPORT_DONE`），同一编号换了文件的拒绝（`IMPORT_OP_REUSED`）。页面每次导入用新的编号，提交前把编号与原请求（含文件内容）存在本机并读回核对，存不了就不发；结果不确定（断网、超时、服务器出错）时页面上方列出这一笔，只能查回、按原内容重新提交或确认作废（`/api/erp/ops`，类型 `price_import`；作废登记在 `op_fences`，迁移 `234`），在此之前不能再导别的文件。文件与预览时不一样的拒绝（`IMPORT_STALE`），有 `error` 的整份不导（`IMPORT_INVALID`）。导入成这家门店的草稿，替换原来的草稿（门店级咨询锁 → 原草稿行，再删、再写；`docs/LOCKING.md`），留审计（`price_catalog`，`detail.action = import`）。

挡导入的问题：

- 表头少了某一列或写错字（「资深价格」「核心针对人」）：每张表读到的列都要有（按摩及助浴还有核心针对人群、服务操作内容、项目亮点），写明少了哪一列（不然整列成了空的，双价悄悄变单价、说明悄悄清空）；
- 导入的每一项最后再用页面编辑的同一份校验过一遍（分档 0 小时之类），导进来的都能照常修改；

- 文件本身不对：合并区域过大（一个超过 2000 格或一张表合计超过 5 万格）、一张表超过 2000 行、一个房型合并超过 20 行、整份认出超过 3000 项，整份拒绝（`IMPORT_FILE_INVALID`）；一项认出超过 20 档价格报错（与页面编辑同一个上限 `PRICE_VARIANTS_MAX`，导进来的都能照常修改）；一项超过 300 个房号报错（`PRICE_ROOM_NUMBERS_MAX`，同样与页面编辑一致）；各个文字字段（名称、编号、单位、说明、分档的单位与说明……）的长度上限也与页面编辑一致，超过的报错；
- 客房的过夜价、钟点价逐行认：有一行认不出、两列个数对不上（配不出是哪种房的）报错，不跳过它再按先后配对；
- 少了某张表、表头不对（零点菜品每个餐段的表头要有「菜品分类」「菜品名称」「售价」「单位」，写错字的报出是哪一行、少了哪一列）；
- 房号过多（一个房型超过 300 个）；
- 房间分档、超时价、封顶价写了金额却不合法（「6小时：0」「包天：0」「0封顶」「超时0/H」「超出按照-588元/小时」「-599/晚」「低消：另议」「abc元/位」（位价逐行核对）「abc/12H」（另写的价格档逐行核对）「低消：3,000」（金额里写逗号的一律报错，不截成一段））：报错，不当成没填、没有封顶；
- 价格为空（零点菜品除外，菜品没写售价是「待定价」）、价格写法看不懂、金额多于两位小数（「599.999/晚」整段报错，不截出其中一段）；
- 时长格式不支持或不在 1–2880 分钟里（娱乐价格「39/0min」也算），时段看不懂（时、分各自要合法，「7:99」不换算成 8:39）；加钟价多出来的位数（「加钟/19.999」不截成 19.99）；
- 菜品、按摩缺了名称却还写着售价 / 单位 / 编号 / 时长 / 价格：报错，不当空行跳过；
- 房间价格里相邻几行写了同一个房型（轰趴房按面积连着写几行除外）：后面那几行报错，不悄悄只读第一行；
- 名称重复：每张表都查——同一张表、同一个板块 / 餐段、同一个分类里（不分大小写、不管空格，与页面编辑同一个查重键），写明第一次出现在第几行；

## 5. 编辑与校验（第三批，迁移 `231_price_catalog_edits.sql`）

同一页（`PriceCatalogPane.tsx`，表单与改动记录在 `PriceEntryDialog.tsx`；服务端 `src/server/modules/price-catalog/edit.ts`）：

- **单条新增**：「条目」右上角「新增一项」，选工作表与种类（服务费只有一条规则，不新增），排在这张表最后。
- **修改 / 改价**：每行「改」。价格形态在单价 / 专业·资深 / 待定价之间切换；待定价两个价格都空着（不存 0），服务费按百分比填。分档（轰趴房各面积、客房大小房、餐饮包房位价……）能改价格，档名与档数照导入的表（PC13）；主价格由分档推出来的（轰趴房 = 各档最低价、餐饮包房 = 位价里最低的、客房 = 过夜价里最低的，与导入同一个口径）跟着分档变，页面上不另填。
- **停用 / 启用**：停用不删除（写原因），历史单据照旧显示名称与价格；停用的不算条数。启用时同名在用的挡下。
- **校验**（页面边填边提示、服务端写入前再查一遍，同一份 `priceEntryProblems`）：价格形态与价格一致；金额大于 0、不超过 100 万元；待定价不填价格；只有服务费按比例；待定价的菜不能下单；按摩板块必须是 9 个之一、零点餐段必须是 4 个之一；时长、时段、台位合法；加钟 / 超时价与每次多少分钟要成对填，娱乐与按时计费的房型还要填基础价含多少分钟。名称重复（同一张表、同一个板块 / 餐段、同一个分类里在用的，不分大小写、不管空格）在服务端锁里查（`PRICE_NAME_DUPLICATE`）。
- **改价留痕**（`price_catalog_changes`，只追加）：新增、修改、停用、启用各一条——经办人、时间、改前与改后的整项、原因、价格有没有变（`price_changed`）。页面「改动记录」按「标签：旧 → 新」列出改了什么（价格那行在最前，如「价格：专业 ¥499.00 / 资深 ¥599.00 → 专业 ¥529.00 / 资深 ¥599.00」），可以只看改价；每行「记录」看这一项的全部改动。
- **版本号**：修改、停用带着读到的版本号，别人先改过就拒绝（`PRICE_VERSION`），刷新后再改；什么都没改的保存不留痕、版本不变。
- **操作编号与「结果待确认」**（迁移 `235`）：新增、修改、停用 / 启用都带操作编号，编号记在那一条改动留痕上（`price_catalog_changes.op_key`）。页面提交前把编号与原请求存在本机，结果不确定（断网、超时、服务器出错）时在页面上方查回、按原内容重新提交或确认作废（类型 `price_entry`）；原样重提返回这一项现在的样子、不再写一次；作废过的原请求晚到也不改。确认之前「新增一项」「改」「停用」都不能点。这一页的写操作会互相覆盖（导入替换草稿、切换让草稿生效、改条目同步收银价），所以导入、单条改动、切换 / 放弃 / 回滚、对接里任何一笔还在提交中（请求还没回来，关了对话框也算）或结果待确认，这一页所有写操作的按钮都不能点，回来了、或查回 / 确认作废以后再操作（`priceOps.ts`，`useErpRecorded`）。
- **一键切换生效**：草稿上「切换生效」。条数与表格（224 项、每个板块 / 餐段）一致的直接切；对不上的列出差几项，写明原因才切（PC11，原因记进审计）。原来生效的那份转停用，成为「上一版」。
- **整体回滚**：生效中的那份上「回滚到上一版」，写原因；上一版恢复生效，刚才那份成为上一版（PC12）。带操作编号（迁移 `233`）：结果不确定原样重提时什么都不改，不会把之后别人切换的结果再切回去；页面同样先存本机，结果不确定的在页面上方查回、重提或确认作废（类型 `price_rollback`）。
- **放弃草稿**：草稿连同条目、改动记录一起删掉，审计留一条（PC14）。
- 切换生效、放弃草稿与整体回滚一样带操作编号（迁移 `236`，记在 `price_catalog_set_ops`）：原样重提什么都不改、返回现在的样子；页面先存本机，结果不确定时查回、重提或确认作废（类型 `price_set`），确认之前这几个按钮都不显示。

  - 名称、类别（部门营业额、券、会员折扣按它算）、点单分区、适用性别、停用不动；已开的单不变。补了哪些记一条审计 `price_catalog` / `fit_items`（哪几个项目、改了什么）。
- **分类核对**（`checks.ts`）：「点单页上」改成真正看得到的个数（对上了、在用、按摩标了需要技师、菜品挂了在用的档口且不要技师，与点单菜单同一个条件），对不上的逐项写原因（没对上、停用、没标需要技师、没挂档口、没有在用的档口建不了菜；价目表里不能卖的、对上的原有项目却还在点单页上的也列出来），页面在表下列出来。
- **加钟**（`clockroom.ts` `extensionLine`）：切换前按「标准」档开出的钟，标准档去掉以后加钟按「专业」档（同一个价），不会因为取不到原来的档被拒。钟房加钟的操作编号摘要改按提交上来的（钟单、钟数、合计）算，与房态中心续钟一样——两次提交之间价格档变了，原样重提照样认得出是同一笔；升级前发出的原请求按当时明细算的摘要也认。
- **分类核对卡片**：个数对不上、或有对不上的项（少一项又多一项时个数会相等）都标红、列明细。
- **正式服怎么做**：更新到带这一修正的版本后，在「后台 → 全品类价目表」重新导入《价目表 1119》成草稿（或用现在生效的那份改一项再改回来也会同步，但整份切换最省事），切换生效一次，看「分类核对」都对得上、下面没有列出看不到的项；门店电脑、平板强制刷新。还没有出品档口的先在后台建一个档口再切换。

## 9. 模板替换与页面维护（店主 2026-11-24《价目表模板替换与页面维护需求说明》）

店主把总表拆成五个表格（门店价格、娱乐价格、房间价格、零点菜品价格、按摩及助浴价格），每个模块用自己的一张导入、导出；页面上直接维护。没有迁移。

- **只导一张表**（`POST /api/admin/price-catalog/import/preview`、`/import` 带 `sheet`：`store` / `entertainment` / `room` / `dish` / `massage`）：只读这一张（文件里只有这一张、工作表名被改成「Sheet1」也认）；导成草稿时**只换这一张**，别的表照现在的草稿（没有草稿就照生效中的那份）原样带过来；条数对照只列这一张。别的照整份导入（预览摘要、操作编号与「结果待确认」、有问题整份不导、审计 `detail.sheet`）。
- **读法补充**：类型 / 房型 / 菜品分类 / 板块只在组首行写、后面留空（合并或没合并都一样）→ 留空沿用上一行；「中餐零点」「中式零点」统一成「中式零点」（`dishCategory`，PC31）；夜间票备注已经写了「含…」的不再加「含」。报错带文件名（`issue.file`）、工作表、行号、字段与原因。
- **各模块的模板**（`GET /api/admin/price-catalog/template?sheet=`）：照店主拆出来的那张表——门店、娱乐第 1 行门店名，房间价格 D、F 两列没有表头，零点菜品一张表四节（各有节标题与表头），按摩十列（不带核心定位、思路、评分）。不带 `sheet` 的照旧是六张表的总模板。
- **按模板格式导出**（`GET /api/admin/price-catalog/sets/:id/export-sheets?sheet=`，`sheet-io.ts`）：把这份价目表（页面改过的也在）按导入的格式写回去——「39/2h」「加钟/19.9」「399/2H起开」「超时199/H」「999封顶」「6小时：999」「包天：5000」「S301-S339」、轰趴房一个面积一行、客房过夜价与钟点价两列、零点四节、按摩双价或适用性别。导出的文件原样再导入，条目逐项一样（`tests/price-catalog-sheets.test.ts`；店主的五个表格本机核对过：导入 → 导出 → 再导入 10 / 8 / 9 / 131 / 67 项逐项一样）。只导出在用的条目（停用的不导出，导回去就没有了）；门票的名称照「12H 含餐 / 不含餐」生成，娱乐加钟按每 60 分钟（与导入同一个口径，PC31）。不带 `sheet` 的导出整份（五张表 + 储值政策）。原来的「导出这一份（逐项核对用）」照旧是核对表。
- **页面**（「价目与套餐 → 全品类价目表」）：导入卡片选「整份（六张表）」或「只导『某张表』」，模板按选的那张下载；「按模板格式导出」整份或某一张；地址带 `?sheet=room` 时导入目标与列表筛选直接是这一张。单条新增、改价、停用 / 启用、改动记录（旧值 → 新值、经办人、时间）、即时生效（改生效中的那份同步收银项目）照第 5、6 节；停用不删除，不另做物理删除。
- **各模块的入口**（`AdminShell.tsx` 的 `PriceSheetLink`）：门票（「价目与套餐 → 门票」）→ 门店价格；房态中心房型配置（「空间台账 → 房态中心房型」）→ 房间价格；餐饮菜品（「餐饮 → 菜品送到哪个档口」）→ 零点菜品价格；技师项目（「技师 → 需要技师的项目」，康美部的项目）→ 按摩及助浴价格。**娱乐价格没有单独的「娱乐项目管理」页**（系统里娱乐设施只是价目，没有别的管理页），不另加入口，在全品类价目表里选「娱乐价格」维护。

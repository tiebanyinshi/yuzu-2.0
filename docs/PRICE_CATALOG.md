## 2. 数据模型（迁移 `230_price_catalog.sql`）

- `price_catalog_sets`：一份价目表（导入的一份文件，或手工维护的一份）。`status`：草稿 `draft` / 生效 `active` / 停用 `retired`；一家门店同时最多一份草稿、一份生效。导入先落草稿；核对条数无误后再切换生效（第三批），原来生效的那份转停用，可以整体回滚到它。
- `price_catalog_entries`：价目表里的一项。
  - **价格形态** `price_mode`：
    - 双价 `dual`：专业价 `price_cents` + 资深价 `price2_cents`。
    - 单价 `single`：只有 `price_cents`。
    - 无价格 `none`：待定价或免费，两个价格都是**空值**、不存 0；页面写「待定价」，不写「0 元」。
    - 比例 `rate`：服务费 `rate_bp`，万分之几，10% = 1000，不在商品上存 0.1 元。
    - 数据库约束保证形态与价格列一致。
  - **金额**：一律整数分。「399/2H」「加钟/19.9」「688 元/位」这类写法拆成价格、时长、单位分别存：
    - 时长：`duration_minutes`，一律分钟——按摩服务时长、门票 12H / 24H、娱乐与房间的「基础价含几分钟」。
    - 加钟价（娱乐）/ 超时单价（房间）：`extra_price_cents`，加上每次多少分钟 `extra_minutes`。
    - 封顶价：`cap_cents`。
    - 台位数 / 房型总间数：`units_count`。
    - 房号清单：`room_numbers`。
    - 时段：`window_start` / `window_end`，0–1439 分钟，跨零点时结束小于开始。
    - 是否含餐：`includes_meal`。
    - 适用房型：`venues`，房间 / 大堂 / 浴区。
    - 适用性别：`gender`。
    - 核心人群、操作内容、项目亮点、备注。
  - **一项里还分档的** 放在 `variants`，每档有名称、价格、分钟、单位、房号、几人位：
    - 轰趴房按面积分 4 档，每档 6 小时 / 12 小时 / 包天；
    - 客房大房间、小房间的过夜价与 3 小时价；
    - 餐饮包房的三种位价与低消；
    - 棋牌房的 8H 价。
  - **板块 / 餐段**存在 `section`，**菜品分类**存在 `category`，**原始编号**存在 `code`，**表格行号**存在 `source_row`，便于与表格核对。
  - **不录内部参考字段**：成本、成本率、思路、核心定位都不录（需求说明第五节）。
  - **停用不删除**：停用是把 `active` 改成 false，不物理删除。
  - **能不能下单**：`orderable`。2 楼零点没有售价的菜录为「待定价」、不能下单，补价后启用（约束：菜品无价格时不能可下单）。

## 3. 导入（第一批）

- `GET /api/admin/price-catalog/template`：导入模板，与《价目表 1119》同结构的六张表（表头照原表，数据留空）。
- `POST /api/admin/price-catalog/import/preview`：读 `.xlsx`，六张表按工作表名认，逐行校验，返回：
  - 条目；
  - 问题：写明工作表、行号、字段与原因。`error` 挡导入，`warning` 只提醒；
  - 条数对照；
  - 预览摘要。
- `POST /api/admin/price-catalog/import`：带预览摘要。文件与预览时不一样的拒绝（`IMPORT_STALE`），有 `error` 的整份不导（`IMPORT_INVALID`）。导入成这家门店的草稿，替换原来的草稿（锁住原草稿行再删、再写），留审计（`price_catalog`，`detail.action = import`）。
- `GET /api/admin/price-catalog`：生效与草稿两份的概要与条数对照。`GET /api/admin/price-catalog/sets/:id`：一份价目表的全部条目。
- 权限沿用「管理充值套餐与消费项目」（`catalog.manage`；需求说明：不改权限模型）。

各表怎么读（合并单元格先把左上角的值填满整个合并区域；全角数字、冒号按半角认）：

| 工作表 | 读法 |
| --- | --- |
| 门店价格 | 门票：「项目」12H / 24H 是时长，「备注」含餐 / 不含餐，名称「门票 12H 含餐」。夜间票：「项目」是时段，21 点–次日 11 点。餐票：「时间」是供应时段（7:30–10:00……），名称「早餐餐票」。服务费：「价格」0.1 或 10%，存比例 |
| 娱乐价格 | 「39/2h」→ 基础价 39 元含 120 分钟；「备注」里的「加钟/19.9」→ 每 60 分钟 19.9 元；「数量」是台位数；只写一个价、没有时长与加钟的是畅玩卷（单次） |
| 房间价格 | 「399/2H起开」→ 起开价含 120 分钟；「超时199/H」→ 每 60 分钟 199 元；「999封顶」→ 封顶价；「699/8H」→ 一档。房号「S301-S339」「F301-307」「Q301 Q302」展开成清单。轰趴房合并的 4 行合成一项、一行一档（面积、房号、几人位、6 / 12 小时与包天）。客房按先后把大小房的过夜价与 3 小时价配成档。餐饮包房：位价、低消、超时 588 元/小时，开瓶费等原样留作备注 |
| 零点菜品价格 | 分段标题（「2楼餐厅零点菜品」「早餐自助零点菜品」……）定餐段，「菜品分类」向下沿用；没有售价的录「待定价」、不能下单 |
| 按摩及助浴价格 | 「板块分类」向下沿用，必须是 9 个板块之一；时长 80min / 80分钟 / 60' → 分钟；专业价、资深价都有为双价，只有专业价为单价；「资深价」一列写的是性别（女、男/女）的写进「适用性别」、不参与计价，写「—」的是没有资深价；名称带「女宾」的适用性别为女；「类型」房间 / 大堂 / 浴区 → 适用房型 |

挡导入的问题：
- 少了某张表、表头不对；
- 价格为空（零点菜品除外，菜品没写售价是「待定价」）、价格写法看不懂；
- 时长格式不支持、时段看不懂；
- 名称重复：同一个板块里，或同一个餐段同一个分类里；
- 板块不存在、餐段不认识。

只提醒的：
- 菜品待定价；
- 表格自相矛盾，请门店核对：
  - 房型的总间数与房号清单算出来的个数对不上（原表 SPA 房写 35 间、S301–S339 是 39 个；按摩房 30 间、M301–M329 是 29 个；足浴情侣房 6 间、F301–307 是 7 个；客房 7 间、R01–R08 是 8 个；轰趴房 9 间、H201–H210 是 10 个）；
  - 轰趴房 100 平、150 平的 12 小时价比 6 小时价低。

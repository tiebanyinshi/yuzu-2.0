# 福田店老数据迁移：核对、配置与导入步骤

店主 2026-11-24 发来《汤崎数据迁移 11.26》压缩包（福田旧收银系统导出的导入模板，约 45 个 xlsx，不进仓库），要求：看本系统能不能装下这些老数据、配置按实际业务改、写好说明让服务器助手（Codex）能直接导入。

本文是核对结论与做法。第 1 节是先要店主定的事，第 2 节逐份文件的对应与问题，第 3 节要改的配置与代码（分批），第 4 节是给 Codex 的导入步骤。数字都来自压缩包本身（只数条数、看表头与取值分布，没有把会员、员工的个人信息抄进仓库）。

## 0. 前提：福田作为第二家门店

本系统 8.0.22 起支持多门店（`docs/MULTISTORE_V8022.md`）：宝安是 1 号本店，福田建成第二家门店（代码建议 `FT`）。

- **按店分开的**：手牌、来访与账单、班次、日结、房间与房型、技师与技师分组、桌台、设备、空间台账、房态中心房型、员工的所属门店、价目表（每家一份，第二家店写本店价）、各店规则设置。
- **全公司一份的**：会员与钱包、券、次卡、权益、收银项目（第二家店只能设本店价，不能有自己独有的项目）、出品档口、技师工种、部门、工号与手机号唯一。
- 页面上的导入（员工批量开通、空间台账、手牌、菜品）**按操作人当前所在的门店**落库：先在右上角切到福田再导。
- 命令行的导入（`import-hand-tags`、`import-opening` 等）**目前一律落到 1 号本店**，福田要用必须先加 `--store FT`（第 3 节第一批）。

## 1. 要店主先定的事

会员储值是最大的一块，而且和店主 2026-11-03 定过的规则冲突，**没定之前不导会员余额**：

1. **福田会员要不要并进本系统、两店通用一个钱包？** 2026-11-03（`docs/MEMBERSHIP.md`、PENDING M1）定的是「福田不用本系统收银，只开只读查询，不通卡」；8.0.22 的多门店（MD2）是全公司一个钱包。导入福田余额就等于通卡，要店主明确改 M1。价目表里写的「储值政策：同步大客部门，建议两店通用」也指向通卡，请确认。
2. **余额总数要核对**：会员卡文件 65,524 张卡，「储值余额合计」加起来约 **6,204 万元**，有余额的 36,187 张。这个数量级要旧系统（或财务）出一份**控制总数**（人数、本金、赠金）对上才能导；正式库的期初导入本来就强制要控制总数。
3. **本金 / 赠金怎么分**：文件只有「储值余额合计」，「储值余额」「赠送余额」「可用 / 限制」几列全是空的。默认全部记本金（赠金为 0），待确认。
4. **过期卡**：有效期在 2015–2018 年的卡很多，还有余额的照导、冻结还是排除？默认：照导（余额是对客的负债，不因卡过期清零），在会员备注里写原卡有效期，待确认。
5. **一个手机号多张卡**（6,817 个重复手机号）：本系统一个会员一个钱包、只能有一张在用的卡。默认把同一手机号的余额加总成一个会员，原卡号都记在期初记录与备注里，待确认。
6. **没有手机号的卡**（16,481 张）：本系统会员可以是不记名卡，但期初导入现在要手机号。默认：有余额的先放进排除清单（单独一份表，店里补登手机号后再导），零余额的不导，待确认。
7. **68 种会员卡类型**（畅享卡、二星、三星、尊享卡、珍珠卡、崎士卡、积分卡……）对应本系统哪一档会员等级（L0–L6）？本系统按累计充值定档，文件里没有累计充值。默认：全部先 L0，卡类型记成会员标签（分组「福田旧卡」），等店主给对照表再调档，待确认。
8. **积分余额、卡押金、卡密码、身份证号、邮箱**：本系统没有积分、没有会员密码；卡押金有台账但没有「期初押金」。默认：积分、密码不导；身份证号不导（敏感）；邮箱不导；卡押金单独列一份清单给财务，待确认。
9. **项目与菜品**：福田的技师项目（90 行）、房费项目（26）、计时项目（6）、菜品（约 858 道）是与宝安共用收银项目（同名的用宝安的项目、福田设本店价），还是福田另有一份？本系统收银项目全公司一份、第二家店只能设本店价，**福田独有的项目宝安也会看到**。默认：福田另做一份《福田价目表》（与宝安 1119 同样的五张表），在福田门店里导入全品类价目表，同名的对上宝安的项目写本店价，福田独有的新建（宝安那边在自己的价目表里不卖就不显示在价目表分类里），待确认。
10. **消费分区与业态**（楼层部、休闲部、上善汇、1 号公馆、净桑、综合娱乐区、餐饮区、女宾部）、**KTV、网吧**：本系统没有「消费分区」，最接近的是空间台账的区域、项目的分类（部门营业额按分类算）。默认：消费分区建成福田空间台账的区域；KTV、网吧先当「开单即占用」的业态（按时长收房费），待确认。
11. **休息大厅、睡眠区、网吧的座位**（房间列表 715 行里大部分）：一座一张卡片（房态中心「设数量」按床位建）还是一个大厅？默认一座一张，和宝安的休息大厅一样，待确认。
12. **部门与岗位**：福田 15 个部门、23 种角色，本系统部门是固定的一份，岗位只有负责人 / 员工，细的权限再按人调。默认按第 2.3 节的对照表并部门，休闲部、楼层部、上善汇要不要新增部门待确认（新增部门要改代码）。
13. **手牌**：用 12.10 的 1,250 张（已整理过）还是源数据 2,220 张？默认用 12.10。散客 / 儿童 / 便衣客 / 虚拟 / 公司内部这些类型本系统没有（只有普通 / VIP），默认都当普通；手牌 ID（RFID 卡号）要一起导。
14. **智能设备（沙发电视 268 台）与网吧设备（36 台）**：本系统的设备只有打印机、读卡器这类收银外设。默认不导，待确认（要管的话另做资产台账）。
15. **线上平台套餐**（高德、美团、客路）：本系统团购平台只有美团、点评、抖音、其他。默认高德、客路先记「其他」，待确认。

## 2. 逐份文件的对应

同一类有好几个版本的（源数据 / 重复 / 补充 / 郑荣给），默认用**最后整理的那一份**（下表「用哪份」），其余只作核对。

### 2.1 会员卡（`会员卡导入模版（汤崎导入）.xlsx`，65,524 行）

- 落到：会员（全公司）+ 期初导入（`import-opening`，本金 / 赠金分开记「期初导入」流水，不算充值实收）+ 会员标签（原卡类型）。
- 现在的期初导入挡住的地方：手机号必填、11 位、文件内不能重复；一次最多 5,000 行；手机号已是会员但名字不同的拒绝；已有有效期初的会员不能再导（宝安已经导过的同一个人，福田的余额要另外的办法）；正式库必须给控制总数。
- 要加的（第三批）：按第 1 节定下的规则把福田的卡**先转成期初导入的格式**（一个手机号一行、加总余额、原卡号与卡类型写进备注 / 标签、排除清单另出一份），再分批导；期初导入记上「门店」，否则门店间结算会把福田的会员算成宝安的（结算按会员第一笔充值所在的门店定归属）。

### 2.2 储值卡（`储值卡导入模版`）

空表，不用导。

### 2.3 员工账号（`员工账号导入模板（郑荣给）.xlsx`，288 行）

- 落到：员工账号 + 员工档案 + 所属门店（福田），用后台「组织架构 → 批量开通」（OA-02），先切到福田门店再导，一次最多 200 行（分两批）。
- 列对应：姓名、手机号（必填、在职员工里唯一）、工号（全公司唯一，福田工号和宝安撞了要加前缀，默认加 `FT`）、部门（必填）、岗位（负责人 / 员工）、入职日期。员工卡号、性别、邮箱没有地方放。
- 部门对照（本系统的部门：总经办、人力行政部、财务部、前厅部、男宾部、女宾部、保健部、康美部、娱乐部、餐饮部、出品部、工程部、外联部、大客户部；默认，待确认）：同名的直接对上（前厅部、娱乐部、保健部、男宾部、女宾部、财务部、总经办——总经办只能店主手工建）；餐厅部、餐饮部 → 餐饮部；客户部 → 大客户部；品牌部 → 外联部；电脑部 → 工程部；休闲部、楼层部、上善汇 → 待定（本系统没有，要么并到最接近的部门——休闲部、楼层部的服务员与输单员多半对应前厅 / 康美——要么新增部门，新增要改代码）。角色里带「主管 / 经理」的记负责人，其余员工；收银员、输单员、技管组等细权限导入后按人调。

### 2.4 技师（`技师导入模板(1) (1).xlsx` 437 行 + `技师导入模板数据补充1.13（郑荣给）.xlsx`）

- 落到：福田门店的技师名册（技师号在本店唯一、1–6 位字母数字）与技师分组；用命令行 `import-technicians`（8.1.35 第二批）直接读旧系统的这份模板。
- 等级「标准 / 专业 / 优选」和本系统三档一致（决定技师能做哪一档价）；没写的按「标准」。
- 用这份文件预览（演示库、只预览）的结果：能导 333 位（标准 268、专业 52、优选 13；测试组 6 位跳过），会建 25 个分组；**98 行要先改**：
  - 51 行的等级是旧系统的星级（一星 6、三星 14、五星 12、七星 18、八星 1），本系统没有——店主给对照，用 `--grade-map 一星=标准,三星=标准,五星=专业,七星=优选,八星=优选` 这样写（**对照待店主定**）；
  - 46 行没写性别（必填，店里补上）；
  - 1 行姓名超过 16 个字。
  - 分组里有「x」「固定组(大堂)」「培训老师」「美甲组」这样的名字，导入前店里确认要不要（不要的用 `--skip-group` 跳过，导入后也能在后台改名、停用）。
- 没有地方放的：是否挂牌 / 挂牌日期、物理卡 ID、介绍人、身份证、出生日期、籍贯、身高体重、英文名、手机号。默认不导（身份证等敏感）。
- 补充文件（1.13）是另外 16 位，表头一样，改好以后同样导一次（技师号已有的会跳过）。

### 2.5 技师项目、房费项目、计时项目

- 技师项目（`技师项目导入模版.xlsx` 90 行，一个项目按等级一行）：转成《福田价目表》的「按摩及助浴」表（专业价 / 资深价）再在福田导入全品类价目表；「买假项目」不是卖的项目（请假在本系统是技师请假），不导；会员价、预估成本、条形码、准备 / 结束时长没有地方放。
- 房费项目（12.10 版 26 行）：商务房、钟点房、客房 → 客房的房型与房价（福田门店里建）；8 个「钟消」房、棋牌、桌游、情侣电影院 → 开单即占用的业态 + 房费项目；平日 / 节假日两个价本系统没有，默认按平日价。
- 计时项目（6 行：电玩、Xbox、乒乓球、桌球、二楼 / 三楼网吧）→ 价目表「娱乐」表（按时长）或开单即占用。

### 2.6 房间列表（715 行）

- 落到：福田的空间台账（先建楼层、区域，再导空间；编码要符合「大写字母开头、2–8 位字母数字」，原房号不合格的转码，原房号写进显示名）+ 房态中心房型。
- 22 种房间类型：休息 A–F 区、睡眠区、(女宾) 睡眠区、网吧 → 休息大厅（一座一张）；中式房、泰式房、一中一泰、香薰房、SPA 房、足浴按摩房、周转房 → 按摩 / 足浴 / SPA 房；棋牌室、足浴麻将房、桌游房 → 开单即占用；客房 8 间 → 客房；**无效房 2 间不导**。

### 2.7 桌台（`桌台列表导入模板（未重复）.xlsx` 56 张）

- 落到：福田门店的桌台（名称 ≤12 字、区域、座位数）。桌台类型写进区域（餐厅散台、餐厅 N 人包房、KTV、外卖）。外卖「桌台」是虚拟的，默认不导。没有导入器，量少，默认后台手工建或第二批顺带做。

### 2.8 手牌（`手牌管理导入模板（12.10）.xlsx` 1,250 张）

- 落到：福田门店的手牌池（牌号「0–2 个字母 + 1–5 位数字」、男 / 女区、普通 / VIP、RFID 卡号）。
- 现有导入（`import-hand-tags`、后台手牌导入）不带 RFID 卡号这一列、命令行不能指定门店；手牌区域（T 区、共用柜、A1–A3……）本系统按牌号前缀认，不合的只能记备注。要改（第一批：`--store`、RFID 列）。

### 2.9 菜品（`菜品导入模板2.2补充.xlsx` 的「菜品（最终）」858 道）

- 落到：收银项目（全公司一份）+ 福田本店价。菜品导入按名称对，和宝安同名的会改到宝安的价——**不能直接用现有的菜品导入**。默认：并进《福田价目表》的「零点菜品」表，在福田导入全品类价目表（同名的写本店价，福田独有的新建）；规格超过三档、称重、保质期、起售份数没有地方放。

### 2.10 其余

- 技师班次（16 行周排班）：本系统按人按天排班，没有「周模板」，导入后在技师排班里手工排。
- 智能设备、网吧设备：默认不导（第 1 节第 14 条）。
- 线上套餐、优惠套餐、套餐配置草稿：团购核销按平台和套餐名记，不用导；平台名见第 1 节第 15 条。
- 领券会员模板：本系统发券按等级 / 标签选人，没有按名单发；需要时先给名单打标签再按标签发。
- 短信签名注册：不是数据，是短信平台的手续。

## 3. 要改的配置与代码（分批）

- **第一批（8.1.35，已做）**：命令行导入加 `--store <门店代码>`（`import-hand-tags`、`import-opening`、`import-count-cards`；整条命令在那家店里跑，不认的命令带 `--store` 直接拒绝，宝安的内置柜号清单不能导到别的店）；本文与第 4 节步骤。手牌导入的 RFID 卡号列放到第二批。
- **第二批（8.1.35，已做技师）**：技师名册导入 `import-technicians <技师导入模板.xlsx|csv> --store FT [--grade-map …] [--skip-group 测试组] [--skip-invalid] [--apply]`——直接读旧模板（表头前的填写须知跳过）、技师号已有的跳过、分组没有的建、整批一个事务、记审计，默认只预览。手牌导入的 RFID 卡号列还没做。
- **第三批（店主定了第 1 节 1–8 条以后）**：福田会员卡转换脚本（读压缩包里的会员卡文件 → 按规则出期初导入 CSV + 排除清单 + 标签清单 + 汇总，对控制总数）；期初导入记门店。
- 配置（不改代码，Codex 在后台做）：建门店 FT 与主体；福田的营业日、钱箱、规则设置；楼层、区域、空间；房态中心房型；客房房型；福田价目表。

## 4. 给 Codex 的导入步骤（福田）

照 AGENTS.md「环境隔离」：真实数据只在店主同意的环境导；**先在独立演示库用同一批文件演练**（不碰正式库），核对条数与自检全 ✓ 再上正式服；正式服导入前先备份（`./scripts/update.sh` 自带，或 `cli.js backup`）。每一步都是先预览再 `--apply` / 确认。

1. 后台「门店与主体」建福田门店（代码 `FT`）与所属主体；给要用福田的员工挂上门店。之后的页面操作先在右上角切到福田。
2. 福田的规则设置：营业日起始、钱箱、前台规则、技师规则、餐饮 / 客房开关（按福田实际）。
3. 空间：建楼层、区域（消费分区 → 区域），用「空间台账 → 导入」导房间列表（第 2.6 节转好编码的那份）；房态中心房型「设数量」补床位；客房在「客房」里建房型与房间。
4. 员工：「组织架构 → 批量开通」分两批导 288 人（第 2.3 节对照好部门、工号加 `FT`）。

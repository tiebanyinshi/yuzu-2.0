## 1. 单项打折

### 1.1 怎么用

收银台账单每一行右边多一个「折」。点开以后二选一：

- 按折扣：敲几折（8 = 八折，8.5 = 八五折，0 = 免单），常用的 9.5 / 9 / 8.8 / 8.5 / 8 / 7 / 5 / 免单 有现成的按钮；折后价四舍五入到分；
- 填折后价：直接写这一行收多少。

原因选填。打过的行再点「折」可以改成别的折扣，或「恢复原价」。门票不能单项打折（按在店时长计价，要降价请改票种）。

### 1.2 谁能打、打到多少

按岗位分四档，每档一个下限（最低收原价的百分之几），在后台「手牌与前台 → 前台规则 → 收银台：单项打折与押金」改：

| 档         | 谁                                     | 默认下限（待确认） |
| ---------- | -------------------------------------- | ------------------ |
| 前台收银等 | 其余有「结账收款」权限的               | 90（最低九折）     |
| 值班经理   | 旧岗位是值班经理的                     | 70（最低七折）     |
| 部门负责人 | 店总、总经办成员、各部门「负责人」岗位 | 50（最低五折）     |
| 店主       | 店主、总裁                             | 0（能免单）        |

高一档的下限不能比低一档高（保存时核对）。超过自己那一档的，页面弹「请经理授权」，复用原来的当场授权（`/api/auth/authorize`，用途 `line_discount`）：授权绑定这一行、此刻的原价与折后价，5 分钟内用一次；授权人要有「当场授权优惠」的权限，**而且他那一档的下限够打到这个价**（值班经理授权不了五折，店主能授权免单）。签发时、核销时各核对一次（核销时下限改了也拒绝）。

### 1.3 钱怎么记、与会员折扣怎么叠加

- **明细不改**：`bill_lines` 的金额照旧是原价（只追加的规矩、钟单、出品单、技师的钟数都不受影响）。折扣记在新表 `bill_line_discounts`（原价、折后价、几折、档与下限、谁打的、谁授权、原因、操作编号），只能从「有效」改成「已撤下」，不能改、不能删（触发器）；一行同时只有一条有效（部分唯一索引）。
- **账单与结账核对**：账单详情每一行带上折扣，账单合计显示折后（「原价 ¥… · 单项打折已减 ¥…」）；结账核对多给 `lineDiscountAmount`（每位客人 `lineDiscount`）。
- **结账**：应收合计照旧按原价算（`checkouts.total_amount`、`checkout_bills` 与自检的口径都不变），服务端在来访、账单的锁里算这几张账单上有效的折扣合计，记一笔收款明细「单项折扣」（`checkout_payments.method = 'line_discount'`，优惠、不是收款，一张结账单最多一笔），员工只要收 **应收 − 单项折扣**。页面带上确认时看到的折扣合计（`expectedLineDiscount`），与此刻的不一致拒绝（`PRICE_CHANGED`）。
- **叠加顺序（待确认 8.2.1-2）**：先单项打折；**打过单项折扣的行不再用会员折扣、券、次卡**（不打折上折——这几样都从 `couponLines` 取明细，那里把打过折的行去掉）；整单的「优惠 / 免单」照旧能一起用，部门快照里按折后的金额比例分摊。
- **部门营业额快照**（`yuzu_snapshot_checkout_items`，迁移 530 换了一版）：单项折扣按行记到那一行的部门与项目（`checkout_items.discount`），整单优惠按折后金额分摊，券与会员折扣照旧按适用的明细；已有的结账单没有单项折扣，算出来与原来一样。自检 ⑮「快照的优惠合计 = 这张结账单的优惠」把单项折扣算进去。
- **报表口径**：日结、看板、报表、客户部把「单项折扣」算进「优惠」一列（`businessBreakdown` 的 `discount`），净营业额 = 应收 − 优惠（含单项折扣）− 券抵扣 − 会员折扣 − 退款；实收不受影响。
- **反结账**：照旧撤销结账单；账单恢复在店，折扣还在那一行上，重新结账再记一笔。
- **转单**：打过折的行不能直接转（`LINE_NOT_MOVABLE`），先恢复原价、转过去以后在那张手牌上再打——折扣跟着原账单，避免转过去变回原价没人发现。
- 都带操作编号（`line_discount`，写编号前核对「确认作废」），结果待确认照前台的做法（对话框里查回 / 原样重提 / 确认作废）；审计 `frontdesk_line_discount`、`frontdesk_line_discount_revoke`。

## 2. 一键快捷键（发卡台、收银台）

### 2.1 原来为什么「要先把鼠标移到按钮上」

查了 `CashierPage.tsx`、`FrontdeskPage.tsx` 原来的写法：

1. 两个台各自在 `window` 上听 `keydown`（冒泡阶段），只有发卡台 F2、收银台 F4 / F6 / F8 / F9；**打单、充卡、组合拆分、备注都没有键**，只能移鼠标去点；
2. 收银台的 F 键要求「已经打开了一位客人」，发卡台的组合拆分在「更多」菜单里——**没打开手牌时按键什么也不发生**；
3. **有对话框开着时也什么都不发生**，而且没有任何提示，店员以为键坏了，只好去点按钮；
4. 页面里的输入框、读卡器的牌号框会先处理按键，冒泡到 `window` 的监听有时收不到。

### 2.2 现在

- 一张表管两个台的键（`src/client/features/frontdesk/hotkeys.tsx` 的 `DESK_HOTKEYS`），按钮上写键位，页头「快捷键」或按 `?` 看一览：

| 键  | 做什么               | 哪个台                                           |
| --- | -------------------- | ------------------------------------------------ |
| F1  | 充卡（会员充值）     | 两个台                                           |
| F2  | 接待发牌             | 发卡台                                           |
| F3  | 备注（光标进备注框） | 两个台                                           |
| F4  | 加项目               | 收银台                                           |
| F6  | 买角（敲数字代号）   | 收银台                                           |
| F7  | 组合 / 拆分同行手牌  | 两个台                                           |
| F8  | 预结账               | 收银台                                           |
| F9  | 买单（结账）         | 两个台（发卡台带着这张手牌到收银台直接打开结账） |
| F10 | 打单（打预结单）     | 两个台                                           |
| ?   | 快捷键一览           | 两个台                                           |

- 在**捕获阶段**听，先于页面里的输入框；只认 F 键（输入框里打字不会误触），`?` 在输入框里不算；F5 是浏览器刷新，不占。苹果笔记本上 F 键照旧要按住 fn（演示里说的防误触）。
- **没打开手牌时先弹「选手牌」**：刷手牌或输牌号（末位即可）回车，选好了接着做，不用再按一次。
- **有对话框开着时**不叠第二个对话框，提示「先关掉现在的对话框（Esc），再按 F9 买单」。
- 充卡：这张手牌上有会员的，到会员工作台直接打开这位会员的充值；没有会员的到工作台查会员（或新建）。
- 组合 / 拆分（F7，两个台都有，收银台也加了「同行」按钮）：这位客人还没有同行时选另一张在店的手牌组成同行（按键后依次选两个手牌）；已经在同行组里时问「移出同行组」（回车确认），也可以改为与别的客人同行。
- 盲打牌号照旧：在页面任意位置直接敲数字或字母进牌号框。

## 3. 经办人前置与改价、折、赠标记

账单的每一行最上面先写经办人：**工号 · 姓名 · 手机尾号 4 位 · 时间**（工号、手机号取员工档案 `staff_profiles`，没建档案的只写姓名）。行名前面有角标：

- 「改价」：手动定的价——手动金额（不是丢牌赔偿、房费、门票）、时价 / 杂项、称重的菜；
- 「折」：单项打了折；
- 「赠」：单项免单（折后 0 元）。

打过折的行下面一行写「原价 ¥… · 8 折 · 减 ¥… · 工号 姓名 打，某某授权（原因）」，行的金额写折后。结账单、小票上「单项折扣」作为一笔优惠列出。

## 4. 换牌规则

换牌原因选「手牌丢失」才默认勾「锁定原手牌」并收丢牌赔偿；「柜锁故障」「手牌损坏」「顾客要求换柜」都**不锁**原牌（原来是除了顾客要求换柜都锁，柜锁故障锁了原牌是错的）。确实要停用的手动勾选。服务端的默认本来就是不锁（`lockOld` 默认 false），收赔偿时必须锁照旧；原因字典（`src/shared/custom-fields.ts` 的 `swapReasons`）不变。

## 5. 手牌押金

- **收**：账单（两个台都有）里的「押金」一块 →「收押金」：现金、微信、支付宝、银行卡，或从**这张手牌上的会员**的储值扣；金额先填后台设的默认（100 元，后台「收银台：单项打折与押金」改），原因有「外出留牌」「去其他区域」「借用物品」可选、也能手写。押金单号 `YJ…`。储值扣的记一张储值消费单「手牌押金 YJ…」（单笔上限、充值当日额度、扣款规则与结账用储值相同，确认时的本金 / 赠金构成对不上拒绝），这张消费单不能在会员那里单独撤销（`DEPOSIT_LINKED`）。
- **一键退**：押金那一行点「一键退」（储值的写「退回储值」）：现金类按原方式退，储值扣的按原单撤销，本金、赠金原样退回原卡。
- **结账时抵扣**：结账核对列出押着的押金；结账的事务里一起退掉（`refund_kind = checkout`，记上结账单）。页面按现金类押金先填好**同样方式**的收款（抵扣），押金比应收多的提示「当面退给客人 ¥…」，抵扣后还要收多少也写出来；储值扣的先退回原卡，结账核对给的会员余额已经算上退回的钱，之后的储值支付按退回以后的余额扣。
- **撤销来访**：押着押金的不能撤销，先退押金（`DEPOSIT_HELD`）。
- **交班与日结**：押金是负债、不算营业额。收、退都记经办人当班的班次；交班表的「押金」一块（原来只有客房押金）把手牌押金的现金类收、退合进去，现金计入应有现金；日结的押金一块同样合进去，「当天结束时押着的押金」也算上手牌押金。储值扣的不是钱箱里的钱，不列在交班、日结的押金里（会员日结里是消费单与撤销单）。
- 表 `tag_deposits`：一笔一行，只能从「押着」改成「已退」（触发器），退的时候记谁、何时、哪个班次、哪种退法（一键退 / 结账时退）、储值的撤销单、结账单。
- 都带操作编号（`tag_deposit`、`tag_deposit_refund`），结果待确认照前台的做法（押金对话框里处理）；审计 `tag_deposit_received`、`tag_deposit_refunded`。

## 7. 没做的

- 押金没有单独的快捷键（F 键已经用满，按钮在账单里）；押金没有罚没（客人不回来的押金怎么处理待店主定）。
- 单项打折只在手牌账单上（收银台）；桌台结账（餐饮）的账单不能单项打折，照旧用整单优惠 / 免单。
- 「明细查询：从消费记录跳转查看消费明细」「培训知识库」不在这一批。

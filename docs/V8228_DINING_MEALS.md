# 8.2.8 餐厅：入口刷手牌、含餐抵扣、裸票时段价、餐台与餐包

需求来源：店主 2026-11-27《新店系统需求现场走场确认》第一节「餐厅与餐饮」第 1 条与第四节待办（「餐厅增加餐包概念……后台区分餐包不减免、餐台计入减免」）。
同一份文件的水吧（首杯免费、赠标签、取餐叫号）在 8.2.9，休闲娱乐在 8.2.10，泡池在 8.2.10。

## 1. 店主的原话怎么落到系统里

| 原话                                                                                                                       | 系统里                                                                                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 入口统一刷手牌：所有进餐厅的人都要刷手牌，餐厅只负责输单，最终在前台结算                                                   | 餐饮新页面「餐厅入口」：刷手牌（或敲牌号）登记进餐；餐费、点的菜都挂到这张手牌上，照旧在前台收银台结账                                                                                                         |
| 含餐与裸票：手牌含餐时餐费后台抵扣 / 记零；裸票按早餐 / 夜宵 99、午餐 199、晚餐 299 等时段价收取，后台票价要做成可以配置的 | 票种加「含几餐」；后台「餐饮规则」加「餐段与餐费」（早餐、午餐、晚餐、夜宵的起止时间与价钱，可改）。入口刷手牌时按此刻的餐段记一行餐费：含餐还有余额的这一行**原价照记、自动折成 0**（标「含餐」），裸票照价收 |

## 2. 规则

### 2.1 餐段与餐费（后台「餐饮规则」）

默认（都能改；`docs/PENDING_DECISIONS.md` 8.2.8-1）：

| 餐段 | 时间             | 裸票餐费 |
| ---- | ---------------- | -------- |
| 早餐 | 06:00–10:30      | ¥99      |
| 午餐 | 11:00–14:30      | ¥199     |
| 晚餐 | 17:00–21:00      | ¥299     |
| 夜宵 | 22:00–次日 02:00 | ¥99      |

不在任何餐段的时间刷入口：提示「现在不是供餐时间」，不登记。

### 2.2 含餐

票种加两项「12 小时档含几餐」「24 小时档含几餐」（默认 0 = 不含餐；升级时名字是「含餐门票」的按原来写在备注里的 2 餐 / 3 餐填上）。
这次来访按门票此刻的档（在店不到 12 小时按 12 小时档，满了按 24 小时档）能用几餐；已经登记过的餐数够了就照裸票收。

### 2.3 入口登记

- 一位客人（一张手牌）同一个营业日的同一个餐段只登记一次；再刷提示「这一餐已经登记过了」；
- 登记 = 在这张手牌上记一行餐费（「午餐自助」等，金额是这个餐段的价钱，记在「餐饮」）：
  - 含餐还有余额：同一笔里给这一行记一条**自动折扣**（折到 0，原因「含餐」），结账时照单项打折的规矩记「单项折扣」；
  - 裸票：照价收；
- 锁牌外出、已结账的手牌不能登记；
- 登记带操作编号（`meal_entry`），结果待确认照前台的做法；查回、确认作废走餐厅的 `/api/dining/meal-entry-ops`（按「在餐厅下单」的权限，平板也能处理）；
- 登记时带上预览看到的那位客人，锁住以后再核对牌还在他手上（换了牌、结账后又发出去的拒绝，不记到别人头上）；
- 入口登记的餐费不能转单（挂错了作废后重新登记）。

### 2.4 餐台点菜折零

登记了这一餐（此刻的餐段）的客人，在**餐厅出品口**点的菜（手牌点单）：明细照原价记，同一笔里自动折成 0（原因「自助」）。
水吧、果吧的不算（8.2.9 另有首杯免费）；桌台点单（餐包）照价收。

### 2.5 自动折扣（「含餐」「自助」，以及 8.2.9 的「首杯赠」）

照 8.2.1 单项打折的那张表记（`bill_line_discounts`），多一档 `auto`（系统按规则打的，没有授权人），记规则名。
账单、结账单、小票上与单项打折一样标「赠」（折到 0）、写原价；结账时一起记一笔「单项折扣」；作废那一行时一起撤下。
收银员可以撤下自动折扣（照撤下单项打折的权限）。

## 3. 页面

- 餐饮新页面「餐厅入口」（权限「在餐厅下单」）：刷手牌 → 显示客人、票种、此刻餐段；按「登记进餐」→ 显示这一餐收多少（含餐：剩几餐、本餐 0 元）；当天已登记的客人列在下面；
- 后台「餐饮规则」加「餐段与餐费」；后台「票种」加「含几餐」。

## 4. 数据与锁

迁移 `600`：

- `ticket_types.meals_12h`、`meals_24h`（含几餐，默认 0）；
- `meal_entries`：入口登记（来访、营业日、餐段、含餐 / 裸票、那一行餐费明细、操作编号、经办人），同一来访同一营业日同一餐段唯一；只追加；
- `bill_line_discounts`：档 `tier` 加 `auto`、加 `rule`（`included_meal` / `buffet` / 8.2.9 的 `first_cup`），`auto` 的规则必填、不要授权；
- 操作编号与「确认作废」追加 `meal_entry`。

加锁顺序：入口登记走挂账（`postChargesTx`：来访 → 账单 → …），在锁住来访以后核对这一餐有没有登记过、写登记与自动折扣；餐台点菜折零在挂账的同一个事务里、写完明细以后记。

## 5. 没做的 / 要店主定的

- 餐包「单独的减免规则」具体是什么（例如包厢按人数送菜、满减）：这一版只做到「餐包不参与含餐、自助的减免」，具体规则等店主给（8.2.8-5）；
- 含餐几餐按 12 / 24 小时档算，不按具体哪几餐（早、午、晚）分开计（8.2.8-2）；
- 纸质菜单照旧；平板点单（电子菜单）照旧按桌台点（餐包）。

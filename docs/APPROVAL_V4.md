# 业财法审批流（V4.0，P01–P07）

店主 2026-11-26 交来《业财法审批流开发批次拆分与执行说明-从零梳理版》（以下简称「执行说明」）、42 项任务清单和功能结构图，要求通读后按批次开发，中途不停。执行说明依据的《汤崎审批流程_需求设计 PR 包 V4.0》（PR.md、`docs/00_统一流程底稿.md`、`docs/08_验收案例.md` 共 48 个场景）没有一起给到，仓库里也找不到。所以这里以执行说明和任务清单为准。验收场景只按编号和清单里的规则来理解，等拿到原包再逐条对照（见 `PENDING_DECISIONS.md` 的 AV01）。

服务对象：宝安汤崎、池里、PAJAMA、新生乐园。目标是建一套共用的业财法审批底座：正常事项走得快，重大风险有人负责，供应商、SKU、合同、付款、备用金、人力付款全链路可以追溯。

## 1. 和现有审批中心的关系

现有的「审批中心」（`docs/APPROVALS.md`，迁移 073/076，`modules/approvals`）只服务采购单、物资单据、付款、报销、合同、付款申请这些已有单据。它的约束是：
- 审批链最多 3 级；
- 岗位组只有负责人、财务、店总、店主、法务；
- 店主算在每一组里。

执行说明要求「全部按从未开发处理」：
- 4 级以上的链路；
- CFO、经营主体负责人、董事长等角色映射，且不能拿店主顶替；
- 会签；
- 知会；
- 回避；
- 履约执行人和内控节点。

两者差异太大。所以新建「业财法」模块（表前缀 `gf_`，代码在 `modules/govflow`、`shared/govflow.ts`），共用登录、员工、部门、经营主体（`legal_entities`）、站内通知和审计，不改动现有审批中心的行为。

## 3. P01 审批引擎与角色底座（迁移 `400_govflow_core.sql`）

### 3.1 角色映射（P01-02）

角色共 13 个：
- 财务审核人、财总、CFO、法务；
- 经营主体负责人（CEO）、董事长、业态总经理；
- 供应链负责人、章证管理员、出纳；
- 内部履约执行人、内控、人力资源。

配置规则：
- 店主在「WCP → 业财法审批 → 角色映射」里把真实账号配进去，权限是 `gf.roles`，默认只给总裁。
- 一个角色可以配多个人，可以限定在某个经营主体。
- 撤销只记时间，不删记录。
- 店主不在任何角色里，也不自动顶替这些角色。
- 部门负责人取组织架构里的部门负责人（`departments.head_id`）。
- 全系统最高角色称「董事长」，不出现「集团总裁」。

### 3.2 审批链（P01-01、03、06、07）

节点有四种：
- 部门负责人；
- 内部履约执行人；
- 某个角色（其中任意一人同意即可）；
- 几个角色各由不同的人同意（`all`）。

`all` 同时覆盖两种用法：
- 「财总＋CFO 共同审批」：两人都同意才通过，任一人驳回就不通过。备用金超额特批、HR 付款、月度额度核定都复用这个节点（`COSIGN_FINANCE_CFO`）。
- 「财务、法务分别审核」：并行分审，分别出结论。

同一级里一个人只能占一席，数据库里有唯一索引兜底。链路最多 12 级。

每个节点标注性质：
- 审核；
- 终审（金额或风险终审）；
- 特批。

排链在提交时完成（纯函数 `planFlow`），结果存进这一轮审批：
- **履约执行人 +1**：合同类事项在部门负责人之后、财法之前插入履约执行人。履约执行人和部门负责人是同一人时不重复（场景 43）。
- **内控参与**：事项带了招标、单一来源、新供应商、核心品类、价格异常任一标记时，在终审前加一级内控。常规库内业务不加签（场景 47）。内控的周报和月度审核放在 P03 和 P06。
- **回避**：终审和特批节点里，提交人和「事项本人」（报销人、收款员工等）都不能审（场景 12）。
  - 角色里还有别人的，节点保留，由别人审。
  - 没有别人的，按 财务审核人 → 财总 → CFO → CEO → 董事长 往上移一级。会签节点上移时会避开节点里已有的角色。
  - 董事长本人的事项，如果没有另一位董事长，节点保留，并提示店主加一位授权人。
- 每一级在提交时都要确认现在有人能审，没人的不让提交（`GF_NO_APPROVER`），避免卡在半路。
- 部门负责人自己发起，或履约执行人本人发起的，那一级视同已确认，记一条「自动跳过」。

审批动作：
- **同意**：坐上一席。
- **退回**：发起人改了再提交，从第 1 级走新一轮。
- **驳回**：不通过，这个事项不能再提交，要重新发起。

退回和驳回都要写原因。每个动作都带操作编号，重提不会重复记。级别对不上时拒绝（`GF_MOVED`）。

### 3.3 通用事项的金额终审（P01 用来验证引擎）

审批金额一律按不含税口径。以下是 P01「通用事项」的终审档位，P04 的七类合同沿用同一档位：

| 金额 | 终审 |
| --- | --- |
| < 1 万 | 财总 |
| 1 万到 5 万（不含 5 万） | CFO |
| 5 万到 30 万（不含 30 万） | CFO 审，CEO 终审 |
| ≥ 30 万 | CEO 审，董事长终审 |

另外两条：
- 重大风险、预付款、超预算的，至少到 CFO。
- 30 万的合同类事项是 5 级：部门负责人 → 履约执行人 → 财法分审 → CEO → 董事长。

用例在整值前后一分钱（9,999.99 / 10,000.00、49,999.99 / 50,000.00、299,999.99 / 300,000.00）各验一遍。

### 3.4 知会（P01-04）

- 审批通过以后知会董事长、业态总经理、财总、CFO。
- 知会只是通知，不需要点同意。
- 同一事项同一人只知会一次。已在审批链里出过结论的人和发起人不再知会。
- 以下情况即时站内提醒：金额 ≥ 5 万、异常、紧急、重大风险、特批。
- 其余的进日报：每天 18 点以后，每分钟任务按人汇总成一条站内信，发过的不再发。

### 3.5 微信特批补登（P01-08）

1. 紧急事项两人微信确认以后，在系统里登记：
   - 必须是两个不同的确认人，登记人不能是确认人之一；
   - 生成唯一特批编号 `TP…`；
   - 可以关联原事项。
2. 补登期限是确认日起 1 个工作日（节假日表里的节假日不算，调休上班算）。
3. 补登时要上传需求说明和 OK 截图，各至少一份：
   - 只收 PNG、JPG、WEBP、PDF；
   - 每份不超过 5 MB；
   - 会核对文件头。
4. 补登只能做一次，不重复审批。
5. 关联的事项在补登前状态是「特批待补登」，不能「执行完成」。

### 3.6 通用流程状态（P01-09）

主流程：草稿 → 审核中 → 待执行 → 执行中 → 已完成 → 已归档。

另有：退回、驳回、撤回、特批待补登、后补待完成。

逾期是另一个标记：过了期限还没完成的算逾期。

状态不另建表，由纯函数 `deriveStatus` 从事项、最近一轮审批、特批这几张表算出来。

### 3.7 看得到谁

能看事项详情的人：
- 发起人、履约执行人、事项本人；
- 审批链里能审或审过的人；
- 知会对象；
- 关联特批的登记人和确认人；
- 店主、内控、董事长（这三类看得到「全部」）。

补登的文件也只给这些人下载。

### 3.8 页面

页面在「WCP → 业财法审批」（`/oa/gov`），分区如下：
- 待我审批；
- 我发起的；
- 知会我的；
- 全部；
- 微信特批；
- 角色映射。

事项详情在 `/oa/gov/:id`：
- 显示审批链每一级，会签和并行分审还等谁；
- 显示排链时的调整说明（同一人不重复、加内控、回避上移）；
- 可以同意、退回、驳回；
- 显示知会和特批；
- 可以开始执行、完成、归档。

手机和电脑用同一页面。

## 6. P02 供应商与商品 SKU 两级库（迁移 `410_gf_supply.sql`）

页面在「WCP → 业财法审批 → 供应商库」（`/oa/gov?box=suppliers`），供应商详情在 `/oa/gov/suppliers/:id`。

### 6.1 一级供应商库

1. **建档**：经办人建档，供应商进入「待准入」。
   - 统一社会信用代码按 GB 32100 核对校验位，并以它查重（唯一索引）。重复的不能建档，返回已有那一家。
2. **资料检查**：资料按「统一必填 + 按品类触发」：
   - 统一必填：营业执照、开户证明。
   - 食品：食品经营许可证。
   - 工程：施工资质、安全生产许可证。
   - 设备：产品合格证。
   - 化学品：危化品经营许可证。
   - 服务外包：服务资质。
   - 缺的或过期的，以及没填收款账户的，不能提交入库。
3. **入库审批**：供应链负责人 → 内控 → 董事长。
   - 新供应商按 P01 规则自动加内控。
   - 通过后进入「已入库」，记第 1 版快照，知会 CFO、财总。
4. **退回**：退回后回到「待准入」，改了资料可以再提交。
5. **状态**：待准入 / 审核中 / 已入库 / 停用 / 退出。
   - 停用、退出、恢复由供应链负责人或店主操作，退出时下面的 SKU 一并停用。
6. **收款账号按最小权限**：
   - 店主、供应链负责人、CFO、财总、出纳、董事长和建档人看完整账号。
   - 其他人只看尾号。
7. **历史数据迁移**（场景 37）：由供应链负责人或店主导入。
   - 一律进「待准入」，标「历史迁移」，不能一键激活，要逐家走入库审批。
   - 信用代码不对或重复的跳过，并说明原因。

### 6.2 二级 SKU 库

1. **前提**：SKU 只能挂在「已入库」的供应商下，映射一个集团物料。
   - 集团物料由供应链负责人或店主维护，可以标「核心品类」。
   - 每个 SKU 记适用经营主体、业态（汤崎、池里、PAJAMA、新生乐园）、不含税协议价和税率。
2. **提报**：同一供应商的一批 SKU 一张单提报，提交时逐个建码（`SKU-供应商号-序号`）。
3. **异常判定**：
   - 比同一集团物料现有最低有效价高 10% 以上（整值不算，多一分算）。
   - 核心品类。
   - 有异常的事项自动带「价格异常 / 核心品类」标记，审批链加内控。
4. **董事长终审**（场景 29、31、35）：
   - 看差异摘要（正常的和异常的分开列）。
   - 异常的 SKU 要逐个给结论，少一个都拒绝（`GF_SKU_DECISIONS`），不能一键全过。
   - 不同意的 SKU 记「未通过」，其余生效，协议价第 1 版。

### 6.3 变更（场景 32）

- **核心变更**：主体名称、统一社会信用代码（税号）、开户行、账号、账户名、核心资质。
  - 走 供应链负责人 → 董事长，知会 CFO、财总。
- **一般资料**：联系人、电话、地址、品类、备注。
  - 只要供应链负责人审核，留痕，不知会。
- **审核期间**：同一供应商（或同一 SKU）不能再发起变更，`inLibrary()` 返回不能按库内简化（P04 的「库内供应商 + 有效 SKU 免重复准入」先过这一关）。
- **通过后**：新版本快照，旧快照只追加不改，历史单据按事项里记的版本号对照原版本。
- **SKU 协议价变更**：同样走 供应链负责人 → 董事长。
  - 比上一版变动超过 10% 加内控。
  - 通过后追加新的价格版本，旧版本保留。

### 6.4 选择器（场景 34）

- `GET /api/gf/selector/suppliers` 只给「已入库」的供应商。
- `GET /api/gf/selector/suppliers/:id/skus` 只给有效 SKU；供应商不是「已入库」时返回 409。
- 查不到或状态不明，一律不当作已入库。

## 7. P03 零星采购与备用金额度（迁移 `420_gf_petty.sql`）

页面在「WCP → 业财法审批 → 零星采购」（`/oa/gov?box=petty`）。验收、补发票在事项详情里。

### 7.1 分级与快速通道

- 单笔 ≤ 3,000 元且 ≤ 50 件：基础审核。
- 超出时只加审核内容（必须写比价说明），不加层级。
- 普通员工发起的，审批链是 部门负责人 → 财务审核人。
- 合同、工程、服务外包、预付款、固定资产不走零星采购（`GF_TO_FORMAL`）。

### 7.2 防拆单（场景 3）

- 同日、同供应商（名称去空格、不分大小写）的零星采购合并计算金额和件数。
- 合起来超过基础审核线的，按超出处理（要写比价说明）。
- 这种情况标「疑似拆单」，带「异常」标记（即时知会），并进内控公示。

### 7.3 部门备用金额度（场景 4、5、19、25–27、40）

- **台账口径**：按费用承担部门 + 自然日 / 月统计。默认日 1 万、月 5 万。
- **预警**：占用达到 80% 和 90% 时，给部门负责人发站内预警。
- **提交时锁定重算**：在数据库事务里锁住部门（按编号顺序锁，避免死锁），重新计算占用，然后冻结。页面预检（`/api/gf/petty/preview`）不算最终占用。
- **合并特批**：超日额度、月额度，或两者都超的，审批链只加一级「财总＋CFO 合并特批」。
  - 生成唯一特批编号 `TE…`，记录超出金额。
  - 形成的一次性专项额度只给本事项，下一笔超额要另外特批。
- **台账状态**：冻结 → 验收转实际占用 → 差额释放。
  - 驳回、撤回的解冻。
  - 退回的继续冻结，改了再交。
  - 冲正只有财总能做，追加负数记录，不删历史。
  - 台账只追加，每条带操作编号，重复提交不会重复记。

### 7.4 采购部门日累计（场景 38）

- 店主在设置里指定哪个部门是采购部门。
- 采购部门员工当日的零星采购累计超过 1 万时：
  - 非紧急的转正式采购或合同，不能用备用金特批绕开；
  - 紧急的加一级财总＋CFO 特批。

### 7.5 负责人自购（场景 41）

- 部门负责人自己发起时，负责人一级自动视同确认，不需要采购部门审批。
- 采购部门只收记录：知会供应链负责人，进日报。
- 验收不能免：
  - 必须由费用承担部门里的另一名员工（实际使用人）验收，并同时办部门小仓入库；
  - 采购的人自己不能验收；
  - 实际金额不能超过冻结金额。
- 发票冲抵备用金；没有票的进入「后补待完成」，补了发票才算「已完成」。

### 7.6 逾期

- 审批通过后 7 天内要验收，过期算逾期。
- 经办人（保管人）有逾期未处理的，不能新增零星采购（`GF_OVERDUE_BLOCK`）。
- 恢复要财总复核，留记录（只追加）。

### 7.7 月度额度核定（场景 42）

- 由内控提出建议，财总＋CFO 共同审批。
- 从次月起生效，不能改本月或以前，不自动升降。

### 7.8 内控公示

- 内控每周公示各部门的数据：今天已用、冻结、今天和本月剩余、逾期笔数、疑似拆单笔数、下月核定额度。
- 能看的人：内控、财务审核人、财总、CFO、董事长、店主。
- 部门负责人和部门员工只看本部门。

  - 3,000 元 / 50 件；
  - 1 万 / 5 万；
  - 80% / 90%；
  - 采购部门 1 万。

  - 内控公示的权限。

## 8. P04 七类合同审批（迁移 `430_gf_contract.sql`）

页面在「WCP → 业财法审批 → 合同」（`/oa/gov?box=contracts`）。合同要点、确认归属和变更在事项详情里。

### 8.1 七类与经济实质（场景 36）

七类合同按经济实质区分：

| 类型 | 经济实质 |
| --- | --- |
| 采购 | 物资所有权 |
| 服务 | 劳务成果 |
| 工程 | 施工与工程验收 |
| 租赁及资产使用 | 一段期间的使用权 |
| 经营合作 | 联营、共担收益风险 |
| 无金额 | 没有金额 |
| 其他 | 以上都不是 |

经办人发起时勾选实际情况，系统按经济实质判定类型。

混合合同的归并规则：
- 施工附带设备且不可分，归工程。
- 设备采购只附带一般安装，归采购。
- 资产使用但实质是共同经营，归经营合作。
- 框架合同无价但订单有价，不归无金额。

校验规则：
- 选的类型与判定结果不符时拒绝（`GF_TYPE_MISMATCH`，同时给出建议类型）。确实不同的，选「其他」。
- 同时有几种实质、又没有归并规则的，提示「能拆则拆」。不写不能拆的原因就拒绝（`GF_SPLIT`）。
- 「其他」类要财务审核人或法务确认归属，发起人不能自己确认。未确认的不能签署。

### 8.2 金额口径

- 审批按不含税金额。
- 租赁、经营合作（以及填了每期金额的框架、按量合同）按全合同期计算：每期 × 期数。
- 含税金额单独记录，付款时用。

### 8.3 档位（场景 6–10、44）

| 不含税金额 | 终审 |
| --- | --- |
| < 1 万 | 财总 |
| 1 万到 5 万（不含 5 万） | CFO |
| 5 万到 30 万（不含 30 万） | CEO |
| ≥ 30 万 | 董事长 |

- 重大风险、预付款、超预算的，至少到 CFO。
- 工程合同不论金额都至少到 CEO；≥ 30 万的走 CEO → 董事长，两级都按终审回避。

### 8.4 审批链

部门负责人 → 内部履约执行人（+1，与部门负责人同一人时不重复，场景 43）→ 财务、法务并行分审（分别出结论）→（内控）→ 终审。

审批通过后知会财总、CFO。

### 8.5 库内供应商与价格一致

- 选了「已入库」、没有在审变更的供应商，并且 SKU 都有效：免重复两级准入（不加内控）。财法审核和金额终审照常保留。
- 价格一致性：明细单价必须等于 SKU 现行协议价（`GF_PRICE_MISMATCH`），明细合计必须等于不含税总价（`GF_AMOUNT_MISMATCH`）。
- 采购、服务、工程合同（「其他」类按确认后的归属算），相对方不在库里的：
  - 加内控；
  - 签署前必须完成供应商入库（`GF_SUPPLIER_NOT_ACTIVE`）。

### 8.6 签署、用印、归档

- 「开始执行」= 定稿签署。
- 「完成」= 用印。用印后 1 个工作日内要扫描归档，之前状态是「后补待完成」，过期算逾期。
- 「归档」= 归档完成。

### 8.7 变更（场景 30）

- **只减金额、其他不变**：保留原审批，记一条「减金额」版本，更新审批口径金额。
- **核心变更**（加金额、改相对方、标的、付款条件、期限、类型）：
  - 原审批作废：原合同标「已变更作废」，不能再签署或变更；
  - 按新内容新建合同事项，重新路由，关联原合同；
  - 原合同记一条「重新路由」版本。
- 版本记录只追加。

### 8.8 自测

- `tests/govflow-contract-rules.test.ts`：
  - 七类判定和混合合同；
  - 全期口径；
  - 档位整值前后一分钱（9,999.99 / 10,000、49,999.99 / 50,000、299,999.99 / 300,000）；
  - 工程档位；
  - 变更是否保留原审批。
- `tests/govflow-p04.test.ts`（测试库，合成数据）：
  - 场景 6–10、30、36、43、44；
  - 价格一致和免重复准入；
  - 「其他」确认归属；
  - 签署 → 用印 → 归档。

## 9. P05 付款与紧急特批（迁移 `440_gf_payment.sql`）

页面在「WCP → 业财法审批 → 付款」（`/oa/gov?box=payments`）。出纳付款、重新确认、补发票在事项详情里。实际付款一律按含税金额。

### 9.1 正常付款简化（场景 11）

同时满足以下条件的，只走 主责部门负责人 → 财务审核人 → 出纳：
- 关联有效合同（审批通过、没有变更作废），可写付款节点；
- 有验收或对账依据（预付款除外）；
- 金额在合同剩余应付以内：合同含税金额 − 已付 − 在途，按合同串行计算；
- 已取票，或登记后补；
- 收款账户没有在审的变更；
- 没有异常（标了异常的加一级 CFO）。

### 9.2 无合同付款（场景 13、24）

- 采购、服务、工程类达到 1 万（含）必须签合同，不能走无合同付款绕开（`GF_CONTRACT_REQUIRED`）。
- 其他类别（租金、水电燃气、税费、其他）不受这条限制。
- 无合同付款金额 ≥ 5 万或标了异常的，走 部门负责人 → 财务 → CFO → CEO → 董事长 → 出纳，并即时知会。

### 9.3 紧急特批（场景 14–16）

- **适用范围**：供应商未入库或合同没完成的紧急付款。已入库且合同有效的不能走紧急特批（`GF_NOT_EMERGENCY`）。
- **先登记**：先在「微信特批」登记（P01）。确认人必须是一位 CFO 加一位经营主体负责人，确认时间不能晚于付款发起时间（付款前两人都已同意）。同时记下确认时的收款账号。
- **审批链**：付款申请只要出纳独立核验。
- **分次与超额**：少付、分次可以补登，各次累计不超过特批金额（`GF_SPECIAL_EXCEEDED`）。超额或换账户（`GF_SPECIAL_ACCOUNT`）都要重新特批。
- **补登**：特批没补登前，付款申请显示「特批待补登」。

### 9.4 出纳付款与重复支付

- 出纳要重新输入收款账号，必须同时与申请时的账号、供应商当前的账号一致。
- 每次付款登记银行流水号，流水号全局唯一。
- 可以分次付款，累计不超过申请金额，付满即「已完成」。
- 同一收款方的同一发票号只能付一次，发起时和后补发票时都会核对。

### 9.5 发票（场景 21）

- 先票后款，只有预付款可以暂不取票。
- 登记后补的，期限是 5 个工作日。付完但没补票的显示「后补待完成」，过期算逾期。补了发票变「已完成」。

### 9.6 收款账户变更

- 供应商收款账户的核心变更，在 P02 的基础上另外知会财务审核人。
- 变更在审期间，不能对这个供应商发起付款或付款。
- 变更通过后，这个供应商名下还没付完的付款申请都标「待财务重新确认」。财务按新账户确认后，出纳才能付。

### 9.7 自测

- `tests/govflow-payment-rules.test.ts`：分路；以下边界都卡整值前后一分钱：
  - 1 万（必须签合同）；
  - 5 万（无合同高额）；
  - 剩余应付。
- `tests/govflow-p05.test.ts`（测试库，合成数据）：
  - 场景 11、13–16、21、24；
  - 重复支付：剩余应付、发票号、流水号；
  - 出纳账号核验；
  - 账户变更后重新确认。

## 10. P06 报销、出差、招待、用印证照（迁移 `450_gf_expense.sql`）

页面在「WCP → 业财法审批 → 报销出差用印」（`/oa/gov?box=expense`），里面有四个入口、部门本月差旅额度和证照台账。

### 10.1 普通报销（场景 17、18）

**审批链**：部门负责人 → 财务审核人 → 出纳，不因金额升级。

**知会**（都按「超过」算，整值不算）：
- 超过 2 万：知会 CFO。
- 超过 5 万：知会 CFO＋董事长，即时提醒。

**无票**：没有发票的，在付款（出纳）前加一级财总复核。

**不得重复报销**：
- 同一张发票，已经报销过的，或已经在零星采购验收时冲抵过备用金的，都不能再报（`GF_DUPLICATE_CLAIM`）。
- 关联了备用金事项的，直接拒绝。

**报销人回避**：报销人是事项本人，按回避规则不能终审自己的报销。

### 10.2 出差与部门月度差旅预算（场景 19、20、46）

**额度**：
- 财总设各部门每月的差旅批复额度。
- 出差单显示部门当月的批复、已用、冻结、剩余。

**预算内**：部门负责人 → 财务审核人（预算与标准审核），申请时冻结额度。

**超出部门本月预算**（正好用完不算超，多一分算超）。本月原则上不报，要二选一：
- 登记转下月：冻结记到下月，带「超预算」标记；
- 特殊事项：加 CFO，再加财总＋CFO 特批。

**加审规则**：
- 没有事前申请，或一般超标准的：财总复核。
- 重大异常：加 CFO。
- 重大异常且金额 ≥ 50 万：CFO → CEO → 董事长。

**出差报销**：
- 必须关联本人已审批通过的出差申请，每次出差只能报一次。
- 出差结束超过 5 个工作日才报的，标异常，加财总复核。
- 报销通过后，原申请的冻结转为实际占用。

**驳回、撤回**：冻结的额度释放。

**内控**：按月查看各部门的差旅额度使用情况。普通员工只看本部门。

### 10.3 商务招待（场景 23）

**审批链**：
- 一般：部门负责人 → 财务审核人。
- 超过 2 万：加财总。
- 超过 5 万：再加 CFO。
- 没有事前申请的，至少到财总。

**调整**：
- 金额和人数都减少（或不变）的，不重审，直接调整。
- 任一项增加，要重新发起（`GF_RESUBMIT`）。

### 10.4 用印证照（场景 39）

| 用印类型 | 审批链 |
| --- | --- |
| 已批合同用印，合同没改动（只有初版） | 不重审，章证管理员直接用印 |
| 已批合同用印，合同改动过 | 按非合同文件审 |
| 非合同文件 | 部门负责人 → 财务、法务按内容审 →（高风险 / 超授权：经营主体负责人）→ 章证管理员 |
| 空白文件 | 部门负责人 → 财总＋经营主体负责人特批 → 章证管理员 |
| 电子证照 | 部门负责人 → 章证管理员 |
| 纸质证照借用 | 部门负责人 → 章证管理员 |

**用印后**：
- 普通用印：1 个工作日内扫描归档。
- 空白文件：5 个工作日内补最终版。
- 期限内状态为「后补待完成」，过期算逾期。

**证照**：
- 电子证照：只发水印副本，审批通过即自动归档。
- 纸质证照：
  - 章证管理员登记借出（期限 1–30 天）和归还；
  - 同一份同时只能借出一次；
  - 超期算逾期。

**谁来办**：用印、借还由章证管理员操作，发起人不能自己推进。

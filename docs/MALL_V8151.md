## 1. 自主申请分「非定制」「定制」

自主申请第一步先选两张卡片之一：

|        | 非定制                                                         | 定制                                                                                                                      |
| ------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 是什么 | 市面上买得到的现成品，商城里还没有                             | 按我们的要求做的：印刷品、工服、物料定做……                                                                                |
| 要填   | 物品名称、数量单位、**规格型号（必填）**、品牌、参考链接、照片 | 要做什么、数量单位、**尺寸规格 / 材质工艺 / 设计要求至少一项**、用在哪给谁用、预算（选填）、要不要先打样、设计稿 / 参考图 |
| 都要   | 采购理由 / 使用场景；部门与交付（与原来一样）                  | 同左                                                                                                                      |

- 两种都能传图（最多 9 张）；原来的自主申请不能传图，这一版补上。
- 存法：`purchase_request_lines.custom_kind`（standard / custom）与 `custom_spec`（尺寸、材质工艺、场景、打样、预算，结构化一份，商城回显、改单用）；ERP 采购需求单看的「规格与技术要求」里同时写成一段话（「【定制】尺寸规格：…；材质工艺：…；需要先打样确认；预算约 ¥…」+ 部门写的说明），ERP 那边不用改就看得到。

## 2. 退回后在原单补资料

- 被退回的商城单，详情页顶上写退回原因，按钮「在原单补资料」：打开整张单，**自主申请的行全部能改**（包括换成定制 / 非定制、补图），**商城选品的行只能改数量或删掉**（价格版本跟 SKU 走，改品要重新选购）；经办人、预算项目、期望到货、收货地点、优先级、备注都能改；要写一句「补了什么」。
- 提交后：**单号不变**，回到待审核；主管确认、核库按这一次重新算（与第一次提交一样）；审批记录里依次是「退回：原因」「修改：补资料：……」「提交」，审核的人一眼看到补了什么。
- 只有提单人（或店主）能补；带页面看到的修改时间，之后又有变动的拒绝（`REQUEST_CHANGED`）；不是退回状态的拒绝（原样重提不会重复提交）。
- ERP 填单页照旧不改商城单（`MALL_EDIT_IN_SHOP`），商城单在商城里补。

## 3. 需求池接单与成交方案

**做法（我的决定）**：找供应商、谈价、发样品照片这些照旧在微信上做，**谈定以后，BP 必须回到系统记一条「成交方案」**：供应商、含税单价、税率、运费、交期、报价有效期、给部门看的方案说明、只给采购看的内部备注、报价截图 / 样品照片（微信截图直接传）。理由：转采购单、对账、以后比价都要这几个数，微信里的记录查不回来。

- **接单**：需求池列表每行写「某某跟进 / 待接单」，可按「待接单 / 我接的」筛；详情页「接单」「放回需求池」。有人接了别人不能抢；采购审核（或店主）可以改派。记方案时还没人接的顺手算接单。
- **记方案**：同一行可以记几条（比价），标一条「采购推荐」；还没建档的供应商可以先写名称，转采购单前再建档。原样重提（同一个操作编号）只记一条。
- **部门确认**：部门在「我的采购需求」详情里看到方案卡片——**供应商、交期、方案说明**（店主 2026-11-24 定：成交价不给商城，所以部门看不到价格、截图、内部备注）——点「就用这个方案」。部门已经在微信上说好的，BP 点「部门已在微信确认」，**要写一句谁、什么时候确认的**，记在方案上。同一行只能选定一条，改选会换掉原来的；转了采购单以后不能再换。
- **转采购单**：ERP「待转采购单」带上选定方案——单价按方案的含税单价填、这次带来的行都定了同一家建过档的供应商时自动选上这家；采购照常核对后提交。
- 能做什么：接单、记方案、撤方案、代记微信确认要「采购经办」或「采购审核」；部门确认要是提单人、这个部门的人或主管（店主都能）。

## 4. 收货：合格入库、拒收、待补

- 原来就有：收货填「送达数量」「合格实收」，差额是拒收、要写拒收原因，只有合格的入库、计货款。
- 这一版加 **「其中待补」**：拒收里供应商答应补发的数量（不超过拒收数，选填）；其余算退回不补。存在 `inv_doc_lines.redeliver_milli`。
- 看得到的地方：收货单详情（「拒收原因：…；其中供应商待补 N」）、商城「我的采购需求」每行的进度（「合格入库 N · 拒收 N（其中待补 N）」）。
- 补发的货到了照常再做一张收货单（采购单没收齐时照旧是部分到货）。

## 5. 试点建议（品牌部、客房部 / 布草）

1. 品牌部走「定制」：填尺寸、材质工艺、勾打样、传设计稿 → 主管确认 → 采购审核（不清楚的退回，部门在原单补资料）→ BP 接单、微信找厂、记方案 → 品牌部点「就用这个方案」→ 转采购单 → 收货（打样不合格的拒收、记待补）。
2. 布草部门走商城选品（有 SKU 的）或「非定制」；重点看核库（总仓有货的直接领用）、到货按合格数入库、拒收与待补。
3. 试点时留意：主管有没有及时确认、BP 方案记得全不全、部门能不能看懂方案卡片；反馈记到 `docs/PENDING_DECISIONS.md`。

## 6. 接口

| 接口                                            | 说明                                                                                                                                                                                            |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/erp/shop/requests`（`kind: custom`） | `line.customKind`（standard / custom）、`line.customSpec`（size、craft、scene、sample、budgetCents）、`line.imageIds`                                                                           |
| `PUT /api/erp/shop/requests/:id/resubmit`       | 退回后在原单补资料：`expectedUpdatedAt`、表头几项、`remark`、`lines[]`（`id` + 改的内容；没列的行删掉）                                                                                         |
| `POST /api/erp/shop/requests/:id/claim`         | 接单；`{ release: true }` 放回；`{ take: true }` 审核的人改派给自己                                                                                                                             |
| `POST /api/erp/shop/requests/:id/quotes`        | 记方案（`clientKey`、`lineId`、`supplierId` 或 `supplierName`、`unitPriceCents`、`taxRateBp`、`freightCents`、`leadDays`、`validUntil`、`planNote`、`internalNote`、`imageIds`、`recommended`） |
| `POST /api/erp/shop/quotes/:id/select`          | `{ mode: 'dept' }` 部门确认；`{ mode: 'wechat', note }` BP 代记微信确认                                                                                                                         |
| `POST /api/erp/shop/quotes/:id/withdraw`        | 撤下方案（转了采购单的不能撤）                                                                                                                                                                  |
| `GET /api/erp/requests/open-lines`              | 每行多一个 `plan`（选定方案的供应商、含税单价、交期）                                                                                                                                           |
| 收货单行                                        | 多一个 `redeliverMilli`（待补）                                                                                                                                                                 |

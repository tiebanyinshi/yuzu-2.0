# 8.2.9 · 业财法：角色映射可改、变更记录、提交时快照审批人

《汤崎 ERP｜业财法审批与 WCP 模块 需求变更文档 v0.1》第 4 批（核对见 `docs/V827_APPROVALS_PURCHASING.md` A1）。按文档建议 WB1、WB2（`docs/PENDING_DECISIONS.md`）。数据库迁移 `600`，回滚 `docs/rollback/600_gf_role_snapshot.down.sql`。

## 1. 核对时（A1）

「业财法 → 角色映射」只能新增、撤销，不能改；列表只显示姓名（同名分不清）；审批人每次实时取，改了映射，在途单的审批人跟着变。

## 2. 这一版

- **列表**带工号（登录账号）与所在部门。
- **修改**：换人、改经营主体范围、改备注，要写修改原因；**角色本身不能改**（WB1：要换角色就撤销后新加）。实现上是把旧的一条撤销、新建一条指回它（`gf_role_members.replaces_id`），历史都在。没有改动的拒绝（`GF_ROLE_SAME`）。
- **撤销**可以写原因（选填）。
- **变更记录**（「角色映射 → 变更记录」，要「配置业财法角色」权限）：每一条的新加、修改（谁换成谁）、撤销，操作人、时间、原因，新的在前，最多 500 条。另外照旧写操作日志。
- **快照**（WB2 方案 A）：提交（含退回后再提交）那一刻把各角色是谁、部门负责人是谁存在这一轮审批上（`gf_flows.seat_snapshot`）；之后改映射不影响这一轮，之后提交的按新的。
  - 快照里的人停用了（离职）：这一席没有在用的人时改按现在的映射取，免得单子卡死。
  - 升级前已经在审的单没有快照，照旧实时取。
  - 知会（不用同意）照旧按现在的映射发。

## 3. 没做

加签、转派（WB3：沿用现有，本期不做）。

## 4. 测试

`tests/govflow-roles.test.ts`：工号与部门、修改的校验与权限、在途单按快照 / 之后的按新的、变更记录、快照里的人停用后改按现在的映射。

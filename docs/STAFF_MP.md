## 0. 一句话

员工在微信里打开 **汤崎 WCP**：第一次用柚子的员工账号登录，之后点开就进。首页「今天」只放此刻最要紧的一件事（该打卡就是打卡、到饭点就是饭卡码、巡场时就是这一轮还差几处）和一张待办清单；「学习」是汤崎学堂与知识库；「办事」把考勤、申请审批、吃饭、巡场、工资条、通讯录按要办的事排好；「我的」是自己的资料与设置。一个「扫一扫」认得店里所有的码。

## 1. 谁用、一天里用来做什么

门店一线员工（前台收银、技师、餐饮、客房管家、安保、保洁、工程）与各部门主管、店总、人事。按一天里用到的次数排：

| 次数        | 要做的事                                         | 现在在哪做                               | 小程序里                                    |
| ----------- | ------------------------------------------------ | ---------------------------------------- | ------------------------------------------- |
| 每天 2 次+  | 上下班打卡                                       | WCP 网页（`/oa`）                        | 打开就在首页，最多点 1 下                    |
| 每天 1–3 次 | 到饭堂亮饭卡码；看今天吃什么                     | 柚子饭堂（网页）                         | 饭点时首页直接是饭卡码                      |
| 每晚多次    | 安保巡场扫码                                     | 柚子饭堂「工作台 → 巡场」                | 巡场时首页就是「这一轮还差几处」+ 扫一扫    |
| 每天        | 看排班（今天几点、明天休不休）                   | WCP 网页「我的排班」                     | 首页一行；办事 → 考勤                       |
| 每天 5 分钟 | 每日一练、必修课、上岗前查应知应会               | WCP 网页「员工培训」；汤崎学堂开发中     | 学习 Tab；首页待办提醒必修与每日一练        |
| 每周几次    | 请假等申请、主管审批                             | WCP 网页「审批」                         | 首页待办「待我审批」；办事 → 申请与审批     |
| 每周几次    | 看通知、公告                                     | WCP 网页                                 | 首页铃铛与待办；公告在首页下方              |
| 每月        | 工资条、假期余额                                 | WCP 网页                                 | 办事 → 人事；首页待办「工资条待确认」       |
| 偶尔        | 找同事电话                                       | WCP 网页「通讯录」                       | 办事 → 通讯录，一点就打                     |
| 主管每天    | 本部门今天谁到了、巡场漏了哪、饭堂多少人         | 后台各页                                 | 办事 → 管理（有权限才出现）                 |

从这张表得出三条：**打卡、吃饭、巡场三件事有很强的时间性**（到点就要，晚一分钟都是事）；**学习是每天一点、上岗时随手查**；**其余都是「有事才找」**。所以不按后台模块分 Tab，而是「今天」管时间性的事，「学习」单独一个 Tab（店主说最重要），「办事」收其余的事，「我的」放自己。

## 2. 信息架构

### 2.1 四个 Tab

| Tab  | 英文小标题 | 放什么                                                                         |
| ---- | ---------- | ------------------------------------------------------------------------------ |
| 今天 | TODAY      | 此刻卡（一件最要紧的事）、待办清单、今天的班次、今天的菜单一行、公告           |
| 学习 | LEARN      | 继续学习、我的必修、每日一练、搜应知应会、学习地图、知识库、证书               |
| 办事 | SERVICES   | 按要办的事分组的全部入口（第 2.4 节）；顶上一个搜索框，搜功能名                |
| 我的 | PROFILE    | 自己的资料、学分与等级、假期余额、绑定的微信、改密码、关于（版本、实例标识）   |

没有单独的「消息」Tab：现在没有聊天（WCP 网页的即时通讯这一版不搬），通知只是「有事要处理」或「知会一下」——要处理的进待办，知会的在首页铃铛里看。以后把聊天搬进来时再加消息 Tab（SP03）。

### 2.2 今天（首页）

自上而下：

1. **页头**：「早上好，小林」、门店名、日期与星期；右上角两个圆形按钮：扫一扫、通知铃铛（有未读带红点）。
2. **此刻卡**：只放一件事，按下面的顺序取第一条成立的（规则写成纯函数，单元测试逐条核对）：

   | 优先 | 条件                                                     | 卡上写什么                                                                      | 主按钮                 |
   | ---- | -------------------------------------------------------- | ------------------------------------------------------------------------------- | ---------------------- |
   | 1    | 处在某个班次的上班打卡窗口里、还没打上班卡               | 班次名、上班时间、「还有 12 分钟」或「已迟到 3 分钟」                           | 上班打卡               |
   | 2    | 处在下班打卡窗口里、还没打下班卡                         | 下班时间、「已到下班时间」                                                      | 下班打卡               |
   | 3    | 巡场部门的人、这一轮还没巡完                             | 第几轮、时间段、「还有 3 处没巡」与这几处的名字                                 | 扫码巡场               |
   | 4    | 在开饭时间里、能用饭堂、这一餐还没打卡                   | 「午餐 10:30–14:30」、今天的几道菜                                              | 亮饭卡码               |
   | 5    | 今天有每日一练没做（学堂上线以后）                       | 「今天的 10 道题」、连续天数                                                    | 开始练习               |
   | 6    | 在班中                                                   | 「在班 · 18:00 下班」                                                           | （没有，下面列下一件） |
   | 7    | 今天休息 / 没有排班                                      | 「今天休息」，明天的班次                                                        | 看排班                 |

   主按钮占满卡片宽度、在拇指够得着的下半部；打卡成功以后卡片原地变成结果（✓ 09:02 上班卡 · 准时），轻振一下，2 秒后换成下一件事。

3. **待办**：把要我处理的事合成一个清单，最急的在上面，每条一行（图标、一句话、截止或时间、右箭头）：待我审批 N 件、我的申请有结果、必修课快到期（学堂上线以后）、工资条待确认、新上的培训资料、未读公告。没有待办时写「都处理完了」，不留空白。
4. **今天**：一行写我的班次（「09:00–18:00 · 前厅早班」），一行写今天的菜（能用饭堂才有），点开各到自己的页面。
5. **公告**：最近 3 条标题，点开看全文，「全部公告」在最下面。

### 2.3 学习

店主说培训最重要，所以单独一个 Tab。界面归员工小程序线，内容、规则、接口归主线的「汤崎学堂」（另一个开发会话在做，设计稿 ACADEMY 在它的集成 PR [#50](https://github.com/tiebanyinshi/yuzu-2.0/pull/50) 上）。

- **学堂上线以前**（第一版就有）：顶上搜索框（搜培训资料的名字与内容摘要），「知识库」按文件夹列出员工培训的资料（培训资料 + 本部门），没看过的标「新」；点开文件在小程序里直接看（PDF、Word、Excel、PPT 用微信自带的文档预览，图片放大看，视频在页里播），看过就记「看过」（与 WCP 网页同一条记录）。
- **学堂上线以后**（主线把员工端接口合进 `main` 以后，按服务端报的「学堂开没开」自动出现，不发新版小程序也能亮起来的部分写死在配置里）：继续学习（上次学到哪）、我的必修（带截止日）、每日一练（连续天数）、学习地图、证书、学分与等级。员工端接口挂在员工端口上的做法见第 5.3 节。
- **上岗前查应知应会**：搜索框常驻在页顶，一个输入框同时搜课程与资料；最近搜过的留 5 条。

### 2.4 办事

按「要办的事」分组，组名用动词能懂的话；每组只列这个人能用的入口，整组都没有就不显示：

| 组         | 入口                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------- |
| 考勤       | 打卡、我的排班、考勤记录、假期余额                                                       |
| 申请与审批 | 待我审批、我的申请、抄送我的（发起申请第二批再做，SP07）                                 |
| 吃饭       | 今天的菜单、饭卡码；食堂负责人另有「扫码登记」「今天多少人」                             |
| 巡场       | 扫码巡场、这一轮；能看记录的人另有「巡场记录」                                           |
| 人事       | 工资条、通讯录、公告                                                                     |
| 管理       | 有权限才出现：本部门今天的考勤、巡场记录、饭堂人数（随主线接口逐步加）                   |

顶上的搜索框搜入口名（打「工资」出工资条、打「假」出假期余额与考勤记录）。入口图标一律细线图标、单色，不用表情。

### 2.5 我的

头像（姓名首字）、姓名、部门 · 岗位、门店；学分与等级（学堂上线以后）；假期余额一行；绑定的微信（解绑）；改密码；关于：小程序版本、门店系统的版本 + SHA、实例标识（测试服、演示库要一眼看得出来，`AGENTS.md`「环境隔离」）；退出登录。

### 2.6 扫一扫

首页右上角与「办事」都有。扫到什么按码里的内容分：巡场点的码 → 巡场打卡；员工的饭卡码（食堂负责人）→ 打卡登记；以后培训资料上的码 → 打开那份资料。认不出的码写「这不是店里的码」，不跳到别处。

### 2.7 不同的人看到的不同

| 人                 | 多出来的                                                     |
| ------------------ | ------------------------------------------------------------ |
| 所有在职员工       | 上面的全部（吃饭要能用饭堂；巡场只给巡场部门）               |
| 巡场部门（安保）   | 此刻卡第 3 条、办事 → 巡场                                   |
| 食堂负责人         | 扫一扫认饭卡码；办事 → 吃饭的「扫码登记」「今天多少人」      |
| 有审批的主管       | 待办里的「待我审批」；办事 → 管理                            |
| 平板、他店、设计师等专用账号、离职的 | 登录不了（与 WCP 网页、员工培训同一条规则）  |

能用哪些由服务端在「我是谁」里一起告诉小程序；每个接口照旧当场按权限核对，小程序上的入口只是方便。

## 3. 体验原则（清楚、人性化）

1. **打开就是要做的事**：最常用的事（打卡、饭卡码、巡场）从点开小程序算最多点 1 下；首页不放轮播、不放营销口号。
2. **一屏一个主操作**：每个页面最多一个实心主按钮，放在拇指够得着的下半部；次要操作用文字按钮。
3. **说人话**：按钮写动词（上班打卡、亮饭卡码、同意），不写系统词（提交、确认操作）；错误写「为什么 + 怎么办」（「你还没进考勤组，打不了卡：请找人事把你加进考勤组」，服务端已有的错误文字原样显示）。
4. **结果当场看得见**：打卡、审批、巡场成功后在原地变成结果，不弹「操作成功」再让人点确定。
5. **没网也不慌**：饭卡码离线也能亮；巡场扫到的先存在手机上、联网补交；打卡、审批没收到结果时进「结果待确认」，按原操作编号原样重提（`AGENTS.md` 开发约定），不让人重复打卡。
6. **不让人等白屏**：页面先出骨架，再出数；下拉刷新；接口慢于 300 毫秒才出加载样子。
7. **空的时候也有话说**：没有待办写「都处理完了」，没有排班写「这几天没有排班，问问主管」，不留空白。
8. **该有的才出现**：用不了的入口不显示，不出现点进去才说「没有权限」。
9. **看得清**：正文不小于 28rpx（约 14 像素），对比度不低于 4.5 : 1，可点区域不小于 88rpx（约 44 像素）；数字用等宽。
10. **不打扰**：振动只在打卡、巡场成功时轻振一下；不弹授权，用到定位、相机时再按微信的规矩请求。

## 4. 视觉：汤崎 WCP 的样子

（设计约束的来源与核对清单见第 13 节；颜色与字号在小程序里写成令牌，页面只用令牌。）

- **气质**：一本放在汤泉边的工作手册——正式、安静、留白多；品牌照汤崎品牌书与 VI（`docs/MINIPROGRAM.md` 第 13 节、`brand/README.md`），与顾客小程序同一家人，但更克制：顾客小程序是「来玩」，员工小程序是「上班」。
- **颜色**（界面 90% 以上是中性色，只有一个品牌点缀色）：亚麻米白底 `#F5F1EA`、卡片 `#FCFAF6`、细线 `#E0D7C9`；正文墨色 `#1C1A17`，次要字 `#5F574D`（在米白底上 6.3 : 1），占位与停用的字 `#8A8176`（3.4 : 1，只给占位字与停用的控件）；**主按钮用墨色**（正式）。木色 `#937051` 在米白底上只有 4.0 : 1，**只做大字（36rpx 以上加粗）、细线、进度条与图形**；小号的木色字用加深的 `#7A5C41`（5.4 : 1）。状态色：松绿 `#3F5E4B` 成功 / 已打卡，陶土红 `#A6452F` 错误 / 迟到，湖蓝 `#4E6B82` 提示；状态不只靠颜色，一定配字或图标。不用渐变、不用紫色、不用发光阴影、不大面积铺品牌色。
- **字**：中文用手机系统字体（苹方、鸿蒙），不加载中文网络字体；英文与数字用 Helvetica Neue，时间、金额、工资条的数字等宽。字号用 TDesign 的一套：24 / 28 / 32 / 36 / 40 / 48 rpx（行高 40 / 44 / 48 / 52 / 56 / 64），标题字重 600，不用细体；最小 22rpx；列表文字不小于 28rpx，**课件正文 32rpx**、行高 1.6；打卡卡片上的时间是这一屏真正的内容，用 96rpx 的大数字。
- **英文小标题**：只在四个 Tab 的大标题上方各一个（TODAY、LEARN、SERVICES、PROFILE），不超过 3 个词、木色、字距 0.12em；别的标题上都不挂英文。
- **形**：页边距 32rpx，间距用 16 / 24 / 32 / 48 / 64 rpx 几档；圆角三档：12rpx（按钮、输入框）、16rpx（卡片）、24rpx（底部弹层），卡片里套的元素圆角更小；卡片 1 像素细线、不加阴影（只有弹层有一层柔和阴影），不出现「卡片里套卡片」、卡片左边的彩条、标题上方的图标方块。按钮高 96rpx；列表行高不小于 112rpx；可点区域不小于 88rpx、彼此至少隔 16rpx。
- **图标**：1.5 像素细线单色图标（24 格），不用表情、不用彩色图标。
- **导航栏**：自己画（`navigationStyle: custom`），只保留右上角的微信胶囊；高度按胶囊的位置算（`(胶囊上沿 − 状态栏高) × 2 + 胶囊高`），左边的内容不越过胶囊左沿。Tab 页是大标题，子页面是居中的小标题 + 左上角返回，iOS 边缘右滑返回照样能用。底部固定的按钮条留出 `env(safe-area-inset-bottom)`。
- **动效**：按下反馈 100 毫秒内出现——缩到 0.97、`hover-class` 停留 120 毫秒（微信默认 400 毫秒太拖）；日常的状态变化 200 毫秒、底部弹层 280 毫秒，退出是进入的 60–70%；缓动一律 ease-out（`cubic-bezier(0.23, 1, 0.32, 1)`），不用回弹；只动位移与透明度，不写 `transition: all`；每一屏最多一处「讲究的动效」（打卡成功那一下），每天点上百次的操作不加动画。停用的按钮透明度 0.4。
- **提示**：成功用一句轻提示（1.5 秒自己消失），**错误不用一闪而过的提示**，写在出错的地方、写明原因和怎么办，直到处理好；整页加载失败给「重新加载」按钮。

## 5. 架构

```
员工小程序（汤崎 WCP，微信）
   │ HTTPS  staff.yuzusystem.xyz/api/staffmp/*      （request、downloadFile 合法域名）
   ▼
放 Caddy 的那台服务器（与 sys.yuzusystem.xyz 同一台；docs/DEPLOY_WEBSITE.md）
   ├─ /api/staffmp/*  → yuzu 员工小程序端口 STAFFMP_PORT（新）
   └─ 其余           → yuzu 员工端口 CANTEEN_PORT（柚子饭堂网页，过渡期照旧）
   ▼
yuzu · 员工小程序端口：单开的 Fastify 实例，只挂员工小程序的接口（白名单）
   ▼
yuzu 数据库（员工账号、WCP、员工培训 / 汤崎学堂、饭堂、巡场都在这里）
```

### 5.1 为什么不照顾客小程序走网关

顾客小程序走网关（`src/gateway`）是因为会员、余额只在门店，公网只放一台转发的网关，微信的 AppSecret 也只放在网关上。员工的东西在正式服本来就经 `sys.yuzusystem.xyz` 对外（WCP 网页），员工小程序只是多一个入口：yuzu 多开一个端口、Caddy 多一段转发，**业务规则只有一份**（WCP、员工培训、饭堂、巡场照旧在 yuzu 里），不另起服务、不另存数据。微信登录（`code2session`）由 yuzu 自己去问微信，yuzu 要能往外连 `api.weixin.qq.com`；连不上时只是不能「微信一键进」，账号密码照样能登录。

### 5.2 员工小程序端口

- 单开的 Fastify 实例（和小程序端口、员工端口同一个做法），没设 `STAFFMP_PORT` 不开；端口上**只有**员工小程序的接口：自己的 `/api/staffmp/*`，加上第 5.3 节白名单里的 WCP、员工培训接口。不挂管理后台的页面与接口，不认浏览器的 Cookie。
- **会话**：登录成功发一个令牌，小程序放在本机、每个请求带 `Authorization: Bearer <令牌>`。令牌就是 yuzu 的员工会话（`sessions` 表，与网页同样 12 小时滑动过期），所以 `req.actor`、权限、门店上下文与网页完全一样，各模块的守卫不用改；另记一张表标出哪些会话是小程序发的（解绑、停用时只清小程序的）。不用 Cookie，就没有跨站请求伪造的问题。
- **防护**：过载保护与网页同一套（`lib/protect`）；登录失败计数与网页共用（`auth/lockout`，同一个账号在网页和小程序上输错算在一起）；请求体上限 64 KB（上传附件的接口按它自己的上限）。
- **错误**：统一的错误出口（`lib/http-kit`），错误文字面向员工。

### 5.3 复用 WCP 与员工培训的接口（白名单）

小程序要的打卡、排班、审批、通知、公告、工资条、通讯录、员工培训，网页那边都有现成的接口。员工小程序端口**把这些模块原样挂上**，外面的地址加前缀 `/api/staffmp/`（`/api/staffmp/oa/attendance/today` 进的就是 `/api/oa/attendance/today` 那个处理函数），再用一张白名单（方法 + 路由）只放行员工小程序要用的那几个：

- 管理用的接口（排班编排、考勤设置、工资批次、导入……）即使在同一个模块里也不放行；
- 白名单写在 `src/server/modules/staffmp/allowlist.ts`，用例核对每一条都对得上真实的路由、没有一条管理接口；
- 主线以后改了这些接口的规则，小程序自动跟着变；主线删了或改了地址，用例会报。

汤崎学堂的员工端接口合进 `main` 以后，按同一个办法加进白名单（学习 Tab 按服务端报的开关亮起来）。

### 5.4 饭堂与巡场：员工账号和饭堂账号对上

柚子饭堂和巡场用的是饭堂自己的员工账号（`canteen_employees`，与系统账号分开，`docs/CANTEEN.md` 第 1 节）。员工小程序用的是系统账号，所以要对上（第四批做，细节到时写进本节）：

- 第一次点「吃饭」或「巡场」：按人事档案里的手机号（`staff_profiles.phone`，人事维护）找饭堂名单里同一个手机号的人；找到一个就问「这是你的饭卡吗：张三 · 前厅部」，点「是我」就对上；对上的同时让那个饭堂账号在网页上的登录全部退出、饭卡码换一把钥匙（之后只认小程序这边）。
- 没找到：点「开通饭卡」就用系统账号的姓名、部门在饭堂名单里加一个人（来源记「员工小程序」），不用再登记一遍。
- 饭卡码、打卡、点赞、巡场打卡都照用饭堂与巡场原来的规则（一人一餐一次、码 30 秒一换、离线也能亮、巡场一轮一次），小程序只是另一个入口。
- 对上关系一人一个，后台「员工食堂 → 名单」能看到、能解开。

## 6. 登录与账号

- **第一次**：账号（柚子的用户名）+ 密码登录；勾着「以后用这个微信直接进」（默认勾上）就把这个微信绑到这个账号。
- **以后**：打开小程序先用微信登录（`wx.login` 的 code 交给 yuzu 换 openid），绑过的直接进；会话过期也是这样悄悄重新进，员工感觉不到。
- **谁能登录**：在职员工（账号启用、挂着在营业的门店、不是平板 / 他店 / 设计师等专用账号、人事档案不是离职）；和 WCP 网页、员工培训同一条规则。离职、停用以后马上进不来（每个请求都查）。
- **一个微信只绑一个账号，一个账号只绑一个微信**：在新手机上绑，旧的那个自动解开（审计里记着）；员工可以在「我的」里解绑；后台「WCP 设置 → 员工小程序」能看谁绑了、能解开。解开时这个人在小程序上的会话全部退出。
- **第一次登录要改密码的**（后台建账号时给的初始密码）：登录后先到改密码页，改完才能用别的；老账号还没选新岗位的提示「请先在电脑上登录柚子选岗位」。
- **改密码**：在「我的」里改，改完别的地方（网页、其他手机）的登录都退出，这台不退。
- **模拟微信**：开发、测试环境设 `STAFFMP_MOCK_WECHAT=true` 时不问微信，code 写 `mock-<名字>` 就当成一个微信用户（与顾客小程序的模拟同一个做法）；正式、试用环境设了也不认。

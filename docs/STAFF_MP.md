## 0. 一句话

员工在微信里打开 **汤崎 WCP**：第一次用柚子的员工账号登录，之后点开就进（没信号也先把上次的样子与饭卡码亮出来）。首页「今天」上面一张卡说清此刻的状态（该上班了、在班中、饭点、巡场这一轮还差几处），下面一排位置固定的三个按钮「打卡 · 饭卡码 · 扫一扫」，再下面是要我动手的待办；「学习」是汤崎学堂与知识库；「工作台」把考勤、申请审批、吃饭、巡场、工资条、通讯录按要办的事排好；「我的」是自己的资料与设置。

## 1. 谁用、一天里用来做什么

门店一线员工（前台收银、技师、餐饮、客房管家、安保、保洁、工程）与各部门主管、店总、人事。很多人手机熟练度一般、上班时间紧、常常一只手拿着东西，店里有的地方信号不好。按一天里用到的次数排：

| 次数        | 要做的事                                         | 现在在哪做                               | 小程序里                                        |
| ----------- | ------------------------------------------------ | ---------------------------------------- | ----------------------------------------------- |
| 每天 2 次+  | 上下班打卡                                       | WCP 网页（`/oa`）                        | 首页固定的「打卡」，点开就是打卡页              |
| 每天 1–3 次 | 到饭堂亮饭卡码；看今天吃什么                     | 柚子饭堂（网页）                         | 首页固定的「饭卡码」，没信号也能亮              |
| 每晚多次    | 安保巡场扫码                                     | 柚子饭堂「工作台 → 巡场」                | 首页固定的「扫一扫」；此刻卡写这一轮还差几处    |
| 每天        | 看排班（今天几点、明天休不休）                   | WCP 网页「我的排班」                     | 此刻卡与「今天」一行；工作台 → 考勤             |
| 每天 5 分钟 | 每日一练、必修课、上岗前查应知应会               | WCP 网页「员工培训」；汤崎学堂开发中     | 学习 Tab；待办里的必修                          |
| 每周几次    | 请假、补卡、主管审批                             | WCP 网页「审批」                         | 待办「待我审批」；工作台 → 申请与审批           |
| 每周几次    | 看通知、公告                                     | WCP 网页                                 | 首页铃铛；公告在首页下方                        |
| 每月        | 工资条（有异议就提）、假期余额                   | WCP 网页                                 | 待办「工资条待确认」；工作台 → 人事             |
| 偶尔        | 找同事电话                                       | WCP 网页「通讯录」                       | 工作台 → 通讯录，一点就打                       |
| 主管每天    | 本部门今天谁到了、巡场漏了哪、饭堂多少人         | 后台各页                                 | 工作台 → 管理（有权限才出现）                   |

从这张表得出三条：**打卡、吃饭、巡场三件事有很强的时间性**，而且常常在同一段时间里（午饭时间可能就在下班窗口里）；**学习是每天一点、上岗时随手查**；**其余都是「有事才找」**。所以不按后台模块分 Tab：「今天」管时间性的事，但三件事各有一个**位置固定**的按钮（不让同一个位置在不同时候变成不同的事）；「学习」单独一个 Tab（店主说最重要）；「工作台」收其余的事（员工在 WCP 网页手机版上已经熟悉「工作台」这个叫法）；「我的」放自己。

## 2. 信息架构

### 2.1 四个 Tab

| Tab    | 英文小标题 | 放什么                                                                                       |
| ------ | ---------- | -------------------------------------------------------------------------------------------- |
| 今天   | TODAY      | 此刻卡（状态）、三个固定按钮（打卡 · 饭卡码 · 扫一扫）、待办、今天的班次与菜、公告           |
| 学习   | LEARN      | 搜应知应会、继续学习、我的必修、每日一练、学习地图、知识库、证书                             |
| 工作台 | WORKBENCH  | 按要办的事分组的全部入口（第 2.4 节）；顶上一个搜索框，搜功能名                              |
| 我的   | PROFILE    | 自己的资料、学分与等级、假期余额、绑定的微信、改密码、大字、关于（版本、实例标识）           |

没有单独的「消息」Tab：现在没有聊天（WCP 网页的即时通讯这一版不搬）。**要我动手的进首页待办，只是知会的进首页右上的铃铛**（SP03）。以后把聊天搬进来时再加消息 Tab。

### 2.2 今天（首页）

自上而下：

1. **页头**（大标题区，在微信胶囊按钮的下面一行，不和胶囊挤在一起）：「早上好，小林」、门店名、日期与星期；右边两个按钮：铃铛（有未读带红点）、我的头像（去「我的」）。导航栏常显实例标识与版本 + SHA（`AGENTS.md`「环境隔离」；正式服写「正式服」、中性颜色，测试服、演示库用提醒色）。
2. **此刻卡**：只写状态，不放会随时间换意思的大按钮。状态直接用门店系统回的「下一张卡」提示（`/api/oa/attendance/today` 的 `nextPunch`，它已经分了没进考勤组、缺卡、休息、在班），小程序不另写一套考勤判断。按下面的顺序取第一条成立的：

   | 先后 | 条件（都按门店系统回的）                                  | 卡上写什么                                                                                       |
   | ---- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
   | 1    | 下一张是上班卡、在打卡窗口里                              | 「09:00 上班 · 前厅早班」，「还有 12 分钟」或「已迟到 3 分钟」（迟到用陶土红 + 文字）           |
   | 2    | 下一张是下班卡、已到下班时间                              | 「18:00 下班 · 已到下班时间」                                                                    |
   | 3    | 本人在班中、是巡场部门的、这一轮还没巡完                  | 「第 6 轮 21:00–00:00 · 还有 3 处没巡」与这几处的名字                                           |
   | 4    | 在开饭时间里、能用饭堂、这一餐还没打卡                    | 「午餐 10:30–14:30」与今天的几道菜                                                              |
   | 5    | 在班中                                                    | 「在班 · 18:00 下班」；下班前要走的，卡上有一个文字按钮「提前下班」（点了先确认「会记早退」）   |
   | 6    | 今天休息（有排班、今天是休息）                            | 「今天休息」，下一个班是哪天几点                                                                |
   | 7    | 没有排班                                                  | 「这几天没有排班」，「问问主管」                                                                |
   | 8    | 没进考勤组、缺卡等门店系统给了说法的                      | 原样写门店系统的话，带「去补卡」「怎么办」这样的出路                                            |

3. **三个固定按钮**（一排，位置永远不变）：**打卡**（进打卡页：大按钮打当前该打的卡，下班窗口没到时只有「提前下班」文字按钮）、**饭卡码**（能用饭堂的才有；进饭卡码页，调亮屏幕、常亮）、**扫一扫**（第 2.6 节）。打卡、亮码都在自己的页面上做，结果留在那一页上直到离开，不会因为时间到了就把按钮换成别的事。
4. **待办**：只放要我动手的事，最急的在上面，每条一行（图标、一句话、截止或时间、右箭头）：待我审批 N 件、我的申请被驳回要改、缺卡要补、工资条待确认、必修课快到期（学堂上线以后）。没有待办时写「都处理完了」，不留空白。
5. **今天**：一行写我的班次（「09:00–18:00 · 前厅早班」），一行写今天的菜（能用饭堂才有），点开各到自己的页面。
6. **公告**：最近 3 条标题（置顶的在前），点开看全文，「全部公告」在最下面。

### 2.3 学习

店主说培训最重要，所以单独一个 Tab。界面归员工小程序线，内容、规则、接口归主线的「汤崎学堂」（另一个开发会话在做，设计稿 ACADEMY 在它的集成 PR [#50](https://github.com/tiebanyinshi/yuzu-2.0/pull/50) 上）。

- **页顶是搜索**：上岗前查应知应会最常见，一个输入框同时搜资料与课程；最近搜过的留 5 条。
- **学堂上线以前**（第一版就有）：「知识库」按文件夹列出员工培训的资料（培训资料 + 本部门），没看过的标「新」；点开就在小程序里看——PDF、Word、Excel、PPT 用微信自带的文档预览，图片放大看，视频在页里播（mp4，iPhone 放不了的格式写明「请在电脑上看」）；看过就记「看过」（与 WCP 网页同一条记录）。
- **学堂上线以后**（主线把员工端接口合进 `main` 以后，服务端在「我是谁」里报「学堂开了」才出现）：继续学习（上次学到哪）、我的必修（带截止日）、每日一练（连续天数）、学习地图、证书、学分与等级。员工端接口照第 5.3 节的办法挂到员工小程序端口上。
- **课件是阅读屏**：正文 32rpx、行高 1.6，一屏一段，不放与课无关的东西。

### 2.4 工作台

按「要办的事」分组，组名用员工能懂的话；每组只列这个人能用的入口，整组都没有就不显示：

| 组         | 入口                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------- |
| 考勤       | 打卡、我的排班、考勤记录、假期余额                                                                       |
| 申请与审批 | **发起申请**（请假、补卡、工资条异议……，模板由后台定）、我的申请、待我审批、抄送我的                     |
| 吃饭       | 饭卡码、今天的菜单；食堂负责人另有「扫码登记」「今天多少人」                                             |
| 巡场       | 扫码巡场、这一轮；能看记录的人另有「巡场记录」                                                           |
| 人事       | 工资条、通讯录、公告                                                                                     |
| 管理       | 有权限才出现：本部门今天的考勤、巡场记录、饭堂人数（随主线接口逐步加）                                   |

顶上的搜索框搜入口名（打「工资」出工资条、打「假」出请假与假期余额）。入口图标一律细线图标、单色，不用表情。

- **发起申请**：审批模板是后台定的表单（`/api/oa/approval/templates`），小程序照模板的字段画表单（文字、多行文字、数字、日期、时间、选项、照片附件），提交走网页同一个接口、带操作编号；没提交出去的内容留在手机上（草稿）。服务端给的出路都能接上：考勤记录里的缺卡一点「补卡」带着日期、班次进补卡单；工资条「有异议」带着那一月进工资条异议单。模板里有小程序画不了的字段类型时，这一个模板写「请在 WCP 网页上提交」。
- **工作台那一批的做法**（C）：模板现有的十二种字段都画（附件只收照片，文件在网页上传）；假种从「我的假期」带出来，班次从那天的排班带出来，关联单从「我发起的已通过」带出来；草稿按人、按模板存在手机上（不存照片）。审批人只有「同意」「驳回」，**转交**要选人（`oa/approval/people` 不在白名单），这一版在网页上做。
- **结果待确认**（第 2.8 节）在手机上按人分开存；没确定以前同一处（自己的打卡、同一个模板的申请、同一张单的处理）不发新的，手机上没有「放弃」（端口上没有「确认作废」，查不到也不能断定没生效）。重提被门店明确拒绝算数：审批的提交与处理在事务里先锁操作编号再查办没办过；打卡先查编号、没办过才核对位置，最坏多一条打卡明细（考勤按第一次 / 最后一次算）。没登录（401）不算拒绝，登录以后原样重提。

### 2.5 我的

头像（姓名首字）、姓名、部门 · 岗位、门店；学分与等级（学堂上线以后）；假期余额一行；绑定的微信（解绑）；改密码；**大字**（正文与列表放大一档，默认跟着微信的字体大小设置）；振动开关（打卡、巡场成功时轻振，默认开）；关于：小程序版本、门店系统的版本 + SHA、实例标识；退出登录（「退出」与「退出并解除这个微信」两个）。

### 2.6 扫一扫

首页固定按钮与「工作台」都有；只从相机扫（不让从相册选图，巡场要在现场）。扫到什么按码里的内容分：巡场点的码 → 巡场打卡；员工的饭卡码（食堂负责人）→ 打卡登记（负责人连续扫码用页内的相机取景，一个接一个不用每次点）；以后培训资料上的码 → 打开那份资料。认不出的码写「这不是店里的码」，不跳到别处。已经贴好的巡场码是网址，小程序后台配「扫普通链接二维码打开小程序」以后用微信扫一扫也能直接进巡场打卡（上线前真机试，第 10 节）。

### 2.8 没信号、第一次用、出错的时候

| 情况                         | 怎么办                                                                                                                                                                                                 |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 打开时没信号                 | 先用手机上存的「我是谁」与上次的内容把页面画出来（标「之前的信息」），登录放到后台做；饭卡码照样能亮（码钥匙存在手机上，会话过期也不删）                                                               |
| 打卡时没信号                 | 直接说「现在连不上门店系统，打不了卡：到有信号的地方再点」。**不排队补交**——打卡时间按门店系统收到的时刻记，排队补交会变成迟到                                                                         |
| 打卡、审批没收到回复         | 进「结果待确认」：页面上写「这一次可能已经打上了」，按原操作编号原样重提，拿到明确结果为止（`AGENTS.md` 开发约定）                                                                                     |
| 巡场时没信号                 | 扫到的先存在手机上（读回核对，存不下就不发），联网后按原编号补交（巡场按扫到的时刻核对，与柚子饭堂网页同一个规矩）                                                                                     |
| 定位失败、在打卡范围外       | 写门店系统的原话（「不在打卡范围内」与离最近打卡点多远）；给「重新定位」与「外勤打卡」（写事由、拍一张照片）                                                                                             |
| 没进考勤组、这几天没排班     | 写清楚找谁（「请找人事把你加进考勤组」「问问主管排班」），不给打卡按钮                                                                                                                                 |
| 要刷脸的考勤组               | 写「这个考勤组要刷脸，请在 WCP 网页上打卡」（SP13）                                                                                                                                                    |
| 第一次用                     | 登录页一句话说清用什么登录（「用柚子的账号和密码」），下面写「忘了密码、不知道账号：找人事」；第一次登录要改密码的直接到改密码页；老账号要选岗位的在小程序里就能选，不让一线员工去找电脑           |
| 门店系统出错                 | 错误留在出错的地方，写原因和怎么办；整页取不到时给「重新加载」                                                                                                                                        |

## 3. 体验原则（清楚、人性化）

1. **常用的位置不变**：打卡、饭卡码、扫一扫在首页一排固定的位置；同一个位置不会因为时间不同变成不同的事。
2. **一屏一个主操作**：每个页面最多一个实心主按钮，放在拇指够得着的下半部；次要操作用文字按钮；会产生后果的（提前下班记早退、换绑微信）先确认、写清后果。
3. **说人话**：按钮写动词（上班打卡、亮饭卡码、同意），同一个动作前后叫法一致（上班打卡 → 已打上班卡）；错误写「为什么 + 怎么办」，服务端已有的错误文字原样显示。
4. **结果当场看得见、留得住**：打卡、审批、巡场成功后在原地变成结果，留到离开这一页；不弹「操作成功」再让人点确定。
5. **没信号也不慌**：见第 2.8 节。
6. **不让人等白屏**：页面先出骨架，再出数；下拉刷新；短于 300 毫秒不出加载样子。
7. **空的时候也有话说**：每个列表都写空的时候说什么，不留空白。
8. **该有的才出现**：用不了的入口不显示，不出现点进去才说「没有权限」。
9. **看得清**：正文不小于 28rpx，必要的信息不放在 22、24rpx 的小字里；对比度正文 4.5 : 1、输入框与次按钮的边 3 : 1；可点区域不小于 88rpx；「我的」里能开大字。
10. **不打扰**：振动只在打卡、巡场成功时轻振一下（能关）；权限用到时才请求，第一次登录就把隐私说明一起同意掉（「同意并登录」）。

## 4. 视觉：汤崎 WCP 的样子

（设计约束的来源与核对清单见第 13.1 节；颜色与字号在小程序里写成令牌，页面只用令牌。）

- **气质**：一本放在汤泉边的工作手册——正式、安静、留白多；品牌照汤崎品牌书与 VI（`docs/MINIPROGRAM.md` 第 13 节、`brand/README.md`），与顾客小程序同一家人，但更克制：顾客小程序是「来玩」，员工小程序是「上班」。
- **颜色**（界面 90% 以上是中性色，只有一个品牌点缀色）：亚麻米白底 `#F5F1EA`、卡片 `#FCFAF6`、分隔细线 `#E0D7C9`（只做装饰性的分隔）；**输入框、次按钮这类要认得出边界的控件，边框用 `#958469`（在底色、卡片上都不低于 3 : 1）**；正文墨色 `#1C1A17`，次要字 `#5F574D`（6.3 : 1），占位与停用的字 `#8A8176`（只给占位字与停用的控件）；**主按钮用墨色**（正式）。木色 `#937051` 在米白底上只有 4.0 : 1，**只做大字（36rpx 以上加粗）、进度条与图形**；做字的木色（英文小标题、「新」标签、选中的字）用加深的 `#7A5C41`（在底色、卡片、浅木色标签底上都不低于 4.5 : 1；小程序的 `tests/contrast.test.ts` 逐对核对）。状态色：松绿 `#3F5E4B` 成功 / 已打卡，陶土红 `#A6452F` 错误 / 迟到，湖蓝 `#4E6B82` 提示；状态不只靠颜色，一定配字或图标。不用渐变、不用紫色、不用发光阴影、不大面积铺品牌色。
- **字**：中文与数字都用手机的系统字体（苹方、鸿蒙、安卓的系统字体），不加载网络字体；时间、金额、工资条的数字用等宽数字（`font-variant-numeric: tabular-nums`）。英文只在品牌字标与 Tab 的英文小标题上出现。字号用 TDesign 的一套：24 / 28 / 32 / 36 / 40 / 48 rpx（行高 40 / 44 / 48 / 52 / 56 / 64），标题字重 600，不用细体；**必要的信息不小于 28rpx**，24rpx 只给辅助说明；**课件正文 32rpx**、行高 1.6；打卡页上的时间是这一屏真正的内容，用 96rpx 的大数字。「大字」打开时整套放大一档。
- **英文小标题**：只在四个 Tab 的大标题上方各一个（TODAY、LEARN、WORKBENCH、PROFILE），不超过 3 个词、字距 0.12em；别的标题上都不挂英文。
- **形**：页边距 32rpx，间距用 16 / 24 / 32 / 48 / 64 rpx 几档；圆角三档：12rpx（按钮、输入框）、16rpx（卡片）、24rpx（底部弹层），卡片里套的元素圆角更小；卡片 1 像素细线、不加阴影（只有弹层有一层柔和阴影），不出现「卡片里套卡片」、卡片左边的彩条、标题上方的图标方块。按钮高 96rpx；列表行高不小于 112rpx；可点区域不小于 88rpx、彼此至少隔 16rpx。
- **图标**：1.5 像素细线单色图标（24 格），不用表情、不用彩色图标。
- **导航栏**：自己画（`navigationStyle: custom`），只保留右上角的微信胶囊；高度按胶囊的位置算（`(胶囊上沿 − 状态栏高) × 2 + 胶囊高`），胶囊那一行左边的内容不越过胶囊左沿，**按钮一律放在胶囊下面一行**。Tab 页是大标题；子页面是居中的小标题 + 左上角返回，从扫码、通知直接打开（页面栈只有一页）时左上角换成「首页」；iOS 边缘右滑返回照样能用。底部固定的按钮条留出 `env(safe-area-inset-bottom)`。
- **动效**：按下反馈 100 毫秒内出现——缩到 0.97、`hover-class` 停留 120 毫秒（微信默认 400 毫秒太拖）；日常的状态变化 200 毫秒、底部弹层 280 毫秒，退出是进入的 60–70%；缓动一律 ease-out（`cubic-bezier(0.23, 1, 0.32, 1)`），不用回弹；只动位移与透明度，不写 `transition: all`；每一屏最多一处「讲究的动效」（打卡成功那一下），每天点上百次的操作不加动画。停用的按钮透明度 0.4。
- **提示**：成功用一句轻提示（1.5 秒自己消失），**错误不用一闪而过的提示**，写在出错的地方、写明原因和怎么办，直到处理好；整页加载失败给「重新加载」按钮。

## 5. 架构

```
员工小程序（汤崎 WCP，微信）
   │ HTTPS  sys.yuzusystem.xyz/api/staffmp/*        （request、downloadFile 合法域名；SP17）
   ▼
放 Caddy 的那台服务器（sys.yuzusystem.xyz；docs/DEPLOY_WEBSITE.md）
   ├─ /api/staffmp/*  → yuzu 员工小程序端口 STAFFMP_PORT（新）
   └─ 其余           → 照旧（系统统一登录的应用端口；顾客小程序在这个域名上的路径归顾客小程序线）
staff.yuzusystem.xyz 不动：照旧是柚子饭堂网页与接口（员工端口 CANTEEN_PORT）
   ▼
yuzu · 员工小程序端口：单开的 Fastify 实例，只挂员工小程序的接口（白名单）
   ▼
yuzu 数据库（员工账号、WCP、员工培训 / 汤崎学堂、饭堂、巡场都在这里）
```

### 5.1 为什么不照顾客小程序走网关

顾客小程序走网关（`src/gateway`）是因为会员、余额只在门店，公网只放一台转发的网关，微信的 AppSecret 也只放在网关上。员工的东西在正式服本来就经 `sys.yuzusystem.xyz` 对外（WCP 网页），员工小程序只是多一个入口：yuzu 多开一个端口、Caddy 多一段转发，**业务规则只有一份**（WCP、员工培训、饭堂、巡场照旧在 yuzu 里），不另起服务、不另存数据。微信登录（`code2session`）由 yuzu 自己去问微信，yuzu 要能往外连 `api.weixin.qq.com`；连不上时只是不能「微信一键进」，账号密码照样能登录。

### 5.2 员工小程序端口

- 单开的 Fastify 实例（和小程序端口、员工端口同一个做法），没设 `STAFFMP_PORT` 不开；端口上**只有**员工小程序的接口：自己的 `/api/staffmp/*`，加上第 5.3 节白名单里的 WCP、员工培训接口。不挂管理后台的页面与接口，不认浏览器的 Cookie。
- **会话**：登录成功发一个令牌，小程序放在本机、每个请求带 `Authorization: Bearer <令牌>`。令牌就是 yuzu 的员工会话（`sessions` 表，与网页同样 12 小时滑动过期），所以 `req.actor`、权限、门店上下文与网页完全一样，各模块的守卫不用改；另记一张表标出哪些会话是小程序发的——员工小程序端口只认这些令牌，解绑、停用时只清小程序的。不用 Cookie，就没有跨站请求伪造的问题。
- **防护**：过载保护与网页同一套（`lib/protect`），频率限制按令牌（短时地址按它绑着的会话）或来源 IP；登录失败计数与网页共用（`auth/lockout`，同一个账号在网页和小程序上输错算在一起）；请求体上限 64 KB（上传附件的接口按它自己的上限）。
- **错误**：统一的错误出口（`lib/http-kit`），错误文字面向员工。
- **带不了请求头的地方**（`<video>`、`<image>` 不能带 `Authorization`）：培训视频、审批附件的缩略图用员工小程序端口发的**短时地址**（附件几分钟、培训资料几小时有效、只给这个人、只对这一个文件），端口与登录那一批（A）就做了；文档类（PDF、Office）用 `wx.downloadFile` 带请求头下载后预览。

### 5.3 复用 WCP 与员工培训的接口（白名单）

小程序要的打卡、排班、审批、通知、公告、工资条、通讯录、员工培训，网页那边都有现成的接口。员工小程序端口**把这些模块原样挂上**，外面的地址加前缀 `/api/staffmp/`（`/api/staffmp/oa/attendance/today` 进的就是 `/api/oa/attendance/today` 那个处理函数），再用一张白名单（方法 + 路由）只放行员工小程序要用的那几个：

- 管理用的接口（排班编排、考勤设置、工资批次、导入……）即使在同一个模块里也不放行；
- 白名单写在 `src/server/modules/staffmp/allowlist.ts`，用例核对每一条都对得上真实的路由、没有一条管理接口；
- 主线以后改了这些接口的规则，小程序自动跟着变；主线删了或改了地址，用例会报。
- 老账号选新岗位（`/api/auth/position-options`、`/api/auth/position`）也按这个办法挂上（外面的地址 `/api/staffmp/account/…`），一线员工不用去找电脑。

汤崎学堂的员工端接口合进 `main` 以后，按同一个办法加进白名单（学习 Tab 按服务端报的开关亮起来）。

### 5.4 饭堂与巡场：员工账号和饭堂账号对上

柚子饭堂和巡场用的是饭堂自己的员工账号（`canteen_employees`，与系统账号分开，`docs/CANTEEN.md` 第 1 节；部门用的是 `departments`，与人事的 `org_departments` 不是一张表）。员工小程序用的是系统账号，所以要对上（吃饭与巡场那一批做，细节到时写进本节）：

- **上线前在后台先对好一批**：「员工食堂 → 名单」按手机号把人事档案与饭堂名单对一遍，一对一对得上的列出来，管理员核对后一键对上；对不上的留着。
- **员工第一次点「饭卡码」或巡场**：已经对好的直接用；没对好的先问「以前在柚子饭堂登记过吗」——登记过的输一次饭堂的账号和密码证明是自己，就对上（不靠手机号猜）；没登记过的点「开通饭卡」，用系统账号的姓名开一个普通员工的饭卡（来源记「员工小程序」）。厨师、食堂负责人、巡场部门这些身份只由后台安排，开通的新饭卡不带。
- **对上不影响网页**：厨师发菜单、负责人看柚子信箱还在柚子饭堂网页上（SP11），网页的登录与没补交的巡场都不动；饭卡码两边亮的是同一个人的码（规则照旧一人一餐一次）。
- 饭卡码、打卡、点赞、巡场打卡都照用饭堂与巡场原来的规则（码 30 秒一换、离线也能亮、巡场一轮一次），小程序只是另一个入口。
- 对上关系一人一个，后台「员工食堂 → 名单」能看到、能解开。

## 6. 登录与账号

- **打开小程序**：先用手机上存的「我是谁」把页面画出来，同时在后台用微信登录（`wx.login` 的 code 交给 yuzu 换 openid）：这个微信绑过账号的直接进，会话过期也是这样悄悄重新进，员工感觉不到；没信号时停在上次的样子（第 2.8 节）。
- **登录页**：最上面是「微信一键登录」（绑过的点了直接进；没绑过的说明「第一次要用柚子的账号登录一次，之后就能一键进」），下面是账号（柚子的用户名）+ 密码；「同意并登录」一并同意隐私说明；下面写「忘了密码、不知道账号：找人事」。
- **绑微信（SP05）**：账号密码登录时有一个勾选「以后用这个微信直接进」。
  - 这个微信**没绑过**任何账号：默认勾上。
  - 这个微信**已经绑着别人**（例如在同事的手机上登录）：默认**不勾**；要勾的话先确认「这个微信现在绑着某某。改绑给你以后，某某在这台手机上就不能一键进了」。门店系统同样把关：没有明确要换绑的请求一律不顶掉别人的绑定。被顶掉的人收到一条通知。
  - 不勾就是「只登录这一次」：会话过期或退出以后要重新输密码。
- **一个微信只绑一个账号，一个账号只绑一个微信**：自己在新手机上绑，旧手机上的自动解开（审计里记着）；员工在「我的」里能解绑；后台「WCP 设置 → 员工小程序」能看谁绑了、能解开。解开时这个人在小程序上的会话全部退出。
- **谁能登录**：在职员工（账号启用、挂着在营业的门店、不是平板 / 他店 / 设计师等专用账号、人事档案不是离职）；和 WCP 网页、员工培训同一条规则。离职、停用以后马上进不来（每个请求都查）。
- **第一次登录要改密码的**（后台建账号时给的初始密码）：登录后先到改密码页，改完才能用别的；老账号要选新岗位的在小程序里选（第 5.3 节）。
- **改密码**：在「我的」里改，改完别的地方（网页、其他手机）的登录都退出，这台不退。
- **模拟微信**：开发、测试环境设 `STAFFMP_MOCK_WECHAT=true` 时不问微信，code 写 `mock-<名字>` 就当成一个微信用户（与顾客小程序的模拟同一个做法）；正式、试用环境设了也不认。

| 13 | 按下 100 毫秒内有反馈：缩到 0.97、`hover-class` 停留 120 毫秒；停用透明度 0.4 | emil-design-eng、微信、Material 3 |

| 17 | 子页面左上角有返回，边缘右滑能返回；底部固定条留安全区 | 微信、Apple HIG、gstack |

### 13.2 方案评审记录

2026-11-27，独立的评审（扮演「微信小程序清晰、人性化体验专家」，只给它初稿与员工的处境，让它自己读仓库、查微信官方文档）。结论：「方向对，按一天里什么时候做什么组织，规则只有一份，也说人话；但有四处会造成误打卡、走不通或串号，提审还缺两步准备」。逐条怎么改的：

| 级 | 评审说的 | 怎么改的 |
| --- | --- | --- |
| P1 | 此刻卡的主按钮随时间换意思：下班窗口默认提前 60 分钟就开（会记早退），午饭时间常在打卡窗口里，饭堂门口点同一个位置打出去的是打卡；打卡成功 2 秒后换成下一件，连点会触发下一件 | 此刻卡只写状态，下面加一排位置固定的「打卡 · 饭卡码 · 扫一扫」；没到下班时间只有文字按钮「提前下班」并确认「会记早退」；结果留到离开这一页；直接用门店系统回的 `nextPunch`，「今天休息」和「没有排班」分开说；巡场那条只在本人在班时出现（第 2.2 节） |
| P1 | 第一版没有发起申请，可服务端给的出路（缺卡补卡、工资条有异议）都指向申请单，网页手机版已经能做 | 工作台那一批就做发起申请：照后台的审批模板画表单（请假、补卡、工资条异议……），缺卡、工资条带着内容进申请单（第 2.4 节、第 9 节） |
| P1 | 绑定默认勾选、新绑的顶掉旧的：在同事手机上登录会把同事的微信绑到自己，同事再打开进的是别人的账号 | 这个微信绑着别人时默认不勾，要勾先确认会顶掉谁；门店系统也把关：没带 `replace` 不顶掉别人；被顶掉的人收到通知；不勾就是「只登录这一次」（第 6 节，已在 A 批实现并有用例） |
| P1 | 没网时卡在微信登录；打卡按门店系统收到的时刻记，排队补交会变成迟到 | 启动先用手机上存的内容画页面、登录放到后台；会话过期不删饭卡码钥匙；打卡没网直接说「到有信号的地方再点」，不排队（第 2.8 节） |
| P1 | 提审少准备：`getLocation` 要「工具 > 办公」类目并在接口设置里开通；有账号体系要给测试账号，可正式库不许写演示数据 | 写进上线步骤（第 10 节第 1、4 条）；审核专用账号请店主定（SP14） |
| P2 | 饭堂账号按手机号对上不可靠（饭堂登记没验短信、人事档案的手机号可能是空的），「开通饭卡」会给厨师、负责人、安保开一个没角色的新号；对上时让网页登录全部退出会打断厨师发菜单、没补交的巡场 | 上线前后台按手机号预先对好一批；员工端没对好的先问「以前登记过吗」，用旧饭堂账号密码证明；开通的新饭卡只是普通员工；对上不动网页的登录（第 5.4 节） |
| P2 | 待办里混着「要处理」和「知会」，三处都有未读 | 待办只放要动手的事，知会的进铃铛（第 2.1、2.2 节） |
| P2 | 木色字、细线、卡片边界对比度不够；安卓没有 Helvetica Neue；22/24rpx 放了必要信息 | 字用的木色加深到 `#7A5C41`；输入框、次按钮的边 `#958469`（评审建议的 `#9C8B72` 在米白底上只有 2.94 : 1，对比度用例没让它过）；数字用系统字体 + 等宽数字；必要信息不小于 28rpx；「我的」里能开大字（第 4 节） |

| P2 | 「请在电脑上选岗位」对一线员工是死路 | 选岗位的两个接口挂进白名单，小程序里就能选（第 5.3 节，已在 A 批实现并有用例）；登录页写「忘了密码、不知道账号：找人事」 |
| P2 | 首页要用到后面几批的数据 | 分批改成：骨架与学习 → 工作台 → 今天 → 吃饭与巡场（第 9 节） |

评审认为应该保留的：按「什么时候要做什么」分 Tab、学习单独一个 Tab；白名单挂主线接口、每个请求当场核权限、服务端错误原文显示；用不了的入口不显示、权限用到时才请求；结果在原地显示、按原操作编号原样重提、饭卡码离线也能亮、暂时不做「消息」Tab。

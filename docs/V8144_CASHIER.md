# 8.1.44（收银台）：《前台系统开发》里收银台的六条

店主 2026-11-25 的《前台系统开发》十一条，这一份是收银台的六条（第 1、7–11 条）；另外五条（已发券改使用条件、混合支付、同行人组建与拆分结算、房态显示当天预约、买单时建档与查会员）在另一份说明里。店主早先的话：先看系统里有没有类似的，有就补全、扩展，不另做一套；做之前想想会不会把原来的弄复杂。

迁移 `350_visit_remarks.sql`（回滚 `docs/rollback/350_visit_remarks.down.sql`）。

## 1. 逐条

| 需求 | 系统里已有的 | 这一版 | 怎么不把原来的弄复杂 |
| --- | --- | --- | --- |
| ① 前台备注记经办人与时间，分同组备注与单人备注 | 没有给客人写备注的地方：接待时只有一个「称呼」（16 个字）；「异常处置」是提醒、加收、上报这几样处置，不是备注；结账单上的备注只管那一笔收款 | 新的「备注」：一条记谁、几点（`visit_remarks`，只追加）；有同行时选「单人 · 这张手牌」或「同组 · 组号」，同组备注组里每张手牌都看得到，单人备注只在这一张；写错了「撤下」（留原因、经办人，划掉显示，`visit_remark_removals`） | 不往「异常处置」里加一种：异常有待办、责任人、处理结果，备注没有，混在一起两样都难看。备注与发牌、挂账、结账互不相干，不加锁顺序以外的东西 |
| ⑧ 收银台单独增设备注板块（客诉或特殊标签） | 同上 | 与第 ① 条**是同一份数据**：收银台账单右边一块「备注（客诉 / 特殊标签）」，发卡台客人卡上也是这一块；写的时候可以点一个标签（默认「客诉」「特殊关照」），带了标签的在收银台待结账清单那一行标出来 | 标签清单放在已有的「数据字典」（`remarkTags`，后台「数据字典与字段」改），不另建标签表；记的是文字，清单改了以前的照旧显示 |
| ⑦ 发卡台去掉「选择套餐」 | 「接待发牌」每位客人一行有一个「票种」下拉（不含餐 / 含餐 / 儿童免票……），就是业务说的「套餐」；改票种另外在账单上 | 接待发牌去掉这个下拉，一律按默认票种发牌；要改（儿童免票等）在账单上「改票种」，收银台也加了这个入口，照旧要当场授权 | 服务端不动：发牌请求不带票种时本来就用默认票种，带票种的旧请求（结果待确认的重提、别的终端）照旧能用；接待时选免票的授权流程留着不删（不再从页面走到） |
| ⑨ 收银台提供打单、买单、买角 | 打单：有「预结账」（屏幕上看）但打不出来；买单：就是「结账」；买角：没有 | 打单：账单底部「打单」，打一张 80mm 预结单（这位客人和同组在店的手牌，已挂明细 + 按此刻估算的门票 + 合计，写明不是结账单）；买单：「结账」按钮改叫「买单」（F9 照旧）；买角：「买角」（F6）打开挂账对话框，先敲数字代号回车加一份，代号 → 项目与价格档的清单在后台「手牌与前台 → 前台规则 → 买角代号」，默认空 | 预结单用结账对话框同一个核对接口（`/api/frontdesk/checkout-preview`），不另写计价；买角就是加项目，提交走原来的挂账（同一个操作编号、结果待确认、技师、沽清、出品口），不另开一个写入口；代号清单存在前台规则里（`frontdesk_rules.buyCodes`），不加表 |
| ⑩ 「加项目」「作废」迁至收银台；发卡台及开台环节不允许 | 8.1.15 起发卡台加项目、作废，收银台只读 | 收银台账单上：加项目（F4）、买角（F6）、每条明细的作废 / 退菜、改票种；发卡台客人卡去掉加项目、F4 与每条明细上的作废，接待发牌本来就不能加项目；顶部「结果待确认」里的挂账改到收银台处理 | 权限照旧（「接待发牌、同行绑牌、挂账、换牌」与「作废他人或超时明细」，岗位不变），作废照旧留原因、经办人、时间与审计。服务端不按「哪个台」拦：两个台是同一批岗位，接口分不出是哪个页面发来的，硬拦只会挡住点单页、钟房、房态这些本来就能挂账的地方。换牌、同行、转明细、异常处置留在发卡台 |
| ⑪ 收银台左栏收纳、账单区放大，上栏去掉重复的手牌、入场时间、在店时长 | 收银台左边是待结账清单（宽），右边 400–460 像素的账单 | 打开一位客人后（门店电脑、平板横屏）左栏收成 320–360 像素、一行一位（牌号、客人、金额、提醒），选中的那一行写入场时刻与在店时长；右边账单区放大，够宽时明细在左、权益与备注在右；账单抬头不再写手牌号、入场时间、在店时长（牌号留给读屏）。没选人时照原来的版面；窄屏（账单是侧滑抽屉）照原来的抬头 | 只改版面，数据与接口不动 |

## 2. 待业务确认（`docs/PENDING_DECISIONS.md` FD44-1–FD44-5）

- 买角数字代号的编码规则、对应项目与计价口径：清单没给之前默认一条都没有，收银台「买角」写明还没配置；代号 1–4 位数字，一个代号对一个项目的一档价格，按项目当前价计价。
- 「加项目」迁到收银台以后的操作权限与作废留痕：照原来的权限与留痕（见上表第 ⑩ 条）。
- 收银台备注板块的预设标签：默认「客诉」「特殊关照」两类；不选标签也能写。
- 「选择套餐」理解成接待发牌里的「票种」下拉；不是的话请业务指出是哪一项。
- 备注谁能撤下：写的人自己，或值班经理及以上（有「作废他人或超时明细」的）。

## 3. 接口

| 接口 | 说明 |
| --- | --- |
| `POST /api/frontdesk/visits/:id/remarks` | 写一条备注：`{ clientKey, scope: 'single' \| 'group', tag?, note }`，返回这位客人的详情。有「接待发牌……」或「结账收款」权限的都能写；同一个 `clientKey` 原样重提返回第一次的结果，内容对不上 409；没有同行写同组备注 422 `NO_GROUP` |
| `POST /api/frontdesk/remarks/:id/remove` | 撤下：`{ visitId, reason }`（`visitId` 是现在打开的客人，返回他的详情）；只能撤一次 |
| `GET /api/frontdesk/visits/:id` | 多 `remarks`：这位客人的单人备注与所在同行组的同组备注（含撤下的） |
| `GET /api/frontdesk/board` | 每位在店客人多 `remarkTags`（没撤下的备注带的标签，去重）；`rules` 多 `buyCodes` |
| `GET` / `PUT /api/frontdesk/rules` | 多 `buyCodes: { code, itemId, tier }[]`（默认 `[]`，最多 200 条）；只改别的规则不动它。保存时核对代号格式、不重复、项目在售且有那一档价格 |
| 页面 `/print/prebill/:ids` | 收银台「打单」的 80mm 预结单（只读，数据来自 `checkout-preview`） |

审计多两种：`visit_remark`（前台备注）、`visit_remark_removed`（撤下前台备注）。数据字典多两份：`remarkTags`（前台备注的标签）、`remarkRemoveReasons`（撤下备注的原因）。

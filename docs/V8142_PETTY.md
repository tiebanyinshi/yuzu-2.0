# 8.1.42 · 备用金合并：零采备用金并进备用金

店主 2026-11-25：「零采备用金和备用金重复了，请将所有零采备用金和备用金的部分进行合并。以后只有一个备用金，请你在前后端以及数据库都执行这个操作，注意一致性。」

迁移 `340_petty_merge.sql`，回滚 `docs/rollback/340_petty_merge.down.sql`，升级用例 `tests/upgrade-petty-merge.test.ts`，功能用例 `tests/petty-uses.test.ts`。没定的默认做法见 `docs/PENDING_DECISIONS.md`「8.1.42 备用金合并」BH1–BH6。

## 1. 原来的两套

| | 备用金（v0.7.7、v0.7.29，`docs/EXPENSES.md`、`docs/ERP_PURCHASING.md` 第 4 节） | 零采备用金（8.1.9，`docs/ERP_V819.md` 第 2 节） |
| --- | --- | --- |
| 账在哪 | 按部门：打款（BY）、用备用金的报销（BX，选出自哪一笔打款）、退回 / 补付（TH / BF） | 全公司一份：设置里的总额 `petty_pool` |
| 余额 | 打款 − 已确认支出 − 退回 + 补付（部门台账、每日平账同一口径） | 剩余可用 = 总额 − 占用 |
| 花钱怎么记 | 财务登记报销单，钱从「备用金」来，扣这个部门的余额 | 采购先「申用」（LC，登记即占用）→ 提交报销（补单）→ 财务登记报销单，钱从「零采备用金」来、勾申用 → 确认后不再占用（「自动回补」） |
| 回到定额 | 按「建议补足」（定额 − 余额）再打款 | 确认即回补，不另记单据 |
| 权限 | `expense.read` 看、`petty.manage` 打款退回、`expense.manage` 报销 | `pool.read` 看、`pool.manage` 申用（店主与采购） |

两套各记各的：零采的钱从来没在部门备用金的台账里出现过，报销单上「钱从哪来」有三种。

## 2. 合并以后：只有部门备用金

- **备用金就是部门备用金**：一个部门一份，保管人、定额、打款、退回补付、台账、余额、每日平账都照旧。
- **申用并进来**：任何部门都可以在自己的备用金上申用（原来只有零采）。申用登记即占用这个部门的可用额度：**可用 = 余额 − 已占用**；申用超过可用拦下（`PETTY_EXCEEDED`）。状态（待报销、已提交、审核中、已报销、已作废）、补单、撤回、作废、结果待确认都与零采时一样。
- **报销**：「钱从哪来」只有**备用金**和**公司直付**两项。钱从备用金来的，照旧选出自这个部门哪一笔打款，**可以**（不是必须）勾这个部门已提交报销的申用；确认后这几笔不再占用，余额少了实际报销的金额。
- **回补**：不再「确认即回补」。余额少了以后由财务按部门备用金的「建议补足」打款（或补付）回到定额——这一笔钱是真的从公司出去的，原来零采时它没有单据，现在有了。这是唯一的行为变化（BH1）。
- **零采备用金的总额就是归属部门的定额**；定额上限从 100 万元调到与原来零采总额一样的 1,000 万元。

## 4. 数据迁移规则（迁移 340）

逐个部门（有零采报销单的部门，加上归属部门）：

1. **归属部门**：设置里的 → 没有就取零采报销单最多的部门 → 名字带「供应链」「采购」的部门 → 都没有就新建「供应链」（BH2）。
2. **申用的部门**：挂着有效报销单（待确认、退回、已确认）的跟报销单的部门，其余记到归属部门。
3. **并入打款**：给这个部门登记一笔打款（凭据「零采备用金并入备用金（8.1.42 迁移 340）」，方式「其他」，日期取这个部门最早的零采报销或申用日期），金额 = **零采总额（只给归属部门）+ 这个部门已确认的零采报销合计**。零采报销单都改成钱从备用金来、挂这笔打款。
   - 为什么这样算：已确认的零采报销当时已经由公司「回补」了，并入打款里包含它们，正好抵掉，部门余额 = 原余额 + 零采总额，零采原来的剩余可用原样变成这个部门的可用（第 6 节核对）。
   - 待确认、退回的零采报销确认以后余额会少这一笔——与以后所有申用一样，由财务按建议补足打款。
4. **没法挂打款的**（这个部门算出来是 0：没配总额、也没有已确认的零采报销）：零采报销单改成「公司直付」（BH3）。
5. **定额**：归属部门的定额加上零采总额（原来没设的就等于总额；两份并成一份），最多 1,000 万元（BH4）。
6. **权限**：岗位建议权限里有 `pool.*` 的换成 `petty.use`，每个岗位记一条配置日志（写法照 `290`）；后台岗位权限、个人微调里加了的换成加 `petty.use`，去掉了其中任何一项的换成去掉 `petty.use`（宁少不多，BH5）。
7. 怎么并的逐个部门记在 `petty_merge_log`（只追加）：并入打款、总额、已确认合计、改了哪几张报销单、申用笔数、原来的定额。迁移最后自己核对并入打款的未平 = 并入的总额，对不上整个迁移失败。

## 5. 页面

- 「费用与备用金」多一个页签「备用金申用」：选部门（设了备用金、有打款或有申用的），顶上余额（定额、建议补足）、已占用、可用、待报销四个数，下面是这个部门的申用台账；只有 `petty.use` 的（采购）进「费用与备用金」直接到这一页，页签也只看到这一个。
- 登记报销：「钱从哪来」两项；选了备用金和部门以后，有已提交的申用就列出来、选填。
- 部门备用金还没打款时申用页写「还没有部门备用金」，指到「部门备用金」。

## 6. 一致性核对

- `tests/upgrade-petty-merge.test.ts`：报销单张数、金额、状态升级前后一样；各部门余额 = 原余额 + 并入的总额；归属部门可用 = 原余额 + 零采原剩余可用；占用合计不变；申用一笔不少；`pool` 写不进去；权限、定额、模块开关、单号计数都改了；三项自检都过；回滚脚本跑完再升级结果一样。
- 运行中：账目自检「备用金申用一致」「部门备用金台账与平账一致」。
- 加锁：申用 = 操作编号 → 这个部门申用的咨询锁（在锁里算可用）→ 写申用；登记报销 = 操作编号 → 申用（id 升序）→ 打款 → 采购单（`docs/LOCKING.md` 第 3 节）。

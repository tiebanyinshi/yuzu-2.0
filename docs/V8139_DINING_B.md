# 8.1.39（餐饮 B）：分时段停售、档口按时段、菜单小分类、明细标单价、同组只看餐饮

《餐饮新店新系统功能需求文档》R3、R4、R10、R12 与《门店系统需求梳理》的「单菜品可绑定不同时间段对应的出品端口，无需重复建菜」。总排期见 `docs/V8138.md`；同一版的另一半（餐饮定价、结账）在另一个分支做，迁移号 `310`–`314` 归它，这里用 `315`。

## 1. 数据

迁移 `315_dish_windows.sql`（回滚 `docs/rollback/315_dish_windows.down.sql`），只加列、加表：

- `service_items.sale_windows`（jsonb，可空）：售卖时段 `[{"start": 660, "end": 840}, …]`，门店时区一天里的第几分钟；开始 > 结束是跨零点（22:00–次日 02:00）；含开始、不含结束。空为全天卖，升级后什么都不用改。
- `dish_station_windows(item_id, start_minute, end_minute, station_id)`：档口时段，这一段时间点的菜到这个档口出品；不在任何一段里的照 `service_items.station_id`。
- 菜单小分类不建表：存在餐饮规则（`settings` 的 `dining_rules.outletGroups`，按店的设置），默认就是原来写死的「餐厅：餐饮、酒水；水吧：手作饮料、糖水、调酒」，果吧不细分。每个小分类最多 8 个字（181 迁移的约束）、一处最多 12 个、至少 1 个。

前后端共用的判断在 `src/shared/dining-v8139.ts`（时段）与 `src/shared/dining.ts`（`diningOutletsOf`；`isValidSlot`、`parseSlotKey`、`allDiningSlots`、`slotOrder`、`diningSlotOf` 都多了一个可选的名单参数，不带为默认名单）。服务端在 `src/server/modules/dining-v8139.ts`。

## 2. 规则

**分时段自动沽清（R3）**：菜品编辑里加「售卖时段」（最多 4 段）。不在时段里的菜，所有点单入口都下不了单——手牌点单、前台加项目、桌台点单、平板电子菜单、小程序扫码点餐、房态点单都走 `takeDishLimits`，在那里先核对时段（只读、不加锁），再扣沽清；补录纸质单不走这一步。点单页的菜单（`/api/dining/menu`，10 秒取一次）给设了时段的菜带 `saleWindows` 与 `offSale`：停售的灰掉，写「不在售卖时段 · 11:00–14:00 供应」；前台加项目、房态点单里同样不能选。到点自己停，不用人去设沽清。

**出品档口按时段切换**：菜品编辑里加「档口时段」（最多 4 段，不能互相重叠）。`kitchenStationsOf` 按下单这一刻选档口：落在哪一段就是那一段的档口（那个档口停用了的照菜品自己的档口）。出品单记的是下单时选的档口，以后改时段不动已经下的单。点单页、厨房屏的菜单上写此刻的档口。

**菜单小分类（R4）**：后台「餐饮 → 餐饮规则 → 菜单小分类」里给餐厅、水吧加、删、挪小分类（例如点心、中餐、烧腊）。点单页、菜品表、排序、厨房屏、台账、退菜记录、点菜单、导入都按设的名单（页面从 `/api/dining/outlets` 取）。没设分类的菜照原来的默认规则归；默认要归的小分类名单里没有了，归到那一处的第一个。删掉或改名（= 删旧加新）的小分类还有菜在用——设到这一类的、按默认归进来的，下架的也算，删除了的不算——整笔不存。

**账单明细标注价格（R12）**：点菜单（小票可视化）每一行写「¥38 × 2」再写金额。结账单（打印、网络打印）原来就有「2 × ¥38」（一份的金额就是单价），不改。

**同组账单只看餐饮（R10）**：前台结账核对的明细下面加「只看餐饮」：几张手牌各自的餐饮明细（单价 × 份数）、餐饮小计，与合起来的餐饮合计（`source = 'dining'` 的有效明细）。只读，只给客人报餐饮的钱用，应收照旧。接口 `GET /api/frontdesk/dining-subtotals?visitIds=…`（前台结账或查看在店手牌的权限），不改结账核对的接口。

## 3. 错误码

| 码                    | 状态 | 什么时候                                                                           |
| --------------------- | ---- | ---------------------------------------------------------------------------------- |
| `DISH_NOT_ON_SALE`    | 409  | 点的菜（含套餐的子项）此刻不在售卖时段；提示写菜名与几点到几点卖、「到点自动停售」 |
| `DISH_WINDOW_INVALID` | 422  | 时段的开始与结束一样、时间不对、段数超了、档口时段重叠                             |
| `DINING_GROUP_IN_USE` | 409  | 保存餐饮规则时删掉、改名的小分类还有菜在用；提示写哪一类、几道菜                   |
| `DINING_SLOT_UNKNOWN` | 400  | 菜品编辑、排序、后台批量设分类交的小类不在现在的名单里（后台刚改过）               |

## 4. 没做的

- 平板电子菜单、小程序的菜单上不标「停售」（下单时照样拒绝，提示几点卖）：电子菜单有自己的「供应时段」，两者怎么合并等店主定；小程序线的目录主线不改。
- 前台结账核对的明细（应收那一张表）没加单价；明细的单价在点菜单、结账单上看。

## 5. 用例

- `tests/dining-v8139-shared.test.ts`（秒级）：时段含开始不含结束、跨零点、重叠、写法核对；默认名单与原来一样；按设的名单核对、排序、按默认归。
- `tests/dining-v8139.test.ts`：手牌、桌台点单不在时段整笔拒绝、在时段照常点、审计记了改动；档口时段选档口、改时段不动已下的单、重叠不让存；加小分类后能把菜挪进去、名单外的拒绝、在用的不能删也不能改名、名字规矩；点菜单带单价；只看餐饮按手牌分、不算非餐饮的明细。
- 看过的尺寸：没有在三台设备上逐页看（这一版没有跑浏览器用例），交验收时补。

# 技师榜单（店主 2026-11-24《技师榜单模块需求说明》）

门店在「技师管理」里多一个页签「技师榜单」：按工种看技师照片卡片和实时状态（空闲、未当班、服务中），服务中的看得到做什么项目、做了多久、还剩多久。只做展示与查询：不维护名册（照片在名册里维护）、不排钟派单，钟房不改。

默认做法与待确认的口径记在 `docs/PENDING_DECISIONS.md`「技师榜单」TR1 起；迁移号 `250` 起（`docs/ROADMAP.md` 第 7 节）。

## 2. 数据从哪来

- **名册**（`technicians`）：技师号、姓名（有花名的显示花名）、工种（`kind`，清单是技师管理里维护的工种字典 `technician_kinds`）、照片（本次加的 `photo_id`）。在职（`active`）的都列；停用（离职）的不列，除非手上还有没结束的钟。
- **钟房**：与钟房、上钟轮播同一份数据（`clockroomBoard`），只读、不加锁、不写。客人姓名、手牌、房间不给榜单（榜单可能放在接待台给客人看）。
- **状态由服务端按钟房算好**再给页面，页面不自己推算（TR2）：

| 榜单状态         | 钟房里是                                                                      |
| ---------------- | ----------------------------------------------------------------------------- |
| 服务中 `serving` | 有在钟上的钟单（上钟中），或已派了钟还没上（`phase` = `waiting`，没有倒计时） |
| 空闲 `idle`      | 上了牌（在岗或休息）、手上没有钟单；休息的另标「休息」                        |
| 未当班 `off`     | 没上牌、休假、停牌                                                            |

- **剩余时间** = 计划下钟（上钟时刻 + 钟单时长，含加钟）− 现在。接口给 `startedAt`、`minutes`、`plannedEnd` 与服务器时间，页面按与服务器的时差每秒倒计时；到点没下钟的显示「待下钟」，钟房下钟后下一次取数变空闲。
- **人气值**（TR3）：近 30 天已下钟的钟单里按点钟记的钟数（按钟单挂的账单明细算，轮钟上「加钟算点钟」加的那几钟也算）；还没有点钟记录的为 0，人气榜按人气值从高到低、同分按综合榜的先后。

## 3. 接口

- `GET /api/technician-ranking`：「维护技师名册」「钟房」「技师上钟轮播」任一项权限都能看（与技师管理、上钟轮播同一批人）。返回服务器时间、营业日、刷新间隔与每页张数、工种清单、技师卡片（按综合榜排好）、各状态人数。
- `PUT /api/admin/technicians/:id/photo`：换照片（`{ mime, data, version }`，浏览器先压缩，1 MB 以内，JPEG / PNG / WebP 按文件头认）；`{ remove: true, version }` 去掉照片。要「维护技师名册」，记审计「保存技师」。按版本号写（`technicians.photo_version`，每改一次加 1）：版本对不上说明别人刚改过，拒绝 `PHOTO_CHANGED`；没收到结果的原样重提（现在的版本正好大 1、照片就是这次要的）原样返回，不会把别人后来的修改改回去。
- `GET /api/technician-photos/:id`：取照片（内容不变，浏览器长期缓存），看榜单的权限就能取。

## 4. 不做的

技师资料的新增、编辑、删除照旧在名册里做（本次只在编辑框里多一个照片）；不做排钟、派单、改单；不改系统主题色；不涉及 OA 考勤与审批；不改价目表。

## 5. 各批交付与验收要点

### 第一批（数据接口与模型）

- 迁移 `250_technician_ranking.sql`（回滚 `docs/rollback/250_technician_ranking.down.sql`）：`technician_photos`（`store_id` + 内容摘要唯一、只追加触发器）、`technicians.photo_id` 与照片版本号 `technicians.photo_version`。
- 服务端 `src/server/modules/technician-ranking.ts`，共用类型 `src/shared/technician-ranking.ts`；照片按文件头认格式沿用电子菜单的 `sniffImage`。
- 用例 `tests/technician-ranking.test.ts`：七位合成技师覆盖空闲、休息、在钟上、已派待上、没上牌、停牌、离职；逐个对钟房 `/api/clockroom` 的状态；把上钟时刻往前挪核对已服务与剩余秒数、到点剩余为 0；人气值的 30 天边界、轮钟与没下钟的不算；工种字典的顺序与字典删掉的工种；权限与照片（去重、换、去掉、格式、审计、只追加、取图缓存）。
- 验收：用独立演示库，钟房里让几位技师上牌、派钟、上钟、休息，`GET /api/technician-ranking` 的 `status` / `note` 与钟房一致；服务中的 `service.remainingSeconds` ≈ 计划下钟 − 现在；返回里没有客人姓名、手牌与房间。

### 第二批（榜单页面）

- 技师管理第五个页签「技师榜单」（`src/client/features/technicians/RankingTab.tsx`，路由 `/technicians/ranking`）；只有「技师上钟轮播」权限的进技师管理只看到榜单（导航「技师管理」也对他们显示）。
- 名册的编辑框（门店「技师管理 → 名册」）多一栏「照片」：选了马上上传（浏览器先压缩），「去掉」马上生效，不跟着「保存」走；带着名册给的照片版本号提交。后台「技师 → 名册」的编辑框不显示照片。
- 状态标签：空闲苔绿、服务中湖蓝、未当班灰（房态的四色只给房态用，`tests/room-colors.test.ts`）。
- 用例 `e2e/technician-ranking.spec.ts` 第一个：工种、翻页、状态、搜索、综合 / 人气榜切换、占位头像、名册里上传与去掉照片。

### 第三批（实时刷新与排序）

- 刷新：`useLivePoll` 按「后台 → 技师 → 技师规则 → 技师榜单刷新间隔」（`rankingRefreshSeconds`，10–300 秒，默认 30）再取；后台不取、断网不取、回到页面与网络恢复时马上取。
- 服务中的卡片：项目、已服务分钟、进度条与「剩 mm:ss」每秒走（按取数时与服务器的时差，不靠取数）；到点没下钟的写「待下钟」、进度条变橙；钟房下钟后下一次取数变空闲。已派待上的写「已派钟，还没上钟」。
- 人气榜：按人气值从高到低、同分按综合榜先后；名次在工种之内算（筛状态、搜人不改名次）；前三名皇冠 / 银牌 / 铜牌，人气值为 0 的不给（TR8）。
- 用例：`tests/technician-ranking-view.test.ts`（排序、前三名、倒计时与进度、筛选与分页，不要数据库）；`tests/technician-ranking.test.ts` 加刷新间隔的设置；`e2e/technician-ranking.spec.ts` 第二个（榜单接口换成模拟数据、浏览器假时钟：倒计时、待下钟、按间隔刷新后变空闲、人气榜排序与前三名）。

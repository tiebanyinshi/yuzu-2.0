执行方式（需求文档第二节）：

- 先在本地开发分支上做，再合到本地 main；全部做完之前不推远端、不动远端分支。
- 分四个批次做。每批做完先自测，过了才开始下一批。

- 开发与验收一律用本地演示库（`yuzu_futian_demo`）和合成数据，不连门店正式库。

迁移号 `470`–`479`（`docs/ROADMAP.md` 第 7 节）。不改版本号。

## 2. 批次 1

- **CY-02 已点菜品**：点单页右侧的「已点菜品」改成列出这位客人（这桌）点过的每一道菜，写明名称、份数和状态（未上 / 制作中 / 已出 / 已上 / 已退），数据就是点菜单。
  - 原来只列进了厨房、还没上的菜，所以水吧、果吧的饮品和已经上了的菜都看不到。
  - 下单成功后跟点菜单一起刷新（`src/client/features/dining/OrderedDishes.tsx`）。
- **CY-03 侧边栏**：右侧栏改成自己滚动（不超过一屏高），「下单」那一栏贴在底部，一直在屏幕里。
- **FT-01**：去掉房态中心的右侧详情栏。点房间卡片直接弹出「详情与动作」；原来详情栏里的「点单」挪进了这个对话框。
- **FT-05**：区域页签（筛选类别）挪到统计卡（房态选项）上面。
- **FT-08 右键设房态**：
  - 房间卡片上点右键，按当前状态给出可以设的房态：标为待清、清洁完成、恢复、维修。
  - 待清、清洁完成、恢复点了马上生效；维修要另填原因和预计完成时间。
  - 走的是原来带操作编号的房间动作，所以房间历史和审计都有记录。

## 3. 批次 2

### 3.1 后台参数（第五节）

后台「空间台账 → 房态中心房型」下面新加「房态中心规则」卡片，存在 `settings` 表的 `room_center_rules` 一行（按店分开）。

| 参数           | 默认    | 说明                                                                           |
| -------------- | ------- | ------------------------------------------------------------------------------ |
| 换技师时限     | 15 分钟 | 上钟后多少分钟内能在房态中心换技师；0 = 不让换                                 |
| 撤房免费时限   | 15 分钟 | 开房（登记）后多少分钟内能撤房；0 = 不让撤                                     |
| 下钟后免房费   | 15 分钟 | 最后一位技师下钟后多少分钟内不收房费                                           |
| 房间按时间计费 | 不开    | 按业态设：计费项目（价格 = 每小时）、起步、计费单位（15 / 30 / 60 分钟）、封顶 |

- 改设置要「系统设置」权限；能看设置的是「系统设置」或「价目维护」。
- 房态中心的看板会带上这三个时限，按钮上写还剩几分钟。

### 3.2 需求与做法

- **FT-02 项目编号**：
  - 后台消费项目可以设编号：字母、数字或「-」，最多 12 个字符，保存时转大写。
  - 编号不能和别的在用项目重复（`ITEM_CODE_TAKEN`）；对接了全品类价目表的项目，编号以价目表为准。
  - 房态中心选项目（登记、加钟、补单）时，输入框里填的正好是某个项目的编号就直接选中；回车也会选中唯一的那条搜索结果。
  - 选项目的面板一打开只显示搜索框和分类页签，点了「全部」或某一类才平铺项目。已经选过项目的照旧平铺。
- **FT-06 换技师**：
  - 房间详情的钟单上有「换技师」按钮：待上钟的一直能换；在钟上的在时限内能换，按钮上写还剩几分钟。
  - 做法就是钟房的「转钟」（同一个函数、同一个操作编号类型）：原明细作废，新技师挂同项目、同价格的明细，并建新钟单。业绩和时间以系统记录为准。
  - 超过时限的由服务端拒绝（`SWAP_TOO_LATE`）。钟房原来的「转钟」不受这个时限限制。
- **FT-07 括单**：
  - 登记时选「点钟」才能勾「括单」，表示技师自己带来的客人。
  - 登记单记 `kind = 'bracket'`，房间卡片和详情上标「括单」。
  - 业绩照点钟算在这位技师名下（用例核对技师报表：点钟数 +1，金额 +198 元）。
- **FT-09 撤房**：
  - 开房后在时限内可以撤，要写原因。撤房不收费。
  - 这间房里每位登记了的客人，这次登记的明细全部作废（账单减回去），钟单按取消派钟或退钟收尾，技师按规则回到原位。
  - 登记单记「撤房」，房间直接回到空闲（不转待清），房间历史有「撤房」，审计记 `room_center_revoke`。
  - 不能撤的情况：
    - 超过时限：`REVOKE_TOO_LATE`。
    - 已经有钟下钟了：`REVOKE_DONE`，请走退房。
    - 时限设成 0：`REVOKE_OFF`。
- **FT-10 + FT-17 ④ 房费**：
  - 房费从最后一位技师下钟、再过免费时长之后开始算，算到退房那一刻。
  - 计费规则：
    - 不足起步按起步收。
    - 之后每个计费单位收一次，不足一个单位按一个单位。
    - 单价 = 项目的每小时价 × 单位 ÷ 60。
    - 超过封顶按封顶收。
  - 退房预览里会写会收多少。退房时房费记到先登记的那位客人的手牌上（明细来源 `room`），房间历史有「房费」。
  - 房费也算没结的账，所以要勾「客人带着手牌继续在店」才能退房。
  - 还有钟没下的，不算房费。
- **FT-11 同类型换房**：
  - 换房只能换到同一个房态中心房型；没归房型的，按同一种业态算。
  - 页面上只列同类型的空闲房间，服务端再核对一遍（`MOVE_OTHER_TYPE`）。
- **FT-19 补单**：
  - 房间详情里有「补单」：手牌、项目、技师、实际开始时间、出单员，手工单号选填。
  - 跟前台「补录纸质单」是同一条路：
    - 要「按实际时间补录纸质单」权限（值班经理及以上），只能补 48 小时以内的。
    - 按实际时间挂账，钟单直接记为已下钟，不动技师排位。
  - 钟单记在这间房里，但不算用过房间（`room_neutral`），房间不占用、不转待清。
  - 另记一张「补单」登记单（`kind = 'backfill'`，一建就结束），关联房间和时间。房间历史有「补单」（含手工单号），审计记 `room_center_backfill`。
  - 业绩照常计入技师（用例核对技师报表）。
  - 补单只给还在店的客人补；已经离店的请到收银台反结账后再补。
- **CY-01 同组汇总**：
  - 点单页「已点菜品」上有「同组汇总」按钮，一屏列出同组每位客人点过的菜（退掉的不算），写明单价、份数和金额，最后是全组合计。
  - 没有同组的只列这一位客人。
  - 接口是 `GET /api/dining/group?visit=`，与点菜单同一批岗位能看。

### 3.4 锁的顺序

- 撤房：
  1. 房态行（`runRoomOp`）
  2. 来访
  3. 账单
  4. 明细
  5. 技师队列
  6. 钟单
  7. 登记单

  其中第 2–6 步跟钟房退钟的顺序一样。

- 退房带房费：
  1. 房态行
  2. 房费客人的来访与账单（在锁登记单之前）
  3. 登记单
  4. 插入房费明细
- 换技师：用钟房转钟原来的顺序。
- 补单：用前台挂账原来的顺序；之后改钟单的房间、插入登记单。

## 4. 待店主确认的取舍（写进 PR 说明的「遗留问题与建议」）

1. **FT-10 房费的起算点**：现在按「下钟 + 免费时长」之后才开始计费；超过免费时长时，免费的那一段不补收。
2. **房费只在房态中心退房时收**：如果客人直接在收银台结账离店，登记单自动结束，不收房费。
   - 建议：门店统一先在房态中心退房，或者以后在收银台结账时也算房费。
3. **FT-06 时限只管房态中心的「换技师」**：钟房的「转钟」照旧不限时，给值班经理处理特殊情况。
4. **FT-07 括单必须是点钟**：业绩照点钟算，提成规则不另加。
5. **FT-19 补单要值班经理及以上**：只补在店客人、48 小时以内的单，跟前台补录纸质单的规则一致。
6. **FT-11**：没归房型的空间按「同一种业态」算同类型。

执行方式（需求文档第二节）：

## 2. 批次 1

- **CY-02 已点菜品**：点单页右侧的「已点菜品」改成列出这位客人（这桌）点过的每一道菜，写明名称、份数和状态（未上 / 制作中 / 已出 / 已上 / 已退），数据就是点菜单。
  - 原来只列进了厨房、还没上的菜，所以水吧、果吧的饮品和已经上了的菜都看不到。
  - 下单成功后跟点菜单一起刷新（`src/client/features/dining/OrderedDishes.tsx`）。
- **CY-03 侧边栏**：右侧栏改成自己滚动（不超过一屏高），「下单」那一栏贴在底部，一直在屏幕里。
- **FT-01**：去掉房态中心的右侧详情栏。点房间卡片直接弹出「详情与动作」；原来详情栏里的「点单」挪进了这个对话框。
- **FT-05**：区域页签（筛选类别）挪到统计卡（房态选项）上面。
- **FT-08 右键设房态**：
  - 房间卡片上点右键，按当前状态给出可以设的房态：标为待清、清洁完成、恢复、维修。
  - 待清、清洁完成、恢复点了马上生效；维修要另填原因和预计完成时间。
  - 走的是原来带操作编号的房间动作，所以房间历史和审计都有记录。

## 3. 批次 2

### 3.1 后台参数（第五节）

后台「空间台账 → 房态中心房型」下面新加「房态中心规则」卡片，存在 `settings` 表的 `room_center_rules` 一行（按店分开）。

| 参数           | 默认    | 说明                                                                           |
| -------------- | ------- | ------------------------------------------------------------------------------ |
| 换技师时限     | 15 分钟 | 上钟后多少分钟内能在房态中心换技师；0 = 不让换                                 |
| 撤房免费时限   | 15 分钟 | 开房（登记）后多少分钟内能撤房；0 = 不让撤                                     |
| 下钟后免房费   | 15 分钟 | 最后一位技师下钟后多少分钟内不收房费                                           |
| 房间按时间计费 | 不开    | 按业态设：计费项目（价格 = 每小时）、起步、计费单位（15 / 30 / 60 分钟）、封顶 |

- 改设置要「系统设置」权限；能看设置的是「系统设置」或「价目维护」。
- 房态中心的看板会带上这三个时限，按钮上写还剩几分钟。

### 3.2 需求与做法

- **FT-02 项目编号**：
  - 后台消费项目可以设编号：字母、数字或「-」，最多 12 个字符，保存时转大写。
  - 编号不能和别的在用项目重复（`ITEM_CODE_TAKEN`）；对接了全品类价目表的项目，编号以价目表为准。
  - 房态中心选项目（登记、加钟、补单）时，输入框里填的正好是某个项目的编号就直接选中；回车也会选中唯一的那条搜索结果。
  - 选项目的面板一打开只显示搜索框和分类页签，点了「全部」或某一类才平铺项目。已经选过项目的照旧平铺。
- **FT-06 换技师**：
  - 房间详情的钟单上有「换技师」按钮：待上钟的一直能换；在钟上的在时限内能换，按钮上写还剩几分钟。
  - 做法就是钟房的「转钟」（同一个函数、同一个操作编号类型）：原明细作废，新技师挂同项目、同价格的明细，并建新钟单。业绩和时间以系统记录为准。
  - 超过时限的由服务端拒绝（`SWAP_TOO_LATE`）。钟房原来的「转钟」不受这个时限限制。
- **FT-07 括单**：
  - 登记时选「点钟」才能勾「括单」，表示技师自己带来的客人。
  - 登记单记 `kind = 'bracket'`，房间卡片和详情上标「括单」。
  - 业绩照点钟算在这位技师名下（用例核对技师报表：点钟数 +1，金额 +198 元）。
- **FT-09 撤房**：
  - 开房后在时限内可以撤，要写原因。撤房不收费。
  - 这间房里每位登记了的客人，这次登记的明细全部作废（账单减回去），钟单按取消派钟或退钟收尾，技师按规则回到原位。
  - 登记单记「撤房」，房间直接回到空闲（不转待清），房间历史有「撤房」，审计记 `room_center_revoke`。
  - 不能撤的情况：
    - 超过时限：`REVOKE_TOO_LATE`。
    - 已经有钟下钟了：`REVOKE_DONE`，请走退房。
    - 时限设成 0：`REVOKE_OFF`。
- **FT-10 + FT-17 ④ 房费**：
  - 房费从最后一位技师下钟、再过免费时长之后开始算，算到退房那一刻。
  - 计费规则：
    - 不足起步按起步收。
    - 之后每个计费单位收一次，不足一个单位按一个单位。
    - 单价 = 项目的每小时价 × 单位 ÷ 60。
    - 超过封顶按封顶收。
  - 退房预览里会写会收多少。退房时房费记到先登记的那位客人的手牌上（明细来源 `room`），房间历史有「房费」。
  - 房费也算没结的账，所以要勾「客人带着手牌继续在店」才能退房。
  - 还有钟没下的，不算房费。
- **FT-11 同类型换房**：
  - 换房只能换到同一个房态中心房型；没归房型的，按同一种业态算。
  - 页面上只列同类型的空闲房间，服务端再核对一遍（`MOVE_OTHER_TYPE`）。
- **FT-19 补单**：
  - 房间详情里有「补单」：手牌、项目、技师、实际开始时间、出单员，手工单号选填。
  - 跟前台「补录纸质单」是同一条路：
    - 要「按实际时间补录纸质单」权限（值班经理及以上），只能补 48 小时以内的。
    - 按实际时间挂账，钟单直接记为已下钟，不动技师排位。
  - 钟单记在这间房里，但不算用过房间（`room_neutral`），房间不占用、不转待清。
  - 另记一张「补单」登记单（`kind = 'backfill'`，一建就结束），关联房间和时间。房间历史有「补单」（含手工单号），审计记 `room_center_backfill`。
  - 业绩照常计入技师（用例核对技师报表）。
  - 补单只给还在店的客人补；已经离店的请到收银台反结账后再补。
- **CY-01 同组汇总**：
  - 点单页「已点菜品」上有「同组汇总」按钮，一屏列出同组每位客人点过的菜（退掉的不算），写明单价、份数和金额，最后是全组合计。
  - 没有同组的只列这一位客人。
  - 接口是 `GET /api/dining/group?visit=`，与点菜单同一批岗位能看。

### 3.4 锁的顺序

- 撤房：
  1. 房态行（`runRoomOp`）
  2. 来访
  3. 账单
  4. 明细
  5. 技师队列
  6. 钟单
  7. 登记单

  其中第 2–6 步跟钟房退钟的顺序一样。

- 退房带房费：
  1. 房态行
  2. 房费客人的来访与账单（在锁登记单之前）
  3. 登记单
  4. 插入房费明细
- 换技师：用钟房转钟原来的顺序。
- 补单：用前台挂账原来的顺序；之后改钟单的房间、插入登记单。

## 3A. 批次 3

- **FT-03 留宿确认单**：过夜客人开房不要求传照片。房间详情里客人那一栏写「留宿确认单：已上传 N 张 / 待补传」，点「拍照上传」：
  - 照片在浏览器里压成 JPEG，经通用附件（`/api/oa/attachments`）传上去，再挂到这位客人的登记单上（`POST /api/room-center/rooms/:id/overnight-photo`，附件 `ref_type = 'room_overnight'`）。
  - 开房 72 小时内都能补传（退了房也行），一位客人最多 6 张；登记时没选过夜的拒绝（`NOT_OVERNIGHT`）。同一张重提照样成功、不重复。
  - 能看照片的：能看房态中心客人的岗位（康美部的账户除外）。审计记 `room_center_overnight_photo`。没有迁移。
- **FT-04 待清房标留宿**：待清的房间，上次清洁完成以后结束的登记单里有过夜的，卡片上标「留宿」、详情里写「上次的客人留宿」；清洁完成以后不再标。撤房、补单、撤销来访的登记不算。
- **FT-12 休息大厅床位下钟即空**：休息大厅一类的业态（`isLobbyBusinessType`），登记了的客人钟都结束了就不再占床位，床位也不因为做过钟转待清（手动标的才待清）。
  - 那张登记单在客人另登记一间时自动按退房收尾（锁那一行，不动床位的房态行），或客人结账时照常结束。
  - 现在休息大厅还不能直接登记、派钟（批次 4 的 FT-16 打开），所以浏览器与用例的核对放在批次 4。
- **FT-13 康美部只看房态与手牌号**：岗位是康美部的、或带「康美部」职责的账户（店主、店总除外）：
  - 房态中心看板的卡片只给房态与客人的手牌号：项目、技师、钟、金额、客人姓名、出单员、备注、预约、点单的单数与金额都不给（看板带 `statusOnly: true`）。
  - 房间详情只列手牌号（在用的房间照旧能点水吧、果吧）；房间历史、结账预览、按手牌查客人都拒绝（403）。
  - 原来康美部卡片上能看到房内点单的单数与金额（回测整改 P07），按 FT-13 不再给；康美部自己的点单记录（撤单要用）照旧能看。

## 3B. 批次 4

迁移 `471`：休息大厅分区 `hall_zones` 与空间上的 `hall_zone_id`、虫洞使用单 `wormhole_stays`、四种新的房间事件。回滚 `docs/rollback/471_hall_wormhole.down.sql`。

- **FT-14 一个工位多个项目**：在用房间的详情里有「加项目」。这间房里已登记的客人同时再做一个项目，要另一位技师（同一位技师接着做用钟单上的「加钟」）。
  - 挂账、派钟与登记走同一条路，另建一张钟单，记在这间房里。
  - 两张钟单同时进行、分别下钟，各自计费、各自算业绩（用例核对：两位技师的报表金额各 +198 元）。
- **FT-15 休息大厅分区**：后台「空间台账 → 房态中心房型」下面有「休息大厅分区与床位」：
  - 分区可以加、删（停用；停用分区里的床位挪出来）、不重名。
  - 床位逐张选分区后一起保存。
  - 加床位用房型卡片上原来的「设数量」。
  - 卡片和详情上写分区名，大厅开单选床位时按分区分组列出。
- **FT-16 大厅开单**：房态中心顶上有「大厅开单」，一行一张床位：
  - 每行填床位、手牌、项目、技师等级与价格、技师性别、技师号（不填技师号按轮钟，前面几行选过的技师跳过）。
  - 「全部提交」逐行提交、各自成单，每行有自己的操作编号和「结果待确认」；没成的那一行写明原因。
  - 每一行就是一次房态中心登记：休息大厅一类的床位从这一批起能登记、能派钟（`lockServiceSpace` 放行）。
- **FT-12 补充**：大厅床位登记、派钟以后，下钟即空闲（用例与浏览器都核对了）。
- **FT-17 足浴区点餐、零售、杂项**：
  - ① 足浴房在用时，详情里有「点餐」，带着这位客人的手牌和房号进点单页（`/crm/dining?tag=&room=`），餐厅、水吧、果吧都能点，出品单写送到这间房。
  - ②③「零售 / 杂项」：把后台设的几个分类（默认「零售」「杂项」）里的项目挂到房里客人的手牌上。
    - 项目的名称、编号、价格在后台价目里维护，输入编号就能选中。
    - 要技师的项目不能挂；手动金额的杂项要「手动输入金额」权限。
    - 房间历史和审计都有记录。
  - ④ 房间按时间计费见批次 2。
- **FT-18 虫洞**：业态是「虫洞」的空间（后台可以改是哪几种业态）是虫洞位。
  - 下单三步：手牌、性别、虫洞号；费用按后台设的项目挂到手牌上，不设就是不收费。
  - 同一个虫洞、同一位客人同时只能有一张。
  - 点「客人离开」、或者客人结账离店，虫洞就空出来。
  - 状态：维修 > 有人（在用）> 清洁时段里、或手动标了待清（待清）> 空闲。用过以后不会自动转待清，而是按后台设的每天几段清洁时段打扫（跨零点的也行）。
  - 清洁时段里的虫洞不能下单。

## 4. 待店主确认的取舍（写进 PR 说明的「遗留问题与建议」）

1. **FT-10 房费的起算点**：现在按「下钟 + 免费时长」之后才开始计费；超过免费时长时，免费的那一段不补收。
2. **房费只在房态中心退房时收**：如果客人直接在收银台结账离店，登记单自动结束，不收房费。
   - 建议：门店统一先在房态中心退房，或者以后在收银台结账时也算房费。
3. **FT-06 时限只管房态中心的「换技师」**：钟房的「转钟」照旧不限时，给值班经理处理特殊情况。
4. **FT-07 括单必须是点钟**：业绩照点钟算，提成规则不另加。
5. **FT-19 补单要值班经理及以上**：只补在店客人、48 小时以内的单，跟前台补录纸质单的规则一致。
6. **FT-11**：没归房型的空间按「同一种业态」算同类型。
7. **FT-13 与 P07 的取舍**：康美部的账户在房态卡片上不再看到房内点单的单数与金额；他们自己的点单记录照旧能看（撤单要用）。
8. **FT-03 照片补传的时限**：开房 72 小时内；一位客人最多 6 张。
9. **FT-16 大厅开单的「性别」按技师性别理解**：轮钟时只派这个性别的技师。如果指的是客人性别，请店主说明。
10. **FT-17 足浴区点餐**：用的是现有的点单页（带着手牌进去），不是在房态点单里另开餐厅出品口。
11. **FT-18 虫洞的费用**：一次性收，按后台设的项目；按时长计费的要另定。

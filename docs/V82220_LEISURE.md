# 8.2.20 休闲娱乐：网吧、桌球按台位计时、单独收费

需求来源：店主 2026-11-27《新店系统需求现场走场确认》第二节「休闲娱乐」。
同一份文件的锁牌外出在 8.2.7，餐厅在 8.2.8，水吧在 8.2.19，男汤 / 女汤泡池排在下一版。

## 1. 店主的原话怎么落到系统里

| 原话                               | 系统里                                                                                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 休闲娱乐板块：网吧、桌球，独立收费 | 门店导航「房态」下多了「休闲娱乐」页：按业态（网吧、桌球……）列台位；每种娱乐用自己的收银项目（价目表建的，部门「娱乐」），在手牌账单上单独一行，营业额单独算 |
| 价目表一键导入                     | 店主在这一页点「按价目表一键建」：生效中的价目表「娱乐价格」里按时长收费的几行 → 业态、计费、台位一次建好（已有的不重复建）                                  |
| 网吧刷手牌开机计时                 | 页面顶上刷手牌：这张牌没有在用的台位 → 点一台空闲的开始计时（牌号带进去）；有在用的 → 直接弹「结束计时」，按时长挂到手牌上，最后在前台一起结账               |

## 2. 计费：基础价含时长 + 加钟

价目表「娱乐价格」写的是「39/2h，加钟/19.9」（2 小时 ¥39，之后每小时 ¥19.9）。开单即占用原来只有「每小时多少钱」一种算法，这一版加一种：

- 起步时长（基础价含的时长）以内只收基础价；
- 之后每个计费单位（价目表的加钟是每 60 分钟）不足一个按一个，收加钟价；
- 账单上两行：「网吧 NB01 2 小时」¥39，「网吧 NB01 加钟（每 60 分钟）」× 几；都是那种娱乐的收银项目（部门「娱乐」）；
- 价目表没写加钟的，按基础价折算每小时（「49/1h」就是每小时 ¥49），页面上标「按基础价折算」；
- 后台原来的「每小时价」算法不变（派对房、娱乐室照旧）。

结账前要先结束计时（与派对房一样：没结束的结账时拦下，`USAGE_UNCHARGED`）。

## 3. 按价目表一键建

- 列出生效中的价目表「娱乐价格」里**按时长收费**的行（价格写成 39/2h 的；按次的畅玩卷不算）；
- 每一行：业态名 = 价目表名称（最多 8 字）、计费项目 = 切换生效时建的那个收银项目、起步 = 价格里的时长、加钟 = 备注里的加钟价；
- 台位：按「数量」（台数）在选定的楼层建，编码 = 前缀 + 两位序号（网吧 NB01…、桌球 ZQ01…，前缀可改）；已有的编码不重复建，被别的业态占用的跳过并列出来；
- 业态加进「开单即占用」与「休闲娱乐」页；
- 只有「后台设置」权限能建；没对接收银项目（还没切换生效）、起步超过 10 小时的不能建，页面上写原因。

## 4. 数据与锁

迁移 `620`：使用单计费表 `space_usage_charges` 的类型加 `extra`（加钟那一条）。计费规则（`usage_rules`，设置里的 JSON）加 `extraPrice`（加钟价）与 `leisureTypes`（休闲娱乐页上的业态），旧数据没有这两项照旧。

加锁：一键建在一个事务里：规则设置的锁 → 空间台账的锁 → 楼层一行（共享锁），再写台位与规则；开单、结束计时照「开单即占用」原来的顺序。

## 5. 没做的 / 要店主定的

- 网吧电脑真的「开机」（控制电脑开关机、上机软件）要接网吧计费系统，这一版只做刷手牌开始计时（8.2.20-1）；
- 会员的包房房费折扣不打到网吧、桌球（只认派对房房费）（8.2.20-2）；
- 台位都建成容量 1 人、可售；要改名字、楼层、区域在后台「空间台账」里改。

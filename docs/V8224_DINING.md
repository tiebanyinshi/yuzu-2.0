# 8.2.4 餐饮：分组默认档口、临时项目进厨房、包房房型、服务费门店默认、返台、公司承担

来源：会议纪要「餐饮系统需求对接会」（2026-11-26）。迁移 `560_dining_v8224.sql`（号段 `560`–`569`，回滚 `docs/rollback/560_dining_v8224.down.sql`）。旧设计：`docs/V8139.md`（低消、服务费、转挂账）、`docs/V8139_DINING_B.md`（档口时段、菜单小分类）。

下面「拍板」的是开发会话替店主先定的做法，默认值都能在后台改，店主要改的在第 8 节。

## 1. 点心不再跑到中厨

**问题**：点心部下的单落到中厨，要重新开临时项目才能出点心；手工下的临时项目不出厨房单，只能人工通知厨房。

**分组默认档口**：后台「餐饮 → 档口与出品 → 分组默认档口」给点单分类（餐厅 · 点心、水吧 · 糖水……，就是 8.1.39 的菜单小分类）设一个默认档口。存在餐饮规则 `dining_rules.groupStations`（按店的设置），能管理价目的岗位改（`PUT /api/admin/dining/group-stations`，与菜品挂档口同一个权限）；保存餐饮规则不动它。

**出哪个档口**（`kitchenStationsOf`，下单这一刻）：

1. 设了档口时段的（8.1.39）、此刻在时段里：时段的档口；
2. 菜没「单独设档口」（`service_items.station_pinned = false`）、分组设了默认档口、那个档口在用：分组的档口；
3. 其余：菜自己的档口（与原来一样）。

点单页、厨房屏的菜单写的也是这个档口；套餐的子项一样按分组走。分组的默认档口停用了，照菜自己的档口。

**单独设档口**：升级后所有菜都是「跟分组」，但没设任何分组默认档口时什么都不变。之后：

- 菜品编辑、后台批量设档口时，选的档口与分组默认不一样就记成「单独设」，一样（或分组没设默认）就是「跟分组」；
- 核对列表（同一张卡片下面）列出**菜自己的档口与分组默认不一致的菜**：哪一类、菜自己设的、分组默认、现在实际在哪出、有没有档口时段；一键「改成跟分组 / 改成单独设」（`PUT /api/admin/dining/items/pinned`，记审计 `items_station_pinned`）。例如纪要里的虾饼确实在中厨做，点「改成单独设」。

**临时项目选档口**：前台「加项目」的手动项目（`customLines`）每一行可以选档口（下拉列菜单上有菜的档口，默认「不进厨房」）。选了档口的：明细记在「餐饮」、照常建出品单到那个档口（`kitchen_items.item_id` 为空，厨房屏显示账单上的名字），退掉时出品单一起退；不扣沽清、不扣料。不选的与原来一样。要「手动金额」权限；餐饮功能关着、档口停用的整笔拒绝。

## 2. 包房房型：低消、中消、只收房费

**房型**（`dining_room_types`，后台「餐饮 → 桌台 → 包房房型」，能管理价目的岗位改）：名称（小房、中房、大房，可加，一家店最多 20 个）、怎么收：

- **按低消**：低消；可以另设**中消**（第二档低消）与什么时候用中消——**开台时刻在中消时段里**（例如 14:00–17:00，可以跨零点）**或人数不超过 N 人**，两样设一样或都设（满足任一样就用中消）；
- **只收房费**：不设低消，结账时记一行「房费（茶房）」（`bill_lines.charge_kind = 'room_fee'`，不算服务费、不算进低消）。

房型不删，不用了停用（挂着的桌照旧按它算）。

**桌台挂房型**（编辑桌台多一个「包房房型」）：挂了房型的就是包房。这一次开台的低消（`tableRuleOf`，`src/shared/dining-v8224.ts`）：

1. 桌台自己设了低消（> 0）的，按桌台的；
2. 否则按房型：只收房费的没有低消；按低消的，满足中消条件用中消，否则用低消；
3. 都没有为不设。

中消看**开台时刻**（门店时区）与**结账时的人数**。结账核对写「中房 · 中消 ¥500，还差 ¥80」「房费（茶房，只收房费）」。低消不够的照 8.1.39：勾「补足低消」、返台再点（第 4 节），或转挂账。

## 3. 服务费：门店默认

- 餐饮规则多两项（店主改）：**服务费（门店默认）**（默认 0%，新店设 15%）、**用在哪些桌**（默认「只收包房」= 挂了房型的桌；可改成「所有桌台」）；
- 桌台的服务费比例改成三种：空着 = 跟门店默认，填 0 = 这张桌不收，填比例 = 照桌台的。升级时原来的 0 改成空（门店默认初始是 0，结账结果不变）；
- 算法照旧：按这一桌点了、没退、没赠送的菜（不算服务费、低消补足、房费这几行）× 比例，四舍五入到分，结账时记一行「服务费 15%」，反结账再结作废重算。

## 4. 返台

**条件**：只有包房（这一次开台有低消）、而且**低消没够**才能返台；要「返台」权限（`dining.returnTable`，默认值班经理及以上与餐饮主管），写原因（2–200 字），记审计 `table_return` 与返台记录 `table_session_returns`（只追加）。

- **转挂账的单**（8.1.39 的「转挂账」，桌台已空出来）：回到原来的桌台继续点。桌台要空着、可用（待清台、维修的先处理）；返台后去掉挂账标记。
- **已结账的单**（结账时补了低消）：客人还没走才行——桌台还是**待清台**（「客人一走就会清台」，清过台的不能返台）、结账后不超过**返台时限**（餐饮规则，默认 30 分钟）、这张结账单只结了这一桌。返台在**同一个事务里反结账**这张结账单（收的钱照反结账退：现金从钱箱退、储值撤销、券退回……；反结账原因写「返台补低消：…」），结账时自动记的服务费、低消补足、房费作废（下次结账按此刻重算），桌台从待清台回到用餐中。要「返台」与「反结账」两项权限。

**页面**：桌台页「挂账中」每一张有「返台」；点待清台的桌，有权限的多一个「返台补低消」（先查这张桌上一次结了账、补了低消的单，写明会反结账哪张结账单、补了多少）。

**操作编号**：请求带 `clientKey`，记在返台记录上（唯一）。同一编号重提（例如没收到回复再点一次）照第一次的结果返回，不会反结账两次；两次同时到时后到的那次等结账单锁、看到已经反结账，再按编号认出是同一笔。返台页面这一次打开用同一个编号；没有接「结果待确认」的本机记录（第 8 节）。

## 5. 公司承担

**结账方式「公司承担」**（`checkout_payments.method = 'company'`）：账挂到公司的内部账户，**不进协议单位应收**（不建 `ar_charges`，与「挂账」是两回事）。

- 选原因：客人身体不适、招待、其他（选「其他」要写说明；说明最多 64 字），记在 `company_reason` 与 `ref`（「客人身体不适：吃坏肚子」）；
- **当场授权**：用途 `company_charge`，值班经理、店总、店主能授权（权限 `auth.companyCharge`），不能由收银的本人授权（店主除外），绑定这次结账的手牌或桌台、金额、原因与说明，5 分钟一次有效，结账时在同一事务里核销；
- 一张结账单最多一笔，可以和别的方式组合（例如一部分公司承担、其余现金）；手牌结账、桌台结账都能用；反结账时照旧作废（不用另外处理）；
- **口径**：算营业额（应收、净营业额里都有，与挂账一样）、不算实收、不进交班的钱箱；**日结单独列出**：营业口径「按方式」里有「公司承担」一行（写「公司内部账户承担，不进协议单位应收」），「异常与提醒」里每一笔一条（结账单号、金额、原因、经办、授权人）。

## 6. 杂项费用

开瓶费、赔偿费、加工费、清洁费照 8.1.39：在菜品里设成「时价 / 杂项」，点的时候填金额。这一版不改。

| ------ | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| D224-7 | 升级后的菜都是「跟分组」   | 设了分组默认档口以后，这一类里原来挂在别的档口的菜马上跟分组走；要留在原档口的在核对列表里点「改成单独设」                                                                                          |

## 9. 没做的

- 康美系统对接（D224-2）。
- 返台、公司承担的页面没有接「结果待确认」的本机记录：返台靠操作编号认出重提，公司承担走结账原来的待确认；
- 前台自检没有给公司承担单独加一项（授权核对在结账事务里做过；要加的话同时改演示数据的预期清单）；
- 桌台点单（开台的桌）没有临时项目入口：临时项目照旧在前台「加项目」里下。

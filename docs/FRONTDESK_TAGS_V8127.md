# 手牌管理：批量规则、修改删除、暂停 / 维修（店主 2026-11-24）

店主 2026-11-24 的需求「开发手牌管理功能」三条：①批量添加手牌，按规则设数量、起始号码，可设排除规则（如尾数含 4 和 7 跳过），自动生成不重复手牌；②已添加的手牌能修改、删除，删除二次确认，客人占用中不可改删；③手牌柜可标「暂停使用 / 维修中」，后台列表用不同颜色区分，前台发放手牌时不能选中，改回正常就能发。规则与默认值见 `PENDING_DECISIONS.md` PC32。迁移 `260_hand_tag_manage.sql`。不改版本号。

## 1. 做了什么

- **管理 → 手牌 →「批量添加与导入」页签**（原「建牌与导入」）：第一块「按规则批量添加」，填分区、柜型（VIP 柜选等级）、数量、起始号码、数字位数、前缀，两排 0–9 的数字开关设排除规则：
  - **排除尾数**：尾数是这些数字的号跳过（默认勾 4）；
  - **排除含有**：任何一位含这些数字的号都跳过（比尾数更严）。
  - 从起始号码往后数，跳过排除的号和已有的牌号（含删除过的），凑够数量；位数用完了就停，提示加大位数或换前缀。先「预览」列出要添加的号，再「添加这 N 张」；改了任何一项要重新预览。一次最多 500 张。
  - 原来的「按号段建牌」（起止号）由这块代替，接口 `POST /api/frontdesk/tags/batch` 保留（导入、演示数据在用）。
- **手牌池**：暂停使用 = 柚黄、维修中 = 深墨底（带扳手图标），锁定、停用、在店照旧；顶上一行图例；每个分区的统计加「暂停 / 维修」几张。
- **点一张手牌**的对话框加了：
  - **牌号**可改（在店的不能改），重号拒绝；
  - **柜子状态**：正常 / 暂停使用 / 维修中 + 说明（最多 100 字），「保存状态」；在店的不能标暂停或维修（先换牌），恢复正常随时可以；
  - **删除这张手牌**：点了以后要勾「确认删除」才能删；在店的不能删。
- **前台**：暂停、维修的牌在看板上同色显示（卡片写「暂停使用 · 说明」「维修中 · 说明」），点了提示换一张；发牌、换牌输入这个牌号时提示「A006 维修中（锁坏了），请换一张」，补全与候选里不出现；看板「空闲」不算它们，另有一格「暂停 / 维修」几张；按状态筛的「锁定」改为「锁定 / 暂停维修」。
- 服务端兜底：发牌（含同行组加人）、换牌、恢复离店时手牌不是正常状态一律拒绝（`TAG_OUT_OF_SERVICE`，恢复离店为 `TAG_UNAVAILABLE`）。

## 2. 数据（迁移 260，只加列与约束）

| 列                                         | 是什么                                                          |
| ------------------------------------------ | --------------------------------------------------------------- |
| `hand_tags.service_status`                 | 柜子状态：`normal` 正常 / `paused` 暂停使用 / `repair` 维修中   |
| `service_note`、`service_by`、`service_at` | 说明（1–100 字）、谁标的、什么时候标的；恢复正常时清空          |
| `deleted_at`、`deleted_by`                 | 删除标记；约束 `hand_tags_deleted_inactive`：删了的必须是停用的 |

手牌表从 004 迁移起就**禁止物理删除**（触发器 `hand_tags_no_delete`：历史来访、换牌记录引用它），所以删除 = 停用 + 标已删除 + 清掉芯片号。删了的不出现在后台列表、前台看板，批量生成不会再用这个号；按清单导入同一牌号会恢复（清掉删除标记）。

## 3. 接口（权限「手牌管理」`frontdesk.tags`，值班经理及以上）

| 接口                                   | 做什么                                                                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `POST /api/frontdesk/tags/generate`    | 按规则批量添加；`preview: true` 只算不建。在门店的咨询锁里算号，唯一约束兜底（撞了整笔拒绝 `TAG_CODE_TAKEN`，请重新预览） |
| `PUT /api/frontdesk/tags/:id`          | 原有的改分区、柜型、启用，加可选的 `code` 改牌号（在店的拒绝 `TAG_IN_USE`，重号 `TAG_CODE_TAKEN`）                        |
| `POST /api/frontdesk/tags/:id/delete`  | 删除（在店的 `TAG_IN_USE`）；返回 `kept` 表示发过、历史照旧可查                                                           |
| `POST /api/frontdesk/tags/:id/service` | `{ status, note }` 标暂停 / 维修或恢复正常（在店的标暂停、维修拒绝 `TAG_IN_USE`）                                         |

改动都锁这张手牌那一行（`FOR UPDATE`，与锁定 / 解锁同一顺序，`docs/LOCKING.md` 前台一节），写审计 `hand_tag_updated`（摘要写明改了什么）。

## 1. 港元现金（CM-2、CM-3）与大额找零（CM-4）

- **开关与汇率**：后台「手牌与前台 → 收银台」设「每 1 港元折多少人民币」（`frontdesk_rules.hkdRatePpm`，百万分之一，0.5–1.5 之间）；没设 = 不收港元（默认）。
- **收法**：结账时「现金」那一笔切到「港元」，填客人实给的港元。这笔的金额照旧是人民币（应收的一部分），页面显示「这笔折 HK$x」（人民币按汇率向上取到港仙）；实给的港元按汇率向下折成人民币，不能少于这笔，多出来的**找人民币**。
- **记什么**：`checkout_payments` 照旧记一笔 `cash`、人民币金额；另记币种、实给的港元、汇率快照、折成的人民币（= 金额 + 找零）、找的人民币（`fx_*`，约束保证 `fx_worth = amount + fx_change`）。以后改汇率不影响已结的单。
- **核对**：只有现金能带港元；提交的汇率要等于门店此刻的汇率（改过了拒绝 `HKD_RATE_CHANGED`，页面重新核对）；折成的人民币不够拒绝 `HKD_SHORT`。
- **营业额、日结、对账包、看板**：都按人民币（金额本来就是人民币），不用改。
- **交班**：港元进钱箱、找零从人民币出，所以结账现金里这几笔折成的人民币（收款 + 找零）从应有现金扣掉（`cash.hkd`），另列应有港元（= 实给的港元合计）。收过港元的班次交班时要填实点港元，带上看到的应有港元（交班期间又收了港元拒绝 `SHIFT_CHANGED`），记进 `shifts.expected_hkd`、`counted_hkd`；交班表与打印的交班表都列出来。
- **退款、反结账**：港元收的按人民币退（退款单、反结账退的是这笔的人民币金额，从钱箱的人民币出）。
- **大额找零**（页面）：现金填了客人实给、找零超过门槛（后台改，默认 ¥500）或超过这笔的 2 倍时，要勾「已核对找零」才能提交（防止 100 输成 1000）。港元的找零同样算。

## 2. 收银申请（CM-5、CM-6）

没有「开退款单」「反结账」权限的收银员不再办不了：

- **提交**：结账记录里「申请部分退款」（同一个退款区，填项目、份数、金额、方式与原因，不选钱箱）或「申请反结账」（写原因）。写一行 `cashier_requests`（只追加），操作编号幂等（`cashier_request`，「结果待确认」照旧）。推站内通知给这家店有对应权限的人（`approval_todo`）。
- **一张结账单一张**：同一张结账单同时只能有一张待审批（唯一索引）；有待审批的申请时，有权限的人也不能直接开退款单、反结账（`REQUEST_PENDING`），要先批准或驳回。
- **批准**：在「收银申请」页（`/crm/cashier-requests`，通知点进来）点「批准」，**走原来的开退款单 / 反结账**（同一个函数、同一套核对与加锁顺序），在同一个事务的最后锁住申请一行、记批准；退款单的操作编号由批准人的页面给，回复丢了重提返回同一张退款单。现金从批准人当班的钱箱退（批准人要开班）。不能批自己的。
- **单子变了**：批准时按此刻的数据核对，已反结账、已退过、项目或方式超额的（`STALE_CODES`）把申请记「已失效」、写明原因并通知申请人；批准人这边的问题（没开班、超过时限）申请留着。
- **驳回**要写原因，通知申请人（`approval_result`）；申请人可以撤回自己的。
- **超时**：24 小时没人处理，每分钟的扫描记「已失效」并通知申请人。
- 为什么不接审批中心（`modules/approvals`）：那套的审批级次、岗位组按 ERP 的权限算，收银的批准就是「有开退款单 / 反结账权限的人」，单独一张表更直、执行时直接复用原来的函数。

## 3. 交班盲点与交接清单（CM-9）

- **盲点**：后台开「交班盲点」（`shiftBlind`，默认关）。开了以后交班页先只填实点（与实点港元），点「提交实点」锁定，之后才显示应有现金、差额与交班汇总，再确认交班。接口照旧（服务端照旧核对应有现金），只是页面先不给看。
- **交给下一班**：交班页列出本人提交、没人批的申请，等本人审批的申请数，没读的通知数，此刻在店没结的手牌数。只是提醒，不拦交班。

## 4. 餐饮补全（CM-16 到 CM-21，迁移 `761`）

- **等叫、加急、打包（CM-16）**：点单页「还没上的菜」与桌台明细里，一道或整单（「整单等叫 / 起菜」）标记（`POST /api/dining/items/flags`，按 id 升序锁住这几道）。等叫只能标在还没开始做的；等叫着厨房屏的「开始做」「出餐」点不了（服务端拒绝 `DISH_HELD`），服务员点「起菜」以后照常。加急、打包只是标记，厨房屏、明细上带出来，不动金额。记审计。下单当时还不能直接标，下完马上在「还没上的菜」里标。
- **沽清一键恢复（CM-17）**：沽清页「全部恢复」把今天的沽清、限量一起取消（与下单扣沽清同一个顺序先锁再删），记审计。柚子的沽清本来按营业日记、换了营业日自动不算，这一点照旧（原型「第二天不自动恢复」不采用，免得改了门店已经习惯的用法）。
- **待催（CM-18）**：桌台看板带最早一道下了单、还没出餐的菜的下单时刻（等叫的不算），超过餐饮规则里的「多少分钟没出餐标红」在格子上标「待催 N 分钟」。用柚子已有的这一个分钟数，不另设餐厅 / 奶茶两个（原型的 20 / 10 分钟可以按店改这一个数）。
- **分次上菜（CM-19）**：出餐以后一行几份可以先上 1 份（`served_qty`），上齐了才算已上菜；撤回先撤上的份数。退菜照原来的权限与留痕。
- **吧台杯型、温度、糖度、小料（CM-20）**：不做。8.1.17 的做法分组（一组只能选一个、能设必选、能加价，`docs/DISHES_V8117.md` 第 2 节）与加料已经能做：杯型、温度、糖度设成必选的组，小料设成加料。8.2.19 水吧（首杯免费、取餐号）照旧。
- **杯贴（CM-21）**：厨房屏上水吧的出品单多「杯贴」，打开打印页（`/print/cup-labels/<出品单号>`），一单的饮品一杯一张：取餐号（8.2.19 的，有的话）、品名、做法与备注、第几杯、手牌或桌号、时刻。浏览器打印，贴纸打印机当普通打印机用；要接专门的标签机指令以后再说（真机确认）。

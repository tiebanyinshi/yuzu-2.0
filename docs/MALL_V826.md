## 2. 分批发配与物料发配记录（第 5、6 章）

- 发配记录：每一次给到部门的数量与那张部门领料单。核库领用是第一次（`stock`），到货以后补发是后面几次（`arrival`）。已发配量 = 记录合计（领料单作废的不算）。升级时把核库已开的领料单抄一份进来。
- 行状态：待发配、部分发配、待到货（关联采购单在途）、可发配（总仓分到了可发量）、已完成、已终止。**部分发配算未完成**。
- 可发量按先申请先给：同一物料几张单在等，总仓的库存按提交时间依次分。
- 「补发物料」：库管在未完成的行上点，开部门领料单（与核库领用同一个函数），发齐了通知提单人。
- 范围：从升级到 8.2.6 那一刻起提交的单，加上已经有发配记录的行；更早的单照原来手工开领料单，免得一升级记录里堆满旧单。
- 入口与权限：库存 →「物料发配记录」，看要库存查看 / 库存经办 / 核库任一；补发要库存经办或核库。ERP 库存的角标数加「可发配」。

## 3. 退回补资料（第 4 章）

- **退回逐项标必补**：ERP 审核退回商城来的单时，要至少标一项「本次必补」（哪一行、哪一项、要补什么），不能只写一句整体意见（`FIX_ITEMS_REQUIRED`）。可标的项在 `src/shared/mall-fix.ts`：行上的名称、数量、单位、规格 / 说明、品牌型号、参考链接、申请理由、参考图片、尺寸、材质、允许误差、颜色 / 表面、工艺要求、图纸、设计版本；整张单的期望到货、收货地点、预算项目、经办人、备注。退回时记下原来填的（补资料页灰字回显）。
- **仅补必补项**（默认）：只有这一轮标的项能改，其余锁定（改了 `FIELD_LOCKED`）；每一项都要补上、不能原样（漏了点名 `FIX_ITEM_MISSING`）；说明可以不写，按补的项自动写。
- **重新填写**：业务字段都能改（原来的做法），要写一句补了什么；这一轮的必补项一并记为已处理。
- 两种都不换单号、不改部门；每次提交存一版快照（`purchase_request_versions`：首次提交 V1，之后每次重提加一版；升级前已提交的单第一次补资料时先补记原版本）。可以多轮退回，每轮各自记原因、必补项与补的内容。
- **Q4**：退回前主管已经确认过的不再确认（回到退回前的节点，不重头审批）；接单的 BP 不变；核库照常。主管退回的（还没确认）照第一次提交重新算。
- 商城详情：退回补资料记录（各轮、原值、补的内容）、提交版本（点开只读看当时的整张单）。

## 4. 终止该申购（4.6、Q5）

- 待审核、退回补资料中的商城单可以终止。提单人点是「申请终止」，等部门负责人（主管）或供应链 BP 确认，期间单子照常；负责人、BP、店主点是直接终止。驳回的写说明给提单人，可以再申请。
- 终止 = 需求单结束（与撤回同一个状态 `cancelled`，原因写「终止：…」，商城上显示「已终止」），核库收起、草稿关掉，不能再改、再提交；已发配的记录照旧留着。
- 入口：退回补资料提示条、需求单详情。申请、确认、驳回都发站内通知。

## 5. 定制必填、填写示例、草稿（第 3 章、Q1、Q2）

- 定制：尺寸 / 规格要带单位（只有数字和分隔符的拦下）、材质要写、图纸文件或图纸链接至少一项（参考图片算图纸文件）。重新填写时照这个核；只补必补项不逼着补没要求的项。
- 申请部门、期望到货日：原来就必填（部门不选的按账号所在部门），Q2 不用再改。
- 「带入示例」按文档的水吧台展示立牌示例填上，部门照着改。
- 自主申请的草稿自动存在本机浏览器（按账号分开），提交成功清掉。

## 6. 收货待判与拒收原因（第 8 章、Q10、Q11）

- 收货一行：送达 = 合格实收 + **待判 / 待检** + 拒收。待判暂不入库、不算拒收、不用写拒收原因；验完合格的再做一张收货单。待补（供应商要补发的）照旧只能在拒收里记。
- 拒收原因加快捷选项，仍可手改。Q11：拒收本期只记录 + 待补（补货任务 = 还开着的采购单 + 待补数量），不联动退货、扣款、供应商考核。

## 7. 与文档不一样、或这一版没做的（偏差说明）

- **草稿**存在本机浏览器，不进系统：换设备看不到，别人也看不到。
- **图纸文件**只收图片格式（JPEG、PNG、WebP，沿用需求单的图片上传）；PDF、CAD 等请放网盘后填图纸链接。
- **不做库存预留**：可发量按先申请先给实时算，终止时没有要释放的预留（文档的「释放预留」自然满足）。
- **「无单不出库」不全局强制**：发配记录只记从需求单发出去的；库管照旧能直接开领料单。
- **发配记录从升级那一刻起算**（见第 2 节）。
- **到货、发配不强制拍照**；部门电子签收（Q7）沿用「单据即凭证」：领料单本身就是凭证，不另加签收步骤。
- **Q6 拆分**：库存不足时系统给建议（核库领用有的、剩下转采购），由库管 / BP 确认，不自动拆。
- **Q8**：采购缺口进需求池由 BP 接单，不自动生成采购单（原来就是这样）。
- **Q9**：成交方案留痕沿用 8.1.51（方案附件截图 + 确认人、确认时间）。
- **主管退回**（部门主管在确认前退回）不要求标必补项，照旧写原因；这样退回的单只能用「重新填写」补。

# 员工培训（店主 2026-11-25，8.1.36）

店主 2026-11-25：「在系统里加入员工培训模块……后台可以自定义上传我们这些培训文件，还需要可以自定义创建部门，可以方便查看各部分文件」；补充：「管理这些培训文件的话在WCP设置里，显示这些文件的话在WCP模块里」，「每新建一个部门就在员工培训板块下有他们部门的一个文件夹，现有部门每个部门都给他们创建一个文件夹专门放自己部门的文件；除此之外还需要一个公司公共的文件夹，专门放共用的，比如员工手册」，又定名「公共文件这个可以取名为“培训资料”」。店主发来的五份素材（员工手册 PDF 22 页、地毯养护 PDF 10 页、应知应会 Excel 两张表、应知应会与部门认知 PPT 12 页、店内问答 PPT 58 页 28 MB）全部放「培训资料」。

素材是门店的业务资料（价格、柜号、布局），**不进仓库**（代码库是公开的），由店主在后台自己上传；演示数据只放几份占位的小文件。

默认做法与待确认的规则见 `PENDING_DECISIONS.md` PC37。迁移号预留 `280`–`289`（ROADMAP 第 7 节）。

## 1. 参考的开源教育平台（2026-11-25 调研）

| 平台                              | 借鉴的做法                                                             |
| --------------------------------- | ---------------------------------------------------------------------- |
| Moodle                            | 分类树（排序、隐藏）；文件按内容摘要只存一份；按人记「看过」           |
| ILIAS                             | 文件对象带多个版本：换新版本只追加、旧版本留着，不清掉已看记录         |
| Canvas / Open edX                 | 每一项单独定完成条件（看过、标记已读、视频看到多少、考试及格）——第二期 |
| Moodle 群组同步 / Frappe LMS 批次 | 按部门、岗位整体指派，新员工自动带上——第二期                           |
| Moodle / Chamilo 题库             | 题库分类、随机抽题、证书带有效期——第三期                               |

Office 文件在网页里预览，各家都是「上传时用 LibreOffice 转成 PDF」，容易出问题且要装很大的软件，所以第一期不在服务器上转（见第 4 节）。

## 2. 分期

- **第一期（本次）**：文件夹（培训资料 + 每个部门一个，后台可新建部门文件夹、改名、排序、停用）；后台上传、换新版本、改标题与说明、下架；员工在「WCP → 员工培训」按文件夹看，PDF、图片、视频、Excel 在页面里直接看，PPT、Word 下载看；记录谁什么时候看过，后台每份文件看得到看过的人。
- **第二期（店主说了再做）**：指派给部门 / 岗位 / 个人、必读与截止日期、完成记录、按部门看谁没看完。
- **第三期（店主说了再做）**：题库、考试、及格线、证书。

## 3. 入口

- **管理**：「WCP 设置」（WCP 板块的管理端，`docs/BOARDS.md`）「人员与行政」分组里的「员工培训」（`/admin/training`，返回 WCP），权限「员工培训管理」`training.manage`（店主默认有，人力行政部负责人的建议权限里也有）。
- **查看**：WCP 左侧菜单与首页的「员工培训」（`/oa/training`，在「人脸录入」与「通知」之间），登录了的员工都进得去，看得到哪些文件夹见 PC37。

## 4. 数据（迁移 280）

| 表                                        | 是什么                                                                                                                                                                                       |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `training_folders`                        | 文件夹：名称、类别（`public` 培训资料（公共） / `department` 部门）、对应的部门（`org_departments.key`，自己新建的部门文件夹为空）、排序、停用。迁移时建好「培训资料」与现有 15 个部门各一个 |
| `training_blobs` + `training_blob_chunks` | 文件内容：按 SHA-256 只存一份，分成 3 MB 一块存在数据库里（备份、恢复跟着数据库走，不另加存储）                                                                                              |
| `training_files`                          | 一份培训文件：所在文件夹、标题、说明、当前版本、上架 / 下架、排序                                                                                                                            |
| `training_file_versions`                  | 版本：第几版、文件名、类型、大小、内容摘要、上传人与时间、说明。只追加                                                                                                                       |
| `training_uploads`                        | 分块上传的进度（传完由服务端按块算摘要、核对文件头，再登记成文件或新版本；内网 HTTP 下浏览器算不了摘要）；带操作编号，没收到结果时原样重提                                                   |
| `training_views`                          | 谁看过：每人每份文件一行（第一次、最近一次、次数、看的哪一版）                                                                                                                               |

**上传没收到结果**（Codex 审查 `e1d8be3`）：发请求以前先把操作编号（UUIDv7，内嵌时间，7 天有效）、文件名大小与传到哪里（文件夹 / 哪份文件的新版本）存进本机并读回核对，存不了就不传；登记好了才删。刷新、离开页面以后，「WCP 设置 → 员工培训」顶上列出没确认的：「查回」走只读接口（`POST /api/admin/training/uploads/lookup`，不新建上传），没登记的选同一个文件「接着传」，按原来的目标传（换了左边的文件夹也不变）。接着传先核对整份文件的内容指纹（页面算，也算进操作编号的原请求，服务端对不上拒绝），同名、同大小但内容改过的不能接着传。「不传了」先请服务端作废登记（`POST /api/admin/training/uploads/cancel`，锁住那次上传的行，与「完成」互斥；服务端没见过且在有效期内的编号登记一行占住），服务端回了作废、已过期或其实已登记好才删本机记录（Codex 审查 `57dd2f6`）；作废记录 10 天后清掉，清掉时对应的 UUIDv7 早已超过 7 天过期，`startUpload` 永久拒绝重开（Codex 审查 `bfc32cd`）。

**改资料没收到结果**：新建 / 修改文件夹、修改文件信息同样先把原请求存进本机，没收到结果的在顶上列出来「原样重提」：新建带操作编号（`training_folders.client_key`），原样重提返回原来那个；修改时服务端发现现在的内容就是这次要改成的，按改好了算（Codex 审查 `a3f5310`）。上传前先查大小（空文件、超过 200 MB 的不进「没确认的上传」）。

**读内容带版本**：页面里看的地址都带当前版本（`?v=`），分段读（PDF、视频拖动）时管理员换了新版本，员工这边拒绝（`TRAINING_VERSION_CHANGED`）重新打开，不把两个版本的片段拼在一起；记「看过」、Excel 预览也带页面打开的版本，不是当前版本的不记、不读。Excel 在页面里看时限住整份 XML 的结构规模（12 万）、结果按内容缓存、同时最多解析 2 份（每人 1 份）、解压后整份 8 MB、最多 20 张表（多了标「表格太大」）、每格 2000 个字、合并单元格只留不重叠的且总面积不超过显示的格子、整份预览 200 万个字，合并单元格裁到显示的范围里（Codex 审查与安全审查）。

**文件大小与总量**（PC37 待确认，Codex 安全审查 `ec38502` / `bfc32cd`）：一份最多 200 MB；培训文件内容一共最多 20 GB、版本最多 5000 个；每人同时最多 5 个没传完的上传（一共 1 GB）、24 小时内最多开始 100 次上传；24 小时还没传完的每小时清一次（`jobs.ts`）。PDF 一次挂 20 页，往下点「再显示」（页数来自上传的文件）；PDF.js 升级到 `6.5.438` 并设单张内嵌图片上限 1600 万像素、画布内存上限 32 MB，完成上传时也按块流式扫描 PDF 图像字典，单张超 1600 万像素或单边超 16384 拒绝（`TRAINING_PDF_IMAGE_TOO_LARGE`）。读内容（下载、视频分段）全店同时 24 个、每人 4 个，满了排队 20 秒，60 秒没往外写就断开（`lib/stream-slots.ts`）。视频建议先压成 720p 的 MP4。

**在页面里怎么看**：

- PDF：用已有的 pdf.js 一页页画出来，手机上也能看；
- 图片：直接显示；视频：页面里播放（支持拖动进度）；
- Excel：在页面里按工作表显示成表格；
- PPT、Word：第一期下载后用手机 / 电脑自带的软件看；想在页面里直接看，可以在后台同一份文件旁再传一份「另存为 PDF」的版本。服务器上自动转 PDF 要在镜像里装 LibreOffice（约 400 MB），等店主定了再加。

## 5. 接口

员工查看的接口（`/api/training/*`）只给在职员工：平板（电子菜单）、他店、设计师等专用账号、系统账号、已离职的一律 403（Codex 安全审查 b638705）。

| 接口                                                                         | 做什么                                                           |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `GET /api/training/folders`                                                  | 我能看的文件夹与每个夹里的文件数（管理权限看到全部，含停用的）   |
| `GET /api/training/folders/:id/files`                                        | 这个夹里的文件（管理权限另带看过人数）                           |
| `GET /api/training/files/:id/content`                                        | 文件内容（支持 Range，视频拖动、PDF 按需读）；`?download=1` 下载 |
| `POST /api/training/files/:id/viewed`                                        | 记一次「看过」                                                   |
| `POST/PUT /api/admin/training/folders…`                                      | 新建、改名、排序、停用文件夹                                     |
| `POST /api/admin/training/uploads` → `PUT …/chunks/:seq` → `POST …/complete` | 分块上传，完成时登记成新文件或某份文件的新版本                   |
| `PUT /api/admin/training/files/:id`                                          | 改标题、说明、所在文件夹、上架 / 下架                            |
| `GET /api/admin/training/files/:id/views`                                    | 看过的人                                                         |

加锁顺序见 `LOCKING.md` 员工培训一节。

# OA 办公：考勤打卡、审批、即时通讯、工资条（店主 2026-11-22）

店主转来《企业 OA 审批 + 考勤打卡系统需求文档》v1.2（2026-11-21），目标是替代员工在钉钉里的日常使用：考勤打卡、OA 审批、即时通讯、工资条。店主的要求：

- 按文档拆成 18 个 PR，**一个做完（CI、Codex 审查通过并合并）再做下一个**。
- 文档里的表设计、接口路径与技术建议不照搬，**以现有系统的习惯为准**；员工的使用入口也参照现有系统已有的模块。要做到的是文档里的需求、业务逻辑与功能。
- 全部 PR 做完后，店主在另一个窗口统一定一个版本号，**这边不改版本号**。

这一批的 PR 编号写作 `OA-01`…`OA-18`（与同时在做的 8.2.0 的 `P01`…`P09` 分开）；迁移号预留 `210`–`229`（ROADMAP 第 7 节）。默认做法 OA1 起，记在 `PENDING_DECISIONS.md`「OA 办公」。

## 4. OA-01 组织架构与员工档案

- **部门**：沿用 `org_departments` 的 15 个部门（OA1）。新加「上级部门」（总裁 / 公司在最上，总经办挂公司下，其余部门默认挂总经办下）与「指定主管」（可不填）。改上级部门不许绕成环。
- **部门主管**：指定了的用指定的（必须是在职员工）；没指定时取本部门在职的负责人岗位里最早建的一位；总经办取总经办岗位，公司取总裁。之后审批的「本部门主管 / 上级部门主管」（OA-10）都从这里取。
- **员工档案**：工号（全店唯一，可空）、手机号（11 位）、入职日期、离职日期、在职状态。每个账号一份，没填的就是空的；部门按岗位来。
- **办理离职**：记离职日期，档案改成离职、账号停用、所有登录会话作废；考勤、审批、工资条等历史一律保留（后续各 PR 都只读不删）。不能给自己办离职，也不能让店里一个在职总裁都不剩。复职：档案改回在职、清离职日期、账号启用。
- **权限**：看与改都要 `hr.org`；`staff.manage`（总裁）照样能做。
- **入口**：后台「人员与行政 → 组织架构」：左边部门树（主管、人数），右边员工档案表（筛部门、在职 / 离职、按姓名 / 工号 / 手机号搜）。

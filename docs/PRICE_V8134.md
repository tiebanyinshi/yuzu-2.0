# 8.1.34 价目重构：只认「全品类价目表」

店主 2026-11-24：「价目、消费项目那些地方太乱了，请你直接重构。只需要参考我发你的这个价目表（《汤崎宝安店价目表 1119》）。把目前多余的价目上的模块和功能都删除，仅保留合理的数据库。不需要在代码里写死，给升级服务器的 AI 说一下怎么给正式服填上；看一下正式服的价目数据有没有奇怪的地方，进行删除。」

盘点见本文第 1 节，改了什么见第 2 节，**升级正式服的步骤（给 Codex）见第 3 节**，待店主确认的默认做法见第 4 节（`docs/PENDING_DECISIONS.md` PC33–PC36）。

## 1. 盘点：价目原来有几套

所有开单路径（前台挂账、房态中心登记、房态点单、点单页、桌台、平板、钟房、会员消费、预约、使用单）只认一张表：收银项目 `service_items` + 各档价 `service_item_prices`（第二家店另有本店价 `service_item_store_prices`），经 `src/server/modules/pricing.ts` 取价，已开的单留快照。这三张表与 `pricing.ts` **保留**——它们就是价目表生效后落到的地方（`price-catalog/materialize.ts`、`links.ts` 同步）。

能改这张表的地方原来有 7 处以上，互相覆盖：

| 入口                                                                                                                | 8.1.34 怎么处理                                                                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 价目与套餐 → **全品类价目表**（`/admin/catalog/full`，迁移 230–241）                                                | **唯一来源**：价格、名称、分类、时长、性别、在用 / 停用都在这里改，切换生效时同步到收银项目                                                                                                                            |
| 价目与套餐 → **导入价目表**（老的价目清单 CSV、内置 10-27 汤崎清单、`import-price-list` 命令、`/api/items/import`） | **删除**：是全品类价目表的旧版本，按名称改名、新建、还能「停用清单外的全部项目」，会和价目表打架                                                                                                                       |
| 价目与套餐 → **消费项目**（`/api/items`）                                                                           | 保留，但对接了价目表的项目只读名称、分类、价格、时长、适用宾客（页面灰掉并说明，服务端 `PRICE_LINKED` 兜底）；力道、精油、说明、排序、停用照常。价目表管不到的收银项目（房费、开台费之类）仍在这里新增、改价           |
| 餐饮 → **菜品管理**                                                                                                 | 保留做法、加料、套餐、换菜、图片、档口、排序、上下架、沽清；对接了价目表的菜名称、分类、改价、删除在价目表里做（改价 8.1.x 已挡，名称、分类、删除 8.1.34 起挡）                                                        |
| 价目与套餐 → **门票**（`ticket_types`）                                                                             | 保留：结账按在店时长算门票费、浴票延迟、券、次卡、会员档阶都靠它。**价目表不再把门票、夜间票建成能挂单的收银项目**（原来两套门票价、前台还能再挂一张门票，有重复收费的风险）；票价照价目表在门票页填（第 3 节第 4 步） |
| 价目与套餐 → **本店价**（第二家店）                                                                                 | 保留：价目表对接了的已挡改价；只剩价目表管不到的项目可改                                                                                                                                                               |
| 价目与套餐 → **充值套餐**                                                                                           | 保留：储值，不是项目价                                                                                                                                                                                                 |
| 客房 → 房型与房价、开单即占用的房费项目                                                                             | 保留：价目表的房间价格（起开价 + 超时 + 封顶、轰趴房分档）开单还没有算法（PC18），只在「价目试算」里算                                                                                                                 |

## 2. 改了什么

- 删：`src/shared/price-list-import.ts`、`src/server/demo/price-list-tangqi-2026-10-27.ts`、`catalog.ts` 里的 `importPriceList` 与 `/api/items/price-lists`、`/api/items/import`、命令行 `import-price-list`、页面「导入价目表」页签、`e2e/price-list.spec.ts` 与相关用例。`docs/data/price-list-tangqi-2026-10-27.csv` 留作历史数据。
- `price-catalog/linked.ts` 的 `assertNotPriceLinked` 带上「管的是什么」：消费项目改名称、分类、时长、性别限定，菜品改名称、分类、删除，对接了价目表的拒绝 `PRICE_LINKED`。
- `price-catalog/materialize.ts`：`NOT_ITEMS` 加门票、夜间票。以前建过的门票项目，下次切换生效时按「价目表新建的、这份里已经没有的」自动停用；也可以用下面的 `price-audit --apply` 停。餐票照旧建。
- 新命令 `price-audit [--apply]`（`price-catalog/audit.ts`）：核对收银项目与生效的价目表，默认只读；`--apply` 只停用两类（不删）——价目表以前建的门票项目、没对接但和已对接的在售项目同名的（「没有价格」不算：数据库要求项目本身的价格大于 0，没有分档价时开单按它当标准档）；「开单即占用」规则里当房费 / 开台费用的项目不动。其余（在售但没对接的、双价还留「标准」档的、价目表在用但收银项目停用的、门票票种价与价目表对不上的）只列出来。
- 消费项目页的说明改了（原来写「价格以这里为准」，与价目表矛盾）。

## 3. 正式服怎么填（给 Codex：升级服务器的 AI）

前提：正式服已升到 8.1.34 的版本标签（`./scripts/update.sh v8.1.34`，升级前自动备份）。**不在代码里写死任何价格**，价目全部从店主的《价目表 1119》（xlsx，店主另发，不进仓库）导入。

1. **升级前先核对一遍现状（只读）**：`docker compose exec app node dist/server/cli.js price-audit`，把输出存档发在 PR / 交接里（这一步看「正式服的价目数据奇怪的地方」）。
2. **导入价目表**：店主或店总账号登录后台 → 价目与套餐 → 全品类价目表 → 导入《价目表 1119》→ 看预览（条数对照、报错）→ 导成草稿 → 对比 → 「切换生效」（条数对不上写原因）。已经生效过同一份的，导入后对比没有变化就不用切换。
3. **对接**：同一页「对接收银项目」→「按名称自动对接」；自动对不上的逐个手工对接（原来就在卖、名字不一样的收银项目），对不上的价目表项目切换生效时会新建。
4. **门票票价**：价目与套餐 → 门票，照价目表「门店价格」填：默认票种 12 小时 = 12H 不含餐（499）、24 小时 = 24H 不含餐（699）；含餐（699 / 899）与夜间票（599）是否另设票种按店主的回复（PC34），没回复前只改默认票种。
5. **核对与清理**：再跑 `price-audit`。两类会被停用的逐个看一眼，确认都是多余的再 `price-audit --apply`（不删，只停用，记审计；已开的单、改价记录照旧）。「在售、没对接价目表」那一组发给店主看，要停的在后台「消费项目」里停用。
6. **自检**：`docker compose exec app node dist/server/cli.js check` 全 ✓；前台开一张演练单挂一个按摩项目、一道菜、一份早餐，价格与价目表一致后作废。
7. 第二家店（福田）的价目表另外一份，等福田的价目表定了再在福田门店里导入（见 `docs/FUTIAN_MIGRATION.md`）。

不要做：用 SQL 直接改价或删收银项目（历史单据、券、次卡按编号指着它们）；在测试服 / 演示服导入真实价目以外的数据规则照 AGENTS.md「环境隔离」。

## 4. 默认做法（待店主确认，PC33–PC36）

- PC33 老的价目清单导入删除，只留全品类价目表。
- PC34 门票不建收银项目，票价在门票页照价目表填；含餐票、夜间票要不要单独的票种待店主定（默认先只改默认票种的两档价）。
- PC35 对接了价目表的项目，名称、分类、价格、时长、性别、菜品删除只在价目表里改；上下架、属性、档口、做法、图片、排序照常在各自页面。
- PC36 `price-audit --apply` 只停用两类明显多余的，不删；其余列给店主决定。
- PC35 补充（Codex 审查）：名称、分类、时长、性别只读只对**价目表新建的**项目；门店原有、后来对接上的项目价目表不改这几样，后台照常能改，价格照旧只认价目表。

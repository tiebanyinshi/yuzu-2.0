# 8.2.27 男汤 / 女汤泡池：刷客人手牌、刷技师工牌下单

需求来源：店主 2026-11-27《新店系统需求现场走场确认》第三节「男汤 / 女汤泡池」。
同一份文件的锁牌外出在 8.2.7，餐厅 8.2.8，水吧 8.2.19，休闲娱乐 8.2.20。

## 1. 店主的原话怎么落到系统里

| 原话                          | 系统里                                                                                                                           |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 男汤 / 女汤泡池面板，可以输单 | 门店导航「技师」下多了「泡池」页：上面选男汤 / 女汤，列出这一边能做的技师项目（价目表里「需要技师」、性别不限或同性别的）        |
| 先刷客人手牌，再刷技师手牌    | ① 刷客人手牌（或输牌号）→ ② 点项目 → ③ 刷技师工牌（或输工号）→「派钟上钟」；读卡器刷到的卡第一步认手牌、第三步认技师工牌         |
| 服务计入技师的业绩明细        | 下单就是钟房的「派钟」：挂到客人手牌的账单上、建钟单、立即上钟；明细上记着技师，结账后进「技师业绩」与提成明细，和钟房派的钟一样 |

## 2. 规则

- 上钟方式：默认轮钟（照钟房的排位核对：上牌、在岗、不在钟上、轮到他）；客人点名的选点钟；
- 价格档按技师等级（与钟房一样）；客人不是这一边（男汤选了女宾的手牌）时页面提醒；
- 技师工牌：技师管理的岗位在泡池页点「绑工牌」，选技师、刷卡就绑上；一张卡只能绑一位技师，不能用手牌的芯片；可以解绑；
- 下钟、转钟、加钟照旧在钟房做。

## 3. 数据与锁

迁移 `630`：技师加一列工牌芯片号 `technicians.card_uid`（写法与手牌芯片号一样，同一门店里不重复）。
下单走钟房派钟（`/api/clockroom/dispatch`）原来的加锁顺序；绑工牌只锁这一位技师的一行。

## 4. 没做的 / 要店主定的

- 技师用的是工牌还是手牌：走场说「技师手牌」，这一版按单独的工牌（技师自己的卡）认，给技师发一张手牌也行——绑的时候刷那张卡就是（不能是正在给客人用的手牌）（8.2.27-1）；
- 泡池项目怎么分男汤、女汤：按价目表的性别限定；不限的两边都列（8.2.27-2）。

## 5. 测试

`tests/pool-v8211.test.ts`：客人按芯片号或牌号认（只认在店的）、技师按工牌或工号认；绑工牌的权限、不能两人一张、不能用手牌的芯片、芯片号格式、解绑；泡池下单（派钟上钟）挂到手牌、钟单上钟中、结账后进技师业绩。
